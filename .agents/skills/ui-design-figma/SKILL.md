# 搭建 Figma 换皮稿

1. 读[共同约定](../ui-design/references/common.md)，核对设计版本认可、目标文件／Frame 与本批范围。现成 HTML／静态稿可接手；只有需求而没有认可方案时先对齐。切换阶段不等于认可版本，先说明已知缺口再确认；同版有效答复不重复询问。
2. 从对话和实际成果确定本次分支，只读相应参考，不要求用户记新命令：
   - **首批搭建**：尚无本功能换皮基线，按[首批搭建](../ui-design/references/figma-initial.md)做代表主界面和够用源，暂停等换皮。
   - **增量补齐**：基线换皮已就绪且用户指定待补范围，按[增量补齐](../ui-design/references/figma-expand.md)复用实际成果，只补缺项；就绪或范围不明时只补问缺项。
   - 明确的局部修改直接处理获准部分，不重建首批或重走无关阶段。
3. 读[Figma 换皮维护与验收](../ui-design/references/figma-ui.md)，核实 Figwright 桥接、目标和本批所需能力。确认完成前仅只读检查；缺少能力报告阻塞，不擅自改配置或更换服务。
4. 涉及组件拆分、拆分验收或接手工作台项目时，再读[组件拆分与验收](../ui-design/references/component-decomposition.md)：AI 主拆、人验收和纠偏；尚未接通的工具能力按实际缺口说明，不要求人全部手拆补位。
5. 按本批范围组装、定向检查和冻结必要新增源。维护便利优先，视觉布局沿用认可稿，Figma 不机械复制 HTML 容器，也不强制全局 Auto Layout。

**交付与停止**：简短给出目标位置、依据版本、本批结果、维护入口、暂缓项与验证缺口。首批或有新增换皮源时交给用户换皮并暂停；无新增源的增量任务交付后结束，不自动启动下一批。Figma 只表达布局与必要视觉状态，不新增点击连接或 Flow。
