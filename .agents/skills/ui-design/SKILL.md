# Figwright Game UI

所有相对路径均相对于本技能目录。开始前阅读 [术语](references/GLOSSARY.md) 与 [设计规范](references/figma-ui.md)。新建或改变主要布局时，另读 [布局预览与确认关卡](references/layout-preview.md)，在用户确认前停留于预览讨论阶段。

## 调用后如何开始

- 用户可通过 `/skill:ui-design` 附带自然语言需求，也可仅调用技能。识别本次是布局预览、新建、修改、检查还是继续已有任务，无需用户记忆固定参数格式。
- 仅调用或目标不明时，先询问任务类型与需求文档或简述；修改、检查任务还需目标 Figma 文件及 Frame。已在上下文明确的信息直接复用，只问缺失项。
- 收到新建或布局预览需求后，先制作灰阶块面预览；预览阶段不要求用户先连接 Figwright。仅预览任务在展示后等待反馈，不主动进入 Figma 搭建。
- 继续已有任务时先定位最近产物和确认状态，从未完成阶段恢复；仍处于布局确认关卡时，含糊的“继续”不替代对具体预览版本的明确确认。

## 执行流程

只读任务仅执行现场读取与适用验收；已有界面仅修改受影响区域及其依赖。

| 步骤 | 操作 | 完成标准 |
| --- | --- | --- |
| 1. 明确范围 | 读取需求；需要参考已有设计时只读检查目标文件与组件 | 明确区域、操作与修改范围，影响主要布局的疑问已解决 |
| 2. 预览并确认 | 按预览参考制作单文件 HTML 灰阶块面布局预览，展示、调整并等待用户确认 | 用户明确认可具体版本；不涉及主要布局时说明不适用 |
| 3. 规划维护源 | 确认 Figwright 桥接与目标；划分共享组件、代表性布局和必要场景 | 明确待替换区内容及演示场景到维护源的复用关系 |
| 4. 建立骨架 | 按确认版配置根 Frame、Auto Layout、组件和实例 | 布局与确认版一致；属性、实例关联及维护源组织已读回检查 |
| 5. 连接原型 | 用局部状态和最少必要场景连接核心路径 | 连接与起始 Flow 正确，演示副本不产生独立换皮负担 |
| 6. 视觉完善 | 完善维护源样式与资源，并检查演示实例同步 | 视觉符合约定，源头修改有效传递，布局保持适配 |
| 7. 验证交付 | 执行结构、尺寸、维护同步、原型及保存检查 | 交付确认版依据、待替换区入口和演示路径，未验证项明确 |

桥接不可用时可继续本地布局预览讨论，但 Figma 搭建报告为阻塞；不擅自切换官方 Figma MCP、其他编辑器或开发额外应用。
