# Game UI Design

所有相对路径均相对于本技能目录。先读 [术语](references/GLOSSARY.md)，再按任务加载参考：
- 新建或调整 HTML／重要界面方案：先读 [界面对齐与追问](references/ui-alignment.md)，方案确认后按 [HTML 预览与 Figma 确认关卡](references/layout-preview.md) 制作。两道确认分别约束 HTML 制作与 Figma 写入。
- 涉及 Figma 读取、搭建、修改或检查：读 [Figma 设计规范](references/figma-ui.md)。
- 需要生成背景、场景或图标占位 PNG：按 [占位资源脚本](references/layout-preview.md#占位资源脚本) 执行，复用固定模板而非临时重写绘图代码。

## 跨阶段默认值

新建界面的基准尺寸默认 **1280×720（16:9）**，HTML 与 Figma 使用同一约定；默认只做该尺寸，多比例预览按用户明确需求追加。用户指定尺寸优先，修改已有界面时保留原尺寸和现有预览，不因默认流程变化删除已有内容。

## 调用后如何开始

- 用户可通过 `/skill:ui-design` 附带自然语言需求，也可仅调用技能。识别是 HTML 预览、新建、修改、检查还是继续任务，不要求固定参数；旧称“布局预览”默认也包含需求交互，用户明确仅需静态稿时除外。
- 目标不明时先询问任务类型和需求文档或简述；涉及已有 Figma 时还需目标文件与 Frame。复用上下文信息，只问缺失项。
- 收到需求后先对齐界面，不立即生成 HTML。追问聚焦歧义和设计风险，功能基本明确时直接采用；完成标准和轮次收敛按对齐参考执行。
- HTML 阶段不要求连接 Figwright；仅 HTML 任务展示后等待反馈，不主动搭建 Figma。
- 继续任务时依据对话、当前 HTML 与 Figma 实际内容恢复阶段和批次；上下文缺失时只确认必要信息。换皮期间的“继续”若未明确本批已换好及后续范围，先澄清，不自动扩展。

## 执行流程

只读任务仅执行现场读取与适用验收；已有界面的明确局部调整直接处理，不重做无关访谈或关卡。

| 步骤 | 操作 | 完成标准 |
| --- | --- | --- |
| 1. 界面对齐 | 读取需求与参考，分轮追问重要界面歧义和风险 | 已确认项、样例假设和待决项明确；重要分歧解决 |
| 2. 确认方案 | 汇总布局、层级、控件表达及交互表现方案 | 用户明确认可具体方案，才开始 HTML 制作 |
| 3. HTML 制作与确认 | 制作、检查并展示 HTML；从上下文识别用户转入 Figma 制作阶段的意图，再询问当前版本是否满足需求 | 获得针对该版本的明确肯定答复后才写入 Figma；切换指令不等于确认，未验证检查如实保留 |
| 4. 确定首批范围 | 确认桥接与目标，在对话中简短说明代表性主界面、够用的独立换皮源和暂缓内容 | 本批范围明确，既能看整体效果，又不提前铺开可复用的其他界面和状态 |
| 5. 搭建代表界面与组件 | 按确认版建立主界面大体布局，实例复用待替换区组件及轻量图片资源 | 换皮可反映到主界面；同类组件只做代表，必要独立样式不强行合并，不制作原型连接 |
| 6. 检查、冻结并暂停 | 按本批范围检查结构、替换入口和同步，建立本批冻结参考，交给用户换皮 | 给出主界面和维护入口、暂缓项及实际验证缺口；停下等待，不以全功能齐全作为首批完成条件 |
| 7. 换皮后扩展 | 用户明确本批已换好并指定继续范围后，读取实际组件，复用其成果搭建后续内容 | 保留用户美术、尺寸与关联；新增独立换皮需求先说明并确认，按新批次检查、追加参考并再次暂停 |

桥接不可用时可继续界面对齐与 HTML 阶段，Figma 搭建报告为阻塞；不擅自切换官方 Figma MCP、其他编辑器或开发额外应用。
