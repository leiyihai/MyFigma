# 游戏 UI 全流程

用户主动选择本入口时，串联以下任务。先从对话和现有成果恢复当前阶段，只补缺失项；各任务的具体规则由其技能维护，不在这里复制。

1. 加载 `ui-design-align`：对齐界面，取得具体方案确认。完成后才进入原型制作。
2. 加载 `ui-design-prototype`：制作并自查可交互 HTML，交付当前版本，等待反馈。仅 HTML 任务到此结束。
3. 用户表达转入 Figma 的意图时，加载 `ui-design-figma`：先确认当前设计版本是否满足需求，再按获准批次搭建、检查、冻结并暂停等换皮。阶段切换请求本身不是版本认可。

用户已指定获认可的现成设计稿时，从相应任务接手，不强制重做 HTML。独立只读检查使用 `ui-design-review`，不是全流程必经步骤。明确的局部修改进入对应产物技能，只重新确认受影响的重要决策。

加载单项技能不等于取得修改授权；缺少工具时按该任务的实际验证缺口交付，不擅自安装依赖、改 profile 或替换桥接。
