# Figma 换皮维护与验收

本文件只约束维护、复用和成果保护，不是另一套视觉设计或 Figma API 教程。视觉布局沿用用户认可的 HTML／静态稿；[共同约定](common.md)定义尺寸与确认边界。

## 按任务加载

- **首批搭建**：读[首批搭建](figma-initial.md)，交付代表主界面与够用的换皮源。
- **增量补齐**：读[增量补齐](figma-expand.md)，以实际已换皮成果补齐指定范围。
- **组件拆分、拆分验收或使用工作台项目**：读[组件拆分与验收](component-decomposition.md)，不把中间组件稿当成已建立的 Figma 主组件。
- 只读检查只使用下面适用的检查项，不创建测试副本、不执行修改。

## 先复用，只补缺口

- 先读目标页面／子树与相关主组件、属性和资源；已有匹配组件就放实例，差异优先用真实的文字、显隐、实例交换或必要变体表达。明确共享的重复元素首遍就建立够用的维护源，不先铺多份再等用户要求组件化。
- 一次有效发现结果可在本批复用；已知节点用 ID 定位，不为每个控件重扫整页。只有来源变化、结果失效或实际缺项时补查。
- 同一维护意图下的共享外观或结构只保留一个权威来源；用户明确要求独立换皮的相似对象不强行合并。同类页面优先复用已存在的区域／模板，不为未来可能复用而预建整套组件库，也不穷举文案、数值和状态组合。
- 可独立换皮的源集中在 `待替换` Frame，背景 `#2B2B2B`；正式展示在区外通过实例引用。页面、图层、组件和属性用清楚中文名；API 字段与节点 ID 保持原样。

## 布局服务于换皮，不强制 Auto Layout

- 原型规定位置、比例、层级与操作表达，**不规定 Figma 必须复制 HTML 的 DOM、flex 或 grid 容器**。在保持确认版观感的前提下，选择层级少、替换方便的结构。
- Auto Layout 只用于确有流式关系、内容变化或排列收益的区域，例如列表、TAB 和按钮的内容排列；它不是根 Frame、每层组件或每个美术槽位的默认要求。
- 背景、底板、图标、HUD 和其他叠放美术，可使用普通 Frame、明确位置及必要的 Constraints；不要为叠放关系套多层 Auto Layout，也不把所有实例统一设成 Hug／Fill。
- 替换美术时应尽量只需定位源、粘贴／替换并调整尺寸，而不用先理解多层自动布局。需要额外容器时，它应承担明确的裁剪、排列或替换职责。
- 以实际替换结果验收：主界面位置正确，文字不被挤走，美术边界完整且关联有效；不以“全是 Auto Layout”或“全部固定坐标”作为合格条件。
- 默认只做基准尺寸；明确要求多比例后才追加，验证各尺寸的布局与同步。已有尺寸和用户调整保留，不因新规范批量转换结构。

## 美术与结构分开，替换入口直接

- 文字、内容布局与背景／底板／图标分开，避免把整屏 UI 或含文字的按钮烘焙成图片。背景／场景可用轻量 PNG；占位资源按[现有脚本](layout-preview.md#占位资源脚本)生成或复用。
- 需要共享或独立换皮的美术才建立相应维护源与实例。美术填充可以直接放在美术主组件上；已有合适层就是入口，不为了“槽位齐全”再加包装层。
- 新建 Figma 占位图标默认采用单层透明 PNG 美术主组件和无子层实例，不逐路径重建；保留已有图标结构与用户美术，不借规范更新重做。
- 需要占位层时统一命名 `占位层`，替换后可移除，文字和关联不依赖它。保持少而明确的维护入口，不把每一层都做成独立组件。
- 区分**只换美术**与**换整套控件**：前者保留外层结构、文字和组件关联；后者仅对用户指定实例交换，并核对目标包含所需内容。指导时指出具体层或实例，不能只说“替换按钮”。
- 九宫格按用户实际插件输出验证四角、边缘、中心和文字遮挡；普通 PNG 或组件不等于九宫格。资源未提供时，只验入口结构，不宣称最终美术兼容。

## 保护现有成果

- 沿用已有尺寸、布局方式、组件关联和用户内容，仅修改任务所需部分。改变共享主组件、分离实例、覆盖美术、删除或重建前，先检查影响范围并取得相应授权。
- 已换皮组件是后续搭建依据，不重新生成灰阶源覆盖它们；需要新的独立美术源时说明缺口并确认。来源不明的工作台 `confirmed` 字段不是用户授权证据。
- 本项目新建 Figma 只表达布局和必要视觉状态，不制作点击连接或 Flow；已有任务范围外的连接、选择与其他文件保持不变。
- 修改前采用适当恢复措施；试验共享修改时用隔离的维护源及依赖实例副本。无法安全隔离就标未验证，不拿正式用户美术做破坏性测试；仅清理本次测试副本。

## 工具调用与证据

- 本项目沿用 Figwright。先按已连接工具 schema 核实桥接、可写编辑模式和目标文件；多文件先绑定明确目标。缺少能力时说明阻塞，不擅自切换服务、安装环境或修改配置。
- 操作以当前 schema 为准；相关创建、属性、绑定和局部诊断按安全重试边界合批，不为固定检查节奏机械拆碎。不要把其他服务的工具名、会话参数或原子性假设套过来。
- 写入尽量带回实际受影响 IDs、数量、关联及尺寸，作为结构证据；证据不足、来源已变或错误可能部分执行时，再定向读回。`ok: true` 或脚本未报错都不是视觉验证。
- 按本批范围合成后看主界面截图；有视觉修复或相关改动才复查受影响内容，不重复未变化的最终截图。文字、裁切、图片比例、长内容和关键状态只检查本批承诺内容。
- 只验实际涉及的换皮／交换路径：必要时在隔离副本替换资源，检查来源到实例的传播、内容保留和位置稳定。没测的路径、保存／同步状态无法确认的部分如实保留，不为验收扩建范围外状态。

## 冻结与交付

- 交给用户换皮前，把本批待替换源导出为完整清晰的图片快照，放入旁边同尺寸、锁定的 `待替换_原始参考` Frame。它不含关联正式源的实例，不能随换皮变化。
- 后续只追加新增源的原貌快照，不覆盖旧基线、不重拍未变化或已换好组件；源过大可分块，但要覆盖本批全部新增源。失败则标明缺口，不用锁定副本冒充快照。
- 简短交付目标文件／页面、依据版本、本批主界面与维护入口、冻结参考、暂缓项及实际验证缺口。不另出长报告，也不将本批交付说成整个功能完成。
