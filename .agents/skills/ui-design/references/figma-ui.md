# Figwright / Figma UI 构建与验收

## 设计目标与默认值

- 通过 Figwright 分批搭建可编辑、可复用的界面与组件，先让用户完成一批够用的换皮，再扩展后续内容。HTML 承担完整交互沟通，Figma 不制作点击连接、Flow、交互组件动作或演示流程。
- 代表性主界面使用独立根容器，基准尺寸沿用技能入口约定。用户指定风格、参考图和现有设计系统优先，不擅自用最终美术取代待替换的结构稿。
- 图片、背景、底板、文字尽量独立，保持层级简洁；占位资源明确可辨，方便用户定位替换入口。
- 面向设计者的页面、Frame、图层、组件、实例、组件属性、变体属性及状态值默认使用清晰中文名，如 `活动主界面`、`任务列表`、`底板槽位`、`状态=可领取`。API 字段、工具参数、节点 ID 及代码标识符保持原样。

## 分批换皮与搭建

### 首批：主界面大体效果与够用的换皮源

- 从确认版 HTML 选一个代表性主界面，保留主要区域、文字层级及按钮、面板的搭配。主界面通过实例引用待替换区组件，用户换皮后能直接观察整体效果；仅摆零散组件或空框不算首批完成。
- 同布局、同美术结构的面板或控件先做一个代表，优先复用已有组件。确实影响主界面观感的独立样式保留，不为压低数量强行合并；优化的是独立美术源数量，不是隐藏或堆叠大量待处理内容。
- 其他状态、TAB 内容、次级界面，以及只会复用本批组件的后续页面暂缓搭建。默认只保留基准尺寸，不追加多比例预览；无需为尚未制作的状态提前建立完整变体集。
- 在对话中简短说明首批包含什么、暂缓什么；有影响范围的重要歧义才继续确认，不另建批次说明或状态清单文件。
- 按本批范围检查替换入口、实例同步及主界面效果，建立冻结参考后交给用户换皮并停下。首批完成条件是可开始换皮并能观察大体效果，不是全功能或全部状态齐全。

### 用户换皮后：复用成果，再按需扩展

- 用户明确本批已换好并指定继续范围后，先读回实际组件、资源、尺寸、属性及关联，再扩展指定界面和状态；完成声明不代替实际检查，也不授权修复、重建或回滚用户的美术。
- 优先复用用户已经换好的组件，保留其外观、尺寸、覆盖值及关联；影响布局或内容表达的变化先说明并确认，不重新生成灰阶源覆盖已有成果。
- 若扩展需要新的独立美术源，先说明增量及不能复用的原因，确认后只做该批新增组件及必要展示；按本批检查、追加冻结参考，再暂停等用户换皮。不把已完成组件重新列为待换皮任务，也不假定本批确认覆盖后续所有界面。
- 暂缓项属于后续范围，不标为本批失败或未验证；本批承诺但未执行的检查仍如实标记。用户只说“继续”且批次就绪或范围不清时，先澄清必要信息。

## 修改边界

- 修改已有界面时保留原尺寸、组件关联、Auto Layout 和用户内容，仅调整任务所需部分；不因新流程取消原型而自动清除已有连接或 Flow。
- 修改主组件前检查受影响实例；涉及任务范围外界面时，先确认共享变更范围。
- 删除、覆盖、分离实例、全量重命名或重建现有结构须有明确任务依据。保留必要的外部映射与关联，不借整理之名破坏用户内容。
- 用户未要求时保持其选择、视口及其他文件不变。测试副本与正式内容分开命名、放置；仅清理由本次任务创建的临时内容。

## 1. 桥接与操作

操作路径为 **AI → Figwright MCP → 本地 WebSocket 桥接 → Figwright Figma 插件 → Figma Plugin API**。不是官方 Figma Dev Mode MCP 或离线文件编辑；目标文件须在 Figma 打开并运行插件。

- 先发现已连接工具及参数 schema，用 `ping` 确认桥接，用元数据确认文件、页面和编辑模式；构建在可写的 Figma Design 中执行，Dev Mode 为只读，FigJam 不适用于本规范。
- 多文件连接先用 `list_files` 确认目标，通过 `use_file` 绑定；重名文件按 sessionId 区分。文件绑定由 MCP 服务进程共享，避免子代理并行切换目标，不杜撰 fileId 或 documentId 参数。
- 检查运行中的服务端与插件兼容性，以当前 schema 为准，不假定固定工具数量。插件未连接时请用户在目标文件打开插件并确认 Connected；关闭插件会断开桥接。
- 需要修改配置、安装或更新环境时先征得同意；阻塞时报告缺口，不自动改用官方 Figma MCP 或其他编辑器。
- 先读页面概览、目标子树、现有组件、样式及变量；之后按节点 ID 查询，减少整页扫描，优先复用已有组件和设计 Token。
- 使用 `batch` 合并区域内可回退的关联读写；参数与批次引用按当前 schema，破坏性操作单独评估。异常后读回受影响节点再重试，避免重复创建。
- 文本使用可用字体，工具或脚本要求时先加载字体。阶段结束读回关键属性并截图目标 Frame，不以 `ok: true` 代替尺寸和结构检查。
- 修改前保留适当恢复副本。设计稿修改、图片导出和本地备份是不同交付物；图片可承载极简场景、占位图标及冻结参考，但不能代替可编辑的 UI 布局、文字和结构组件。
- 交付前确认正确文件中的修改可读回；客户端保存/同步状态无法确认时注明，不虚构保存命令或文件路径。

## 2. 布局与状态展示

### 自适应布局

- 根 Frame 优先用 Auto Layout 管理主要区域排列与空间分配；上下区域用垂直布局，左右分栏用水平布局，适配依靠重新布局而非整体缩放。
- 顶底固定栏保持所需高度，主体填满剩余空间；按钮组、TAB、列表等重复排列使用 Auto Layout，按内容决定间距、换行和滚动视口。
- 尺寸模式按轴确定：Fixed 用于稳定尺寸；Hug Contents 随内容撑开；Fill Container 分配父级剩余空间。父级先获得可确定尺寸，避免同轴父级 Hug、子级 Fill 循环依赖。
- 组件与实例正常参与父级布局；状态和美术交换后保留布局策略。普通子节点位置交给布局管理，HUD、背景或特殊构图确需脱离布局流时再使用绝对定位与 Constraints。
- 美术层与内容层分离，图片选择合适的填充/适配方式；文本明确换行或截断，裁剪只用于有意限定的视口，不以隐藏溢出掩盖布局错误。

### 按需追加适配预览

用户明确要求多比例时，先确认尺寸和当前批次范围，再建立关联同一屏幕主组件的不同尺寸实例，保留其内容与美术继承；实际检查更新同步、各自尺寸保持及布局结果。用 Auto Layout／Constraints 重新布局，不整体缩放、不靠大量覆盖值修补；改变导航或横纵结构等断点设计另行确认。已有预览按修改边界保留，不因默认流程变化自动删除。

### 状态覆盖与复用

- 只覆盖当前获准批次的界面和视觉状态，完整需求仍以 HTML 为沟通依据；首批不提前补齐所有空态、禁用、选中、已完成等状态。
- 用户要求扩展后，主要布局用界面展示，局部差异优先复用已换皮组件，以变体或局部状态稿表达；不穷举状态组合或为点击路径复制整屏。弹窗无需 Overlay 连接。
- 本批确需同一组件的多状态时再使用真实 Component Set 与 Variants，例如 `状态=锁定/可领取/已领取`；不为数值、文案或图标变化扩增变体。需要新美术的状态按新增换皮批次处理。
- 已获准的多个同布局界面优先共享布局模板或区域组件，主要布局不同的部分才独立维护；不为未来可能复用而预先搭建全部页面或屏幕模板。
- 状态展示稿位于待替换区之外，通过实例引用维护源；不建立 reactions 或 Flow。状态名称清楚表达差异，无需另建场景说明文档。

## 3. 换皮维护与美术槽位

### 待替换区

- 功能的换皮维护源集中放在名为 **`待替换`** 的大 Frame，背景固定为 **`#2B2B2B`**，内部使用中文命名。只按获准批次逐步加入主组件、必要状态及美术资源；已换好组件保留原关联供后续复用，不重复复制成新的待换皮源。
- 此 Frame 是工作区容器，不是界面根节点；尺寸按内容设置，保持可读间距，完整展示源稿，不搬入全部状态展示副本。
- 同一外观或布局保留一个权威维护源；跨稿复用的屏幕、区域及资源建立真实组件关联，仅摆放普通 Frame 或独立图片不算统一替换入口。
- 展示稿允许文案、数量及状态等必要覆盖；共享外观继承维护源，避免无必要的颜色、图片和描边覆盖阻断同步。需要不同皮肤时显式交换美术实例，而非默默分离实例。

### 图片化背景、场景与单层图标

- 背景／3D 世界场景采用 [占位资源脚本](layout-preview.md#占位资源脚本) 的极简 PNG，与 HTML 复用资源；不逐层重建地面、建筑、树木或 SVG 路径。场景美术用单张图片承载，拍照按钮、HUD、列表文字等仍独立。纯色背景直接填充。
- Figma 占位图标采用透明 PNG；图标美术主组件自身直接使用图片填充、不含子节点，界面每处图标只保留一个无子层实例，该实例本身就是 `图标槽位`，不再套外部 Frame、路径分组或 `占位层`。必要的主组件定义仍保留以支持同步和实例交换。
- 此单层图标是美术主组件填充，不是把图标烘焙进按钮等结构组件根节点。替换时修改其图片填充或交换此实例；无需为占位先增加子层。用户明确需要多层资源时再确认结构变化。
- 不把“一个 SVG 文件”当作单层保证；导入后读回实际节点数量。资源通过文件路径或当前工具支持的图片入口导入，不将大段 Base64 和矢量数据反复写入对话。

### 结构与美术分层

- 结构组件负责布局、尺寸、文字和内容；背景、底板、图标分别设真实且命名明确的美术承载层，例如 `背景槽位`、`底板槽位`、`图标槽位`。不要求把图片填充直接设置在结构组件根节点上。
- 可交换的美术槽位使用嵌套组件实例，引用待替换区中的美术主组件；需要时暴露 Instance Swap 属性，绑定到真实槽位。
- 需要子层承载的底板等美术主组件，其灰阶示意层统一命名为 `占位层`，仅用于初始外观；文字、图标槽位及属性绑定独立于它，使其可被移除。单层图标按上节执行，不额外建立占位子层。
- 除单层图标外，默认换皮流程：用户将 PNG 图层或图片／九宫格组件的实例粘入对应美术主组件，调整位置、尺寸及适配约束，确认新资源完整承接外观后删除或隐藏占位层。PNG 也可使用独立图层的图片填充，不将这种方式设为唯一入口。保留美术主组件及外部实例关联，无需分离实例。
- 按钮可采用 `按钮 → 底板槽位 + 图标槽位（按需）+ 按钮文字`；底板位于内容下方并随控件适配，独立于内容布局；图标保持约定比例。粘入底板的资源设置贴边／拉伸约束，图标资源按约定比例适配槽位，检查实际可见边界而非只看外层尺寸。
- 九宫格插件输出须检查实际节点类型和拉伸行为；普通 Frame/切片可整理为主组件，再将其实例粘入美术主组件或交换进底板槽位。普通 PNG 填充或包成组件本身不等于九宫格拉伸，不承诺任意插件输出可直接使用。
- 槽位约束与资源自身的适配结构共同决定效果；替换后检查四角、边缘、中心、裁切和文字遮挡，不靠整体缩放伪装九宫格拉伸。用户尚未提供插件输出时，只验收槽位结构，九宫格兼容性标为未验证。

### 内容属性与两级交换

| 差异 | 使用方式 | 示例 |
| --- | --- | --- |
| 文字变化 | Text Property，绑定实际文本层 | `文案`、`标题`、`数量` |
| 元素显隐 | Boolean Property，绑定目标层 | `显示角标`、`显示图标` |
| 只换美术 | 嵌套实例交换，可暴露 Instance Swap Property | `底板`、`图标`、`奖励图标` |
| 换整套控件 | 选中指定实例执行 Swap instance | 两个按钮换成新主组件，其余保持原关联 |
| 控件状态 | Component Set + Variants | `状态=选中/未选中` |

- 交换前先读回选中节点、所在层级及目标主组件的内容，明确是“只换美术”还是“换整套控件”；指导用户时给出具体槽位路径，而非笼统要求交换按钮。
- 只换外观时，交换控件内部的 `底板槽位`／`图标槽位`，保留外层结构组件、文字及布局；纯九宫格底板对应底板槽位。
- 换整套控件时，交换选中的外层控件实例；目标主组件须包含需求所需的底板、文字、图标及布局。纯底板组件不具备原按钮的内容层，整套交换后原文字和图标不会自动补入；发现目标缺少必要内容时，先说明差异并确认改换槽位还是补全目标组件。
- 交换目标须是可用组件；Instance Swap 不是任意图层插入接口。使用真实属性标识创建绑定或修改实例，不假定显示名称就是 API 属性键。
- 新旧组件结构不同，文字、尺寸与覆盖值不保证保留；对应图层尽量保持命名和层级一致，替换后检查实际内容、Fixed/Hug/Fill、对齐及父级布局。
- 插件交换优先使用当前工具明确支持的交换语义；`swapComponent` 的覆盖值保留机制不等同于直接赋值 `mainComponent`，后者会清空覆盖值。不能杜撰工具参数或宣称任意交换无损。

## 4. 冻结参考区

- 首批交给用户换皮前，将本批整个待替换区导出为清晰、完整的图片快照，放在旁边名为 **`待替换_原始参考`** 的同尺寸 Frame 中，并锁定。
- 后续批次只为新增待换皮组件追加原貌快照，集中在同一参考区，可用批次名称区分图片；必要时扩展容器并恢复锁定。已有快照不覆盖、不重拍已完成组件，也不要求参考区始终与扩展后的整个待替换区同尺寸。
- 各批图片保留对应新增源的外观、比例及相对排列，清晰覆盖本批全部新增源；过大时可分块导出再拼放，不以当前视口或单个选中控件冒充完整批次快照。
- 参考区仅含静态图片及承载容器，不含关联正式主组件、资源或变量的实例；图片不随源区更新。普通复制 Frame、仅锁定实例或只分离最外层组件都不能代替冻结快照。
- 创建后检查图像清晰度、完整性、尺寸及锁定状态，确认其内容不依赖维护源。冻结参考区仅供视觉比较，不要求可编辑图层或组件同步。
- 只有用户明确要求更新已有基线时才重建对应快照；追加新批次不构成覆盖旧参考的授权。导出/导入失败时报告该批参考阻塞，不将共享实例副本冒充冻结快照。

## 5. 验证与交付

只按实际执行结果区分通过、失败和未验证；检查在任务过程中完成，最终对话简短交付，不额外生成验收文档。

### 结构、状态与保存

- 按本批获准范围对照确认版 HTML；首批至少能看主界面的主要区域、比例、文字层级及控件搭配，换皮能反映整体效果。暂缓内容不要求补齐，但未经确认的结构性差异仍需修正或取得认可。
- 重复元素为关联正确主组件的实例；只对本批实际新增/修改的状态检查内容覆盖、尺寸及布局，不为验收扩建尚未获准的状态。已有用户美术、范围外结构和原型连接保持不变。
- 修改位于正确文件且可读回；保存/同步状态可确认时已检查，否则注明未验证。

### 换皮与交换检查

- 确认 `待替换` 为 Frame、背景 `#2B2B2B`；状态展示稿在其外且能追溯到维护源，冻结参考区符合第 4 节要求。
- 检查美术槽位独立于结构内容，图标实例无子层，场景是图片而非拆分图形。具有占位子层的美术在移除它后，新资源仍完整显示，内容及绑定有效，关联实例正常继承；尚未移除时说明依赖，移除结果标为未验证。单层图标直接验证图片填充替换与同步。
- 同步测试隔离待测主组件、资源及依赖实例，读回确认测试实例指向测试主组件；普通展示 Frame 克隆不满足隔离。无法安全隔离则标未验证，不修改正式主组件试验。
- 在隔离副本中修改共享外观、共享资源及布局间距，检查对应依赖实例传播；修改实例覆盖值不算同步测试，通过一个实例不代表全部路径通过。
- 分别验证美术槽位交换和整套控件交换：前者读回确认外层主组件关联不变、内容保留；后者确认仅指定实例改关联，并逐项核对文字、图标、尺寸、覆盖值和父级布局。内容消失时先区分目标组件缺层、显隐覆盖、遮挡或裁切；周边因 Auto Layout 尺寸变化而重排不等于错误交换。
- 仅清理本次测试副本。若仍需逐稿独立换皮，合并为维护源复用，或说明限制并取得认可；用户资源未到位时不宣称已验证最终美术或九宫格效果。
