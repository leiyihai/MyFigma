# Figwright / Figma UI 构建与验收

## 设计目标与默认值

- 交付可编辑、可复用、可适配的 Figma UI，通过 Figwright 桥接操作，并用 Figma 原生原型模拟操作和反馈。
- 新建完整界面使用独立根 Frame；基准尺寸沿用技能入口的跨阶段约定。
- 用户指定风格、参考图和现有设计系统优先；未指定时采用相对低饱和、层级清晰的风格化手游 UI。
- 先建立结构与必要交互，再做视觉美化；保持图层简洁，图片、文字和背景尽量独立可编辑。
- 允许占位美术资源，交付时注明。

## 设计稿修改边界

- 修改已有界面时保留原尺寸、组件关联、Auto Layout、原型连接和用户内容，仅调整任务所需部分。
- 修改主组件前检查受影响实例；涉及任务范围外界面时，先确认共享变更范围。
- 删除、覆盖、分离实例或重建现有结构，须有明确任务依据；必要时先确认。
- 用户未要求时保持其选择、视口及其他文件不变。
- 测试副本与正式内容分开命名、放置；仅清理由本次任务创建的临时内容。

## 换皮维护源与演示场景

### 待替换区

- 本次功能的换皮维护源集中放在一个名为 **`待替换`** 的大 Frame 中，背景固定为 **`#2B2B2B`**。该名称是英文命名规则的明确例外；内部图层继续使用英文名。
- 收纳共享主组件、必要状态变体、不同主要布局的代表性源稿，以及需替换的占位图片或独立资源；不把全部演示副本搬入其中。
- 收纳 Frame 只是工作区容器，不是 1280×720 界面根节点，不承担界面自适应或原型起点；尺寸按内容设置，保留可读间距，避免裁切源稿。
- 同一外观或布局只保留一个权威维护源。代表性源稿若被多个场景复用，应组件化为屏幕或区域模板；仅摆放一张普通 Frame 作为参考，不能让其他副本自动同步。
- 展示源稿时优先用共享主组件的实例组合；组件状态按需求创建，不为了罗列演示结果扩增整屏变体。
- 跨场景复用的图片、背景和图标通过共享组件或嵌套实例引用；仅在待替换区摆放一张独立图片，不会让其他图层的图片填充同步变化。没有同步关联的素材只算参考，不算统一替换入口。
- 多个变体中相同的背景、装饰及资源也优先引用共享组件，仅将确有状态差异的外观保留在对应变体中。

### 演示复用与数量控制

- 优化目标是减少独立换皮维护源，而不是强行限制 Frame 总数。局部状态优先交互组件，弹窗优先 Overlay。
- 每增加一个独立演示 Frame，记录其覆盖的操作路径、不能用局部状态或 Overlay 表达的原因，以及引用的维护源；这份场景清单用于检查必要性，不设硬性数量上限。
- 演示场景放在待替换区之外，保持 Flow 起点与目标结构可用；不为了收纳把原型起点嵌套进普通 Frame。使用当前工具支持的顶层 Frame 或实例作为演示起点并读回验证。
- 主要布局相同、仅内容或状态不同的场景共享屏幕模板或主要区域模板；只复用按钮、卡片等小控件，不足以实现布局统一维护。只有布局确实不同的部分才单独维护。
- 整屏复用使用屏幕模板实例，或在顶层演示 Frame 中放置填充的模板实例；区域排列、面板间距及背景布局由模板管理，重复弹窗也复用维护源，避免将复制后彼此独立的整屏当成复用。
- 演示实例允许文案、数量、图标、选中状态等必要内容覆盖；共享外观从维护源继承，避免颜色、描边、图片等无必要的外观覆盖阻断换皮同步。
- 每个必要演示场景都应能追溯到待替换区的维护源。工具限制导致无法复用时，列明独立维护项并先确认，不默默交付多套需逐张换皮的页面。
- 已有设计的整理或组件化遵循修改边界，不借整理之名删除任务范围外场景或破坏连接。

## 1. 桥接与操作

### 连接与目标文件

操作路径为 **AI → Figwright MCP → 本地 WebSocket 桥接 → Figwright Figma 插件 → Figma Plugin API**。这不是官方 Figma Dev Mode MCP，也不是离线文件编辑；目标文件必须在 Figma 打开并运行插件。

- 先发现已连接的 Figwright 工具及参数 schema，用 `ping` 确认桥接，用元数据确认目标文件、页面和编辑模式。构建 UI 应在可写的 Figma Design 中执行；Dev Mode 为只读，FigJam 不适用于本规范的组件与原型任务。
- 多文件连接时先用 `list_files` 确认目标，通过 `use_file` 绑定当前会话；重名文件使用工具返回的 sessionId，不按名称猜测。目标不明确时先询问。
- 文件绑定属于 MCP 服务进程；共享该进程的子代理也共享目标。避免并行任务切换绑定，不向不支持的工具杜撰 fileId 或 documentId 参数。
- 检查服务端与插件版本兼容性；版本警告或结果中的未验证提示需要处理，工具返回成功仍须读回。插件文件夹名称不能替代运行中版本检查。
- 以当前连接的 schema 为准，不硬编码工具总数或假设所有 Figma 功能均可通过插件写入。缺少工具时报告具体缺口，不自动改用官方 Figma MCP。

### 环境阻塞

- 插件未连接时，请用户在目标文件中打开 Figwright 插件并确认 Connected；关闭插件会断开桥接，需隐藏面板时使用插件提供的后台运行功能。
- 检查 MCP 客户端是否启动服务、插件与服务是否在同机，以及版本是否匹配。需要修改配置或更新环境时先征得用户同意。
- Figwright 使用插件桥接，而非官方 MCP 调用链；Figma 文件权限、套餐功能限制及客户端工具审批仍然有效，不承诺所有操作无限制。

### 高效读写与安全验证

- 先读取页面概览、目标子树、现有组件、样式及变量；之后按节点 ID 查询，复用已知 ID，减少整页重复扫描。
- 优先复用现有组件与设计 Token；有明确参考或源代码时取其实际值，均无依据时才建立一致的样式尺度。
- 使用 `batch` 合并一个区域内的关联创建与更新；当前版本支持时用批次结果引用组织父子关系，参数按 schema。只将工具允许且可回退的操作放入批次，破坏性操作单独评估。
- 批次或连接异常后，先读取受影响节点确认实际结果再重试；不要因超时盲目重复创建。阶段结束读回关键属性，并截图目标 Frame，而非每建一个基础图层就截图。
- 文本使用可用字体；自定义脚本或工具要求加载字体时先完成加载。布局敏感操作检查实际尺寸，不能只依据 `ok: true`。
- 修改已有内容前保留适当恢复副本；只在本次修改的范围内操作。Figma 文档变更、图片导出、本地备份是不同交付物，截图不能代替可编辑原稿。
- 交付前确认修改仍存在于正确文件，并在客户端可见时检查保存/同步状态；工具无法确认云端保存时注明，不能虚构本地保存命令或文件路径。

## 2. 自适应布局

### 根容器与区域

- 根 Frame 管理主要区域的排列与空间分配，优先采用 Auto Layout；适配依靠重新布局，而非整体缩放或拉伸。
- 上下区域使用垂直 Auto Layout，左右分栏使用水平 Auto Layout。
- 顶部和底部栏通常为固定高度、宽度 Fill Container；主体区域填满剩余空间。
- 固定导航区保持所需尺寸，弹性内容区占据剩余空间；必要时设置最小宽高。
- HUD、悬浮层和特殊构图可使用绝对定位，明确锚点与 Constraints，并实测父容器尺寸变化后的效果。

### 尺寸模式按轴决定

每个布局容器分别确定宽、高尺寸模式；概念与实际工具字段按当前 schema 映射。

| 模式 | 适用情况 | 检查点 |
| --- | --- | --- |
| Fixed | 固定栏高、图标、需要稳定尺寸的控件 | 父容器变化时保持预期尺寸 |
| Hug Contents | 随内容变化的标签、按钮和内容组 | 长文本或内容增加时受合理边界约束 |
| Fill Container | 占据父容器剩余空间的区域 | 父级支持该方向填充，且可用空间可确定 |

- 父级由子级撑开时，用 Hug 配合可确定尺寸的子级；子级填充时，让父级先获得可确定尺寸，避免同一轴的父级 Hug 与子级 Fill 循环依赖。
- 按钮组、TAB 和奖励列表等重复排列使用 Auto Layout；根据内容选择间距、换行或滚动策略。
- 组件与实例正常参与父级布局；实例宽高模式按使用位置配置，组件化和状态切换保持布局策略有效。
- Auto Layout 内普通子节点的位置由布局管理；定位需求优先用对齐、间距和包裹容器表达，确需脱离布局流时才设置绝对定位。

### 背景与溢出

- 纯色背景优先使用容器 Fill；独立背景图或装饰层可脱离布局流，通过 Constraints 随容器调整，避免挤占内容空间。
- 内容面板按布局职责设置 Fill；图片选择合适的填充或适配方式，保持主体比例。
- 文本明确选择换行或截断；长列表明确选择换行、滚动或分页。设计中表达的滚动区域与演示中实际可滚动是两项独立检查。
- 裁剪用于有意限定的视口；意外溢出应修复布局原因，而非仅隐藏问题。

## 3. 组件、状态与内容

### 复用与绑定

- 重复出现或需要统一维护的 UI 使用真实 Component 和 Component Instances，优先复用已有组件，而非逐份重建主组件。
- 内容差异使用下表属性，并绑定实际图层；通过实例修改验证文字、显隐或嵌套实例确实变化。

| 差异 | 使用方式 | 示例 |
| --- | --- | --- |
| 文本内容 | Text Property | `Label`、`Title`、`Quantity` |
| 可选元素显隐 | Boolean Property | `ShowBadge`、`ShowIcon` |
| 嵌套组件替换 | Instance Swap Property | `Icon`、`RewardIcon` |
| 组件状态 | Component Set + Variants | `State=Selected/Unselected` |

- Instance Swap 对象应为嵌套实例，普通位图按资源处理；不为文案、数量或图标差异扩增变体。
- 使用工具返回的真实属性标识创建绑定或修改实例，不假定显示名称就是 API 属性键。
- 创建后读取节点类型、主组件关联和属性绑定；安全验证主组件变更能同步到实例。普通 Frame 副本不视为实例。

### 状态

- 同一组件的明确状态使用真实 Component Set 和 Variants，例如 `State=Locked/Available/Claimed`；仅创建需求中的状态和组合。
- 对应变体尽量保持外部尺寸、结构和图层命名一致，以便保留覆盖值。展开或改变尺寸时验证父级重新布局。
- 在实例上切换本次新增或修改的全部状态，确认内容覆盖值、尺寸模式和布局有效。
- 属性和变体定义设计内容与状态，不自动产生演示交互；原型触发和动作另行配置。

## 4. 基础原型交互

仅使用 **Figma 原生 Prototype** 模拟操作流程和反馈，默认采用预设内容与状态。完成标准是约定路径可操作、反馈清楚，足以支持策划、程序讨论，而非真实业务规则运行正确。不实现业务计算、数据持久化、外部服务调用或额外应用。本节约束 Figma 原生原型；前置 HTML 同样需要可体验的界面交互，其实现及验收见 [HTML 预览规范](layout-preview.md)，不受 Figma Plugin API 能力限制。

### 范围与路径

- 新建功能 UI 默认包含基础原型；用户只要静态稿时除外。已有 UI 仅补齐受影响的核心交互。
- 明确演示起点和初始状态，至少覆盖“进入 → 操作 → 结果 → 返回或继续”的核心闭环。
- 根据需求补充取消、条件不足、已领取等关键分支，优先局部状态或复用弹层；确需新场景时按维护源复用规则组织，无需真实判断余额、扣费或发奖。
- 核心控件记录“触发方式 → 动作/目标 → 可见反馈”；演示范围外入口注明占位。
- 数量、价格、奖励和条件等样例数据注明为模拟；未确认规则列为待讨论，并记录当前假设。

### 交互选择

| 场景 | Figma 原型方式 | 验收重点 |
| --- | --- | --- |
| 页面进入与返回 | Navigate to；按访问历史返回时使用 Back | 固定目标与历史返回区分，路径正确 |
| 弹窗与二次确认 | Open overlay / Close overlay | 能打开、关闭、取消，遮罩行为明确 |
| 开关、折叠、局部状态 | 交互组件 Change to | 反馈与状态同步，切换不破坏布局 |
| TAB 与内容 | 包含 TAB 与内容区的父组件切换变体，或跳到对应预设场景 | 选中项与内容同步；单个 TAB 的状态不会自动驱动旁边内容 |
| 长列表与页内定位 | 滚动区域 / Scroll to | 能浏览目标内容，固定区域行为符合约定 |
| 提交、领取、购买结果 | 切换结果变体、打开结果弹层或跳转结果场景 | 展示预设成功或失败反馈，不执行真实操作 |

- 优先使用原生连接、交互组件和少量场景；仅当无法清楚表达核心交互、用户确有需要且工具支持时，使用少量原型变量或条件。
- 独立根 Frame 可表达不同页面或流程场景，其中相同 UI 仍用组件实例；同一组件自身的状态按第 3 节管理。
- 点击热区覆盖实际控件且不遮挡相邻操作；必要点击路径不依赖 Hover。动效默认即时或简短过渡。

### Figwright 原型读写

- 配置前用 `get_reactions` 读取受影响节点。**`set_reactions` 替换该节点的全部 reactions，不是追加**；合并本次变更并保留范围外连接后再写入，避免清空原有交互。
- 动作以当前 schema 为准：界面的 Navigate to、Overlay、Change to 等在桥接中使用相应的 trigger/actions 和目标 ID，不把界面名称当作工具名或随意拼 JSON。
- 写入后读回 reactions，核对触发器、动作、目标、过渡及组件状态目标。目标 ID 应来自实际节点，避免连接到临时测试副本。
- 用 `get_pages` 检查页面 Flow；支持时通过 `update_flows` 配置起始 Frame 和演示名称，仅修改任务相关 Flow。Flow 名与 Frame 名不是同一字段，新增连接可能由 Figma 自动产生默认 Flow，需读回确认。
- 部分设置受 Plugin API 限制。例如 Overlay 相对偏移仅在目标 Frame 已采用 Manual 定位时生效，而该定位设置可能需要用户在 Figma 手动配置；记录具体步骤，不能把成功写入连接当作该设置已完成。
- 工具不能配置的属性或交互明确列为手动项；静态场景和截图只能辅助说明，不计为可点击原型完成。

### 演示与重置

- 明确恢复初始状态的方法，并在演示中复测；不能假定 Navigate to 起始 Frame 会清除组件或变量状态。
- 状态仅需在约定路径内一致，不要求完整存档或跨场景业务系统。
- 连接已写入但无法打开演示验证时，标为“已配置、运行未验证”，提供人工走查步骤。

## 5. 验证与交付

每项适用检查标为通过、失败或未验证，不适用项说明原因。节点属性、截图和实际演示分别记录，只有实际执行且达到标准的检查可标为通过。

### 结构与保存

- 根 Frame 尺寸符合约定；主要区域的布局方向、间距、内边距、宽高模式及约束正确。
- 重复元素为关联正确主组件的实例；多状态为同一组件集中的真实变体。
- 内容属性经实例修改测试；状态切换保留预期内容和布局。
- 已有内容和范围外结构、原型连接保留；共享组件变更已检查受影响实例。
- 新建或调整重要界面方案时，与用户确认的 HTML 版本对照区域、比例、内容层级、图标文字表达及核心交互；未经确认的结构性差异或未说明的交互降级不算通过。
- 正确文件中的修改可读回；保存/同步状态可确认时已检查，否则说明尚未验证。

### 换皮维护检查

- 读取待替换区的类型、名称与背景色，确认是 Frame、名为 `待替换`、Fill 为 `#2B2B2B`；原型起点及演示副本位于其外。
- 对照场景清单检查每个演示场景到布局模板、共享区域、控件和资源的关联；查找分离实例及阻断同步的外观覆盖，确认布局相同的场景不需逐屏调整排列和间距。
- 同步测试须隔离待测主组件、共享资源组件及其依赖实例，读取主组件关联，确认测试实例指向测试主组件而非正式源。普通演示 Frame 克隆不自动满足隔离条件；无法安全隔离时标为未验证，不修改正式主组件试验。
- 在隔离副本中修改测试主组件的一个共享外观及一个共享资源，检查与实际依赖关系对应的测试实例是否同步；布局模板还需测试间距或区域排列的传播。修改实例覆盖值不算主组件同步测试，通过一个实例不代表所有场景通过。
- 测试后仅清理由本次任务创建的隔离副本；保留测试修改、关联读回及依赖实例检查结果，未覆盖的传播路径标为未验证。
- 维护入口之外发现仍需逐张换皮的独立副本时，合并为维护源复用，或记录限制并取得用户认可后交付。

### 尺寸与视觉

新建界面默认逐项测试以下尺寸；用户另有适配范围时按约定。修改已有界面时，测试原尺寸及约定范围内的以下尺寸。

| 分辨率 | 测试目的 |
| --- | --- |
| 1280×720 | 默认设计基准 |
| 1600×900 | 较大 16:9 |
| 1920×1080 | 高清分辨率 |
| 1280×800 | 不同宽高比 |

- 在临时副本中调整根 Frame，不手调子节点、不整体缩放，正式稿保持约定尺寸。
- 各尺寸检查关键区域边界并截图：固定区稳定、弹性区填充，无意外重叠、溢出、遮挡或异常拉伸。
- 检查裁切、对齐与视觉层级；在最受约束布局下测试长文本和变体切换，必要时扩展尺寸。
- 只读任务无法安全执行尺寸测试时标为未验证。失败项记录节点、尺寸和现象，修复后复测；适配受限则说明最低尺寸或原因。

### 原型走查

- 检查实际 reactions 和 Flow，再在 Figma 演示模式从约定起点走完核心路径及关键分支；结构截图不替代演示运行。
- 验证点击热区、弹窗打开关闭、返回、TAB 内容联动、结果反馈及必要滚动，确认禁用或已完成状态符合预设。
- 按约定方式恢复初始状态并重复演示，确认无意外死路、遮挡或残留状态影响。
- 失败项记录操作控件、步骤、预期与实际结果；无法启动或操作演示时保留运行未验证项及人工清单。

### 交付记录

最终回复简洁包含：
1. 目标 Figma 文件、页面、根 Frame 名称和节点 ID；仅在可获取时提供真实设计/原型链接。
2. 该功能的原型说明位置，其中记录界面方案确认依据、HTML 路径与确认版本及实现差异；局部修改不适用时注明。

5. 各尺寸结果，以及结构、属性、换皮同步、原型运行和保存/同步检查结果。
