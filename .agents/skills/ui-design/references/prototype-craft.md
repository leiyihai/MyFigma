# 原型工艺：不像 AI 生成的界面

> 本文件的工艺标准改写自 [unslop](https://github.com/heydamir/unslop)（作者 Damir Sokolovsky，[@heydamir](https://x.com/heydamir)，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)）。原技能做的是「事后给已经生成、一眼像 AI 的界面做红线路审」；这里只取它的工艺判断，改写成**生成时**就照着走的标准，删去它的修图流程、图像生成和视频部分。本文件同时合并了设计台自带 `ui-design` 技能里「设计原则 / 别有 AI 味 / 自查」三节中仍然适用的部分。

用于新建或改造灰阶交互原型；只读检查按范围选用。以下是默认工艺，不覆盖用户明确要求或已确认方案；修改现有稿先保留其视觉语言，重要偏离先确认。

## 三个判断

- **一屏一个焦点**：每屏只有一处承载对比和最重的视觉重量（最大的字、最亮的实心块、唯一的满色按钮），其余结构层压低。有第二处在抢，就是没有焦点。
- **把「富」留给内容，骨架退后**：好界面把细节和重量放在用户真正要看的东西上（卡片里的内容、模型区、列表行），导航、分割线、标签、容器都安静。灰阶里这意味着一屏只有 2–3 档明度在说话，不是十档相近的灰。
- **换个产品名还成立，就是模板**：把界面上的产品名换成另一个产品的名字，如果毫无违和，说明版式和文案没有从需求里长出来，重做方向而不是调参。

## 1. 间距与栅格

- 全部落在 4 的倍数上：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。小控件内部允许 2px 微调；为了精确居中而产生的奇数值可以留。
- 同类同距：同一列的卡片同一个内边距，同一列的行同一个高度和同一个间隔。
- 间距表达分组：组内 < 组间 < 区块间。列表读起来是一块，区块读起来是几块。
- 对齐成列：图标一列、标签一列、数字右对齐。不靠零散的 `translate` 或 `margin` 把元素挪出这条线。
- 密度分档：紧凑面板 / 侧栏内边距 16，卡片 20–24，页面边距 24–32。全屏界面按 1280×720 的实际视口算，不要为了「透气」把一屏撑出滚动条。
- 删掉破坏节奏的一次性数值（`margin-top: 13px` 这种），换成上面的台阶。

## 2. 层级与灰阶

- 文字只有三个角色：主要、次要、弱化（例如 `#1f1f1f` / `#6b6b6b` / `#9a9a9a` 一档）。不要出现七八种灰度。
- 分隔优先用间距和明度差，其次才是 1px 线；线要淡（同色系 8–12% 的观感），不要处处描边。
- 主操作只有一个，做实心块；次操作降成描边或纯文字。两个同等强度的按钮摆在底部，就是没有主操作。
- 选中态用一档表面明度变化 + 细线，不要用渐变或发光模拟。
- 状态色（成功 / 警告 / 危险）只在灰阶原型里用明度差或一个标记表达；需要颜色时也只用一档，不铺开。

## 3. 字号与排版

- 字号阶梯取 1.2–1.25 的比例，例如 12 / 14 / 16 / 20 / 24 / 32 / 40 / 56；一屏最多四档。
- 正文 15–16px，行高 1.5–1.7；标题行高 1.1–1.3，大标题字距略收。小字不做负字距，要显眼就加字号或字重。
- 层级靠字号和明度，不靠一路加粗。
- 中文：不用斜体；重 400/500/600，标题最多 700；中英文与数字之间加空格；标点全角；正文行高比英文略大。
- 标题不要一行只剩一两个字（`text-wrap: balance` 或调宽度）。
- 数字用等宽数字（`font-variant-numeric: tabular-nums`），全屏同一套格式。

## 4. 形状与层次

- 圆角一套：控件 8–10、卡片 12–16、面板 14–20。不是什么都做成胶囊。
- 嵌套圆角 = 外圆角 − 内边距，且不小于 4，否则内外圆弧会打架。
- 灰阶下的层次主要靠明度台阶和细线，不靠阴影堆叠；需要浮层时才用一个柔和的中性阴影。
- 计数、单位、次要元信息做成小号弱化文字，不要做成发光胶囊或贴片。

## 5. 文案

- 界面只写玩家会读到的话：标题、说明、按钮、状态、数值、空态。句尾不加句号（整段说明除外），不用感叹号。
- 不喊口号：不用「极致」「畅享」「赋能」「一站式」「焕新」这类词，也不写只有内部人懂的缩写。
- 标题说清这一屏是什么（「限时体验卡」），不要写「欢迎回来 👋」这种招呼语。
- 样例数据要像真的：具体的天数、价格、阶数、卡名，不用「文本」「123」「[X]」占位。
- 状态文字要说明白处境，例如「还差 2 件 · 3 天后失效」，而不是「状态：流失中」。
- **需求文档里的规则句不进界面**：状态矩阵、判定条件、数据结构、埋点、验收清单的措辞属于实现，不是玩家看到的文案。判断不进界面的边界见 [界面对齐](ui-alignment.md#需求文档怎么读)。

## 6. 图标

- 一套线性图标、同一线宽（1.5–2）、同一网格（24），内联 SVG。
- 不用 emoji 当图标；也不为装饰而加图标，尤其是每个小标题前都放一个。
- 图标跟着文字的层级取色（次要或弱化），不单独着色。

## 7. 布局与节奏

- 不要每个区块都居中、每段都是「图标 + 标题 + 一句话」的三栏卡片——这是最快被认出来的 AI 版式。
- 疏密要有对比：一处大留白撑住焦点，另一处信息密一点。全都均匀，读起来就平。
- 首屏自上而下是完整的一屏：标题、主体、主操作都在视口内，不要出现「差一点才看到按钮」的裁切。
- 主操作的位置按全屏游戏的惯例（底部或右下角固定），不要被滚动带走；固定区要预留高度，滚到底的最后一行不被压住。
- 同类列表卡片保持尺寸和对齐一致；主展示与辅助区通过比例、留白和内容密度形成节奏，不为变化而打乱列表扫描。

## 8. 动效

- 默认过渡 150–250ms，`cubic-bezier(.2,.8,.2,1)` 一类缓动；优先只动 `transform` 和 `opacity`。需求明确的状态动效与时长按确认方案执行。
- 不做无意义的循环动效（呼吸、闪烁、漂浮），不做悬停放大，不做弹跳过冲。
- 动效必须解释状态：出现、消失、切换、数值变化。解释不了就删掉。
- 加 `@media (prefers-reduced-motion: reduce)` 关掉非必要动效。

## 9. 一眼看出是 AI 的清单（撞上就改）

- 紫蓝渐变、霓虹发光、彩色光晕、渐变文字、玻璃拟态到处糊。
- 每块都居中、每段都是三栏图标卡片；所有卡片都带大阴影和描边。
- emoji 当图标、装饰性的圆斑和波浪线。
- 米色底 + 衬线大标题 + 砖红的「AI 设计味」；或者反过来，什么都往深色霓虹上靠。
- 没有内容的空话文案，一屏五六个颜色。
- 占位数据长得像占位（「标题一」「示例文字」），或者规则原文直接印在界面里。

## 做完过一遍

- [ ] 一屏只有一个焦点，主操作只有一个
- [ ] 间距全在 4 的倍数上，同类同距，左边缘对齐成列
- [ ] 文字只有三档角色，分隔靠间距和明度而不是满屏线框
- [ ] 一屏最多四档字号，中文没有斜体，数字等宽
- [ ] 圆角成套，嵌套圆角对得上
- [ ] 文案像真产品，没有口号、没有感叹号、没有需求文档的规则句
- [ ] 图标一套、同线宽，没有 emoji 图标
- [ ] 版式有疏密对比，不是均匀三栏
- [ ] 动效解释状态，时长符合确认方案，可被 `prefers-reduced-motion` 关掉
- [ ] 把产品名换成别的产品名，这屏还成立吗？成立就重做方向
