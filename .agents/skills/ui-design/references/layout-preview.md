# 可交互 HTML 制作与自查

预览默认是可交互的灰阶 HTML，而非纯静态线框。已有方案确认直接接手；缺少确认或重要决策变更时，先补齐[界面对齐关卡](ui-alignment.md)。用户明确仅需静态稿时按其要求执行。

## 1. 生成产品界面

- 生成可在本地浏览器直接打开的单文件 HTML，CSS、必要 JavaScript 和占位资源内联；无需构建工具、外部服务或真实数据。以已确认方案为依据，修改已有文件时保留本次范围外的用户调整。
- 默认入口仅呈现产品界面及中性承载背景，不附评审标题、版本条或演示工具栏。需求明确需要演示控件时，按对齐阶段确认的入口和范围提供；必要假设只在对话简短说明，不为 HTML 另写说明文档。
- 内容与行为按[需求文档怎么读](ui-alignment.md#需求文档怎么读)处理：玩家文案呈现在界面，影响状态和操作的规则落成交互，规则措辞不抄成旁注。需求点名的说明区保留其可见要点。
- 按任务约定的基准尺寸呈现界面。小视口可提供单纯的适屏查看方式，不能额外加入评审面板，也不能把浏览器缩放视为自适应验证。
- 主要区域用不同明度的实心灰色区分；嵌套关系结合灰阶差异、间距和留白表达，灰阶不代表最终美术配色。
- 按实际形态排列标题、按钮、列表行、奖励卡片和图片占位，使区块用途直观可辨；仅保留实际 UI 文案，不添加“顶部导航”等用途标签，也不以空盒子代替内容布局。
- 图标与文字遵循已确认的控件方案；灰阶和占位不降低含义辨识度，不以外部说明弥补不清楚的操作。HTML 可保留轻量 SVG 图标，转 Figma 时采用单层 PNG 图标规范，不逐路径复刻。
- 背景和 3D 世界场景只需表达环境与空间，默认使用下述脚本的极简 PNG 模板，HTML 与 Figma 复用同一图片；纯色背景直接填充。不为临时美术细节生成长 SVG 或大量 DOM；拍照等交互可切换预设图片，实际 UI 控件保持独立。
- 使用代表性的文案长度和内容数量，有策划样例时优先采用；必要的样例假设在对话简短说明，避免用极短文案或过少条目掩盖拥挤。
- 复用界面结构和局部状态，不为每个数值、文案或领取状态复制整页。通过产品内入口体验路径；难以自然到达的演示状态可提供单独文件或地址入口，交付时简短给出必要入口。

**完成标准**：HTML 可打开且默认只有产品界面（另行确认的演示入口除外），主要分区和操作位置可直接辨认；交付时给出文件路径，必要时区分版本，不往画面添加版本标记，也不生成补充文档。

### 占位资源脚本

需要背景／场景或 Figma 图标占位图时调用[资源脚本](../scripts/render_assets.py)（路径相对于本参考文件，不是当前单项技能目录），不先在 Figma 搭复杂图层再截图。需要 Python 与 Pillow；缺少依赖时先报告并征得安装同意。模板支持项和命令参数用 `--help` 查，不在每轮重写生成脚本。

以下示例从仓库根目录执行；按当前技能位置、功能目录和所需语义调整路径及选项：

```bash
python .agents/skills/ui-design/scripts/render_assets.py generate --output-dir "交付/<功能>/assets" --scenes world landscape --icons like people camera
```

- 仅生成需要的模板与图标，尺寸、颜色等通过参数指定；同类资源复用输出，不为每个实例重复生成。不支持的业务语义先选可辨识的简单表达，不为占位资源展开复杂绘图。
- 已有本地图片需要叠合时使用 `compose` 子命令，按其 `--help` 的小型 JSON 配置生成一张 PNG；合图仅包括美术，不合并文字、按钮结构和交互控件。
- 单文件 HTML 可先用 `asset://scene-world.png` 等引用生成图片，再调用 `embed --html <输入HTML> --asset-dir <资源目录> --output <交付HTML>` 内联到单独输出文件；资源名可复用在 HTML/CSS/JS 字符串中。脚本直接处理 Base64，仅返回路径、尺寸等摘要，不读取或打印大段编码内容给模型。
- 输出 PNG 留作 Figma 导入源；HTML 内联后不依赖这些外部文件。脚本默认拒绝覆盖文件，使用新路径或在明确需要时指定 `--force`；已有用户 HTML 不因资源规范变化自动重写。
- 生成成功不代表已视觉验证；检查图片尺寸、透明度与含义，合图和模板不能替代实际界面适配检查。

## 2. 默认补齐需求交互

- 对照需求和已确认方案逐项落实“入口／操作 → 反馈 → 状态变化 → 返回或继续”，首版即覆盖需求交互及基本配套；检查在执行过程中完成，不另生成交互清单文件。
- TAB 切换同步内容，列表项打开对应详情；按方案实现弹层、侧栏的打开、关闭和返回，正确处理遮罩、选中态及多层面板关系。
- 长列表和面板实际可滚动；需求包含轮播、分页、加载或刷新时实现对应模拟，保持约定的滚动位置和加载反馈，而非静态文字描述。
- 输入、单选／多选、编辑、保存和取消可体验：保存后本次会话的展示内容同步更新，取消保持原值；不能仅弹“成功”而不产生约定结果。数据只保存在当前演示所需的内存状态，不要求存档。
- 禁用、已完成、空态和加载等按需求及确认方案呈现；不凭空增加失败分支或业务条件。会影响界面判断的缺失规则返回对齐关卡，其余用已说明的样例假设推进。
- 游戏引擎、真实拍摄、网络提交、扣费或发奖等用预设结果模拟；反馈保持路径内一致，不接真实账号、支付、后端或持久化系统。页面内必要的状态更新不是完整业务实现。
- 除非需求明确需要复杂动画，采用清楚、简短的状态过渡。范围外的现有系统入口可保留并在对话简短说明边界，不能将需求内交互悄悄降为无效入口。
- 明确重新开始的方式，例如刷新恢复初始内存状态；默认不额外放演示重置按钮，需求本身有重置操作时除外。

**完成标准**：需求中的交互逐项实现并检查；必要缺口在对话简短指出，静态占位、外部场景菜单切换或笼统成功提示不算交互完成。

## 3. 展示、自查与等待

- 按[设计台能力适配](studio-tools.md)展示当前版本，查看真实渲染并按确认尺寸测量；覆盖本次新增／修改的屏及关键状态，长列表检查滚到底后的内容和固定栏。按清单修正并复测受影响内容。
- 按[原型工艺](prototype-craft.md)自查版式、文案与图标一致性。需求明确的特殊表达优先于默认工艺，不能为统一风格改掉确认方案。
- 对照确认范围实际走完核心操作和关键状态：切换内容同步、弹层打开／取消／关闭、返回、状态迁移、禁用条件和重新开始。计时类检查达标瞬间停表；一次性操作检查不能重复触发。外部系统仅验证约定模拟反馈。
- 渲染／尺寸体检与操作走查分别记录；没有操作工具时保留交互未验证，不能拿静态代码或截图冒充点击成功。工具缺失的降级按能力适配参考处理。
- 给出当前 HTML 路径／版本、实际检查结果和必要缺口，等待用户体验。不自动进入 Figma；用户另行请求时转 `ui-design-figma` 核对版本与写入范围。

**完成标准**：确认范围内交互已实现；渲染、尺寸测量、实际操作三类检查各有覆盖与结果，发现的问题已修或明确说明未修／未验；当前版本可交给用户体验，不将交付等同于全部测试通过。
