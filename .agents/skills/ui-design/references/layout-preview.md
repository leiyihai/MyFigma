# 布局预览与确认关卡

新建界面或改变已有界面的主要布局时，在写入 Figma 前执行本流程。只读检查，以及文案、颜色、图标等不改变主要布局的局部调整，不必重走确认关卡。

## 1. 生成最小预览

- 先明确区域、信息层级、内容顺序、主要按钮与弹窗位置；需求不清且影响布局时先确认。
- 生成可在本地浏览器直接打开的单文件 HTML 灰阶块面布局预览，CSS 内联；无需构建工具、外部依赖或真实数据。
- 主要区域使用不同明度的实心灰色填充，让相邻区块明确可辨；嵌套关系结合灰阶差异、间距与留白表达。灰阶用于区分布局，不代表最终配色或美术风格。
- 按预期形态与位置摆放界面标题、按钮、列表行、奖励卡片及图片占位，使区块用途从内容和结构中直观可辨；保留界面自身文案，不额外添加“顶部导航”“任务列表”等解释用途的标签，也不以空盒子或边框替代内容布局。
- 按任务约定的基准尺寸展示；区域比例、固定／弹性策略及状态差异的说明放在预览界面外，界面内仅保留实际 UI 文案。浏览器缩放预览只是查看方式，不是自适应验证。
- 使用有代表性的文案长度、列表项数量和奖励数量；有策划样例时优先采用，未明确时注明样例假设，避免用极短文字或过少条目掩盖拥挤问题。
- 覆盖不同主要布局的代表性状态；仅数值、领取状态或文案不同的情况在界面外说明，不为每个演示分支复制预览。
- 不实现点击业务、后端、存档或复杂动画。此 HTML 是布局讨论产物，不是正式应用，也不是 Figma 交互原型的替代品。
- 使用有明确位置、可再次打开的文件，并标记版本或修订编号；修改用户已有预览时遵循项目修改边界。

**完成标准**：预览文件已生成，即使不看边框和额外用途说明，也能通过灰阶块面与内容排列辨认主要区块、嵌套关系及操作位置。向用户提供路径、版本及简短布局说明，说明放在界面外；有浏览器或截图能力时检查实际显示，无法运行时说明限制，不声称已渲染验证。

## 2. 展示并等待

- 邀请用户检查区域比例、内容排列、主要按钮和弹窗位置，讨论并修订预览。
- **展示后停止，等待用户明确确认当前版本，再开始 Figma 创建或布局修改。** 用户确认功能需求、同意制作预览或 AI 自检通过，都不等于布局确认。
- 确认前可只读检查已有设计、组件和工具能力；不创建“先做再改”的 Figma 骨架，不把未确认布局扩展成多份场景。

**完成标准**：对话中有用户对具体预览版本的明确认可。仅有未回答的问题、含糊评价或 AI 自行总结时，关卡仍未通过。

## 3. 按确认版搭建

- 以确认版的区域、比例和排列为布局依据，转换为可维护的 Figma Auto Layout 与组件结构，不照搬 HTML 绝对坐标。
- 实现发现主要布局需要改变时，先更新预览并重新确认；局部对齐、间距微调且不改变主要结构时直接调整。
- 完成 Figma 骨架后，与确认版逐项对照主要区域、相对比例、内容顺序和操作位置；功能齐全但布局不符仍需修正。
- 交付时指出采用的预览文件与版本，以及必要的实现差异。

**完成标准**：实际 Figma 布局与用户确认版一致；有结构性差异时已获得重新确认。
