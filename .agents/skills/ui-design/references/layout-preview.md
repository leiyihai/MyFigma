# 可交互 HTML 预览与 Figma 确认关卡

本文件沿用 `layout-preview.md` 文件名；预览默认是可交互的灰阶 HTML，而非纯静态线框。制作前先完成 [界面对齐关卡](ui-alignment.md)。用户明确仅需静态稿时按其要求执行。

## 1. 生成产品界面

- 生成可在本地浏览器直接打开的单文件 HTML，CSS、必要 JavaScript 和占位资源内联；无需构建工具、外部服务或真实数据。以已确认方案为依据，修改已有文件时保留本次范围外的用户调整。
- 页面默认仅呈现产品界面及中性承载背景。评审标题、版本条、场景选择器、计数、重置工具栏等不放入 HTML；方案、假设和使用说明统一写入该功能的原型说明（维护方式见界面对齐关卡），对话只给摘要。
- 按任务约定的基准尺寸呈现界面。小视口可提供单纯的适屏查看方式，不能额外加入评审面板，也不能把浏览器缩放视为自适应验证。
- 主要区域用不同明度的实心灰色区分；嵌套关系结合灰阶差异、间距和留白表达，灰阶不代表最终美术配色。
- 按实际形态排列标题、按钮、列表行、奖励卡片和图片占位，使区块用途直观可辨；仅保留实际 UI 文案，不添加“顶部导航”等用途标签，也不以空盒子代替内容布局。
- 图标与文字遵循已确认的控件方案；灰阶和占位不降低含义辨识度，不以外部说明弥补不清楚的操作。
- 使用代表性的文案长度和内容数量，有策划样例时优先采用；样例假设记入原型说明，避免用极短文案或过少条目掩盖拥挤。
- 复用界面结构和局部状态，不为每个数值、文案或领取状态复制整页。通过产品内入口体验路径；难以自然到达的演示状态可提供单独文件或地址入口，使用方法记入原型说明。

**完成标准**：HTML 可打开且默认只有产品界面，主要分区和操作位置可直接辨认；产物路径和版本在原型说明中可追溯，不需要往画面添加版本标记。

## 2. 默认补齐需求交互

- 从需求和已确认方案提取“入口／操作 → 反馈 → 状态变化 → 返回或继续”的交互清单，更新到原型说明。首版即覆盖需求明确提到的交互及使其可用的基本配套，不等用户逐次要求把按钮接上。
- TAB 切换同步内容，列表项打开对应详情；按方案实现弹层、侧栏的打开、关闭和返回，正确处理遮罩、选中态及多层面板关系。
- 长列表和面板实际可滚动；需求包含轮播、分页、加载或刷新时实现对应模拟，保持约定的滚动位置和加载反馈，而非静态文字描述。
- 输入、单选／多选、编辑、保存和取消可体验：保存后本次会话的展示内容同步更新，取消保持原值；不能仅弹“成功”而不产生约定结果。数据只保存在当前演示所需的内存状态，不要求存档。
- 禁用、已完成、空态和加载等按需求及确认方案呈现；不凭空增加失败分支或业务条件。会影响界面判断的缺失规则返回对齐关卡，其余用已说明的样例假设推进。
- 游戏引擎、真实拍摄、网络提交、扣费或发奖等用预设结果模拟；反馈保持路径内一致，不接真实账号、支付、后端或持久化系统。页面内必要的状态更新不是完整业务实现。
- 除非需求明确需要复杂动画，采用清楚、简短的状态过渡。范围外的现有系统入口可保留并在独立说明标明边界，不能将需求内交互悄悄降为无效入口。
- 明确重新开始的方式，例如刷新恢复初始内存状态；默认不额外放演示重置按钮，需求本身有重置操作时除外。

**完成标准**：交互清单每一项均有实现及检查结果；缺口明确标记，不能把静态占位、外部场景菜单切换或笼统成功提示当作交互已完成。

## 3. 运行检查、展示并等待

- 有浏览器能力时实际打开：检查画面无额外评审内容、无意外裁切或遮挡；按交互清单走完核心路径和关键状态，验证内容同步、取消、返回和重新开始。
- 无运行能力时说明限制，区分代码已实现与运行未验证，提供人工检查步骤，不声称已点击走查。
- 更新原型说明中的路径、版本、检查结果和待决项，在对话给出摘要并邀请用户体验、修订；页面本身继续仅呈现产品界面。
- 展示后等待用户体验和反馈，不主动进入 Figma。根据上下文识别用户希望从 HTML 讨论转入 Figma 制作阶段的意图，不依赖固定口令或关键词；例如“开始做设计稿”“照这个落到 Figma”“可以搭正式页面了”均可能表达该意图。意图不明确时先澄清；明确时指出当前 HTML 文件和版本，询问其是否已满足需求、可否按该版本开始 Figma 制作，措辞可自然调整。
- **阶段切换请求本身不是满意确认。收到上述询问的明确肯定答复后，才开始 Figma 创建或布局修改。** 用户提出修改时先修订 HTML，再确认新版本；用户确认后同一轮切换不重复询问，版本变化则重新确认。
- 将本次确认依据写入原型说明；确认前只允许只读检查 Figma 设计和工具能力，不创建骨架。仅 HTML 任务停留在反馈阶段。

**交付状态**：可将已实现的 HTML 交给用户体验，但运行检查只按实际结果标记；无法操作浏览器时保留“运行未验证”，不能宣称测试通过。

**进入 Figma 的标准**：已针对当前 HTML 版本询问是否满足需求，并获得明确肯定答复；已知缺口和未验证项在询问前说明。用户认可不改变这些检查的实际状态。

## 4. 按确认版搭建 Figma

- 以确认版的区域、比例、内容层级、控件表达及交互反馈为依据，转换为 Figma Auto Layout、组件和原生原型，不照搬 HTML 坐标或生成真实应用。
- 实现发现重要界面决策需要改变时，先确认受影响方案，更新 HTML 并重新取得版本确认；不改变主要方案的对齐、间距等微调直接调整。
- 对照主要区域、比例、内容顺序、操作位置和核心交互。Figma 原生能力或桥接无法等价表达的 HTML 交互应说明差异和手动项，不为了强行一致扩增独立维护页面或复杂逻辑。
- 交付时指出确认的 HTML 文件与版本，以及已确认的实现差异。

**完成标准**：Figma 与已确认版本的界面和交互意图一致，结构性差异或能力降级已明确并获得认可。
