# 增量补齐：基于实际换皮成果扩展

用于已有代表界面／维护源的任务；共用维护与保护规则见[Figma 换皮维护](figma-ui.md)。本分支不是把首批重建成“完整版”。

1. 确认本批换皮已就绪、用户指定的待补页面／状态及设计版本。信息已明确就复用，不重走首批访谈；“继续”但就绪或范围不清时，只补问缺项。
2. 读取实际源、实例、资源与本次相关属性，保留用户已经调整的外观、尺寸、内容覆盖和关联。此前 HTML 是视觉依据，不是覆盖已换皮成果的理由；重要冲突先确认。
3. 对待补范围只判断三类：**已有源直接复用／调整实例属性或布局即可／确需新的独立维护源**。前两类直接增量组装；第三类说明缺口与新增换皮工作，经确认后作为新批次，不重列已有组件。
4. 在获准范围内补齐界面与必要视觉状态。可以完成指定的全部页面，但不穷举状态组合、重复搭已完成区或顺带新增多尺寸；局部差异不复制整屏。
5. 定向检查本批新增／修改内容与依赖路径。新增源才追加原貌参考；没有新增源不重复拍基线，也不要求用户再换一遍皮。

**完成标准**：指定范围已补齐，复用了实际维护源，用户成果保持，新增独立源经确认，证据及必要缺口清楚。暂缓项仍按范围说明，不冒充完成。

**停止点**：有新增换皮源时交给用户换皮并等待；没有新增源时交付本批结果。任一情况都不自动开启下一批。
