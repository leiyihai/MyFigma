# 设计台能力适配

技能需要的是能力和证据，不绑定某个客户端。DSH 专用设计台与通用设计台不要求功能对等，也不改变任务的确认关卡。

## 共用验收口径

| 能力 | 应记录的证据 |
| --- | --- |
| 预览 | 当前文件／版本、展示是否成功、目标视口 |
| 看渲染 | 实际渲染截图、覆盖的屏／状态与尺寸 |
| 按尺寸检查 | 实测视口、页面高度、问题位置与数字；失败或未覆盖项明确保留 |

实际点击和状态迁移验证是另一项：截图、DOM 检查或零错误不能证明交互通过。只记录确实操作过的路径；没有安全的操作工具时请用户体验，并标明交互未验证。

## DSH 专用设计台

宿主提供工具时，HTML 阶段用以下三项，不把插件其他功能或风格流程引入本项目：

1. 首屏写好即调用 `preview_page`，`target` 为 HTML 绝对路径，`kind: "web"`，`size` 显式使用确认尺寸（默认 `"1280x720"`）。后续源文件修改自动刷新；多个页面放在独立设计目录，避免把无关 HTML 一起展示。
2. `look_design` 使用相同 `size` 看真实渲染；长页必要时看底部，按任务检查相应屏与关键状态。
3. `check_design` 的 `sizes` 显式给相同尺寸，核对返回的实际测量尺寸；制作任务按问题清单修正并复测受影响屏；只读检查仅记录问题，不修文件。若工具退回侧栏测量，核对其尺寸，不把缩放显示当作基准视口验证。

只有面板没开不等于工具缺失；先按实际工具返回区分预览失败、浏览器不可用和尺寸未验证，不改 profile 来获得能力。不另造浏览器截图替代这三项；实际操作测试可使用可用的浏览器控制工具，独立于这三项记录。

## 通用设计台与能力缺口

仓库提供独立[通用设计台](../../../../tools/design-studio/README.md)：浏览器界面供用户体验，命令行供 AI 取得渲染与测量证据；不要求 manifest、SDK 或组件拆分协议。DSH 三工具可用时优先沿用；其他客户端或用户明确验收通用工具时使用通用台。只有复制了工具包且本机具备其运行环境时才调用，以工具 README 和 `--help` 为依据。

从仓库根目录使用 `node tools/design-studio/cli.mjs serve <HTML> --size <宽x高>` 展示原型；检查用 `inspect <HTML> --size <宽x高> --screenshot <新PNG路径> --report <新JSON路径>`。截图／报告路径须不存在且父目录已存在，命令不会覆盖源或已有证据。`serve` 是持续服务：以受管后台任务启动、核对输出地址，用完停止；不替换当前 DSH GUI 服务。

核对 JSON 的入口 hash、实测 viewport、页面尺寸及错误；打开 PNG 看渲染，不能只看问题数。该工具是保守的基础检查：不覆盖固定栏遮挡、文字相互重叠和完整交互等，报告的 `scope.notCovered` 必须保留。内容在隔离 iframe 中运行，外链、连接与表单受限制；工具策略导致的失败与原型自身错误分开说明。需要演示 query 或明确的实际操作测试时，用其公开模块接口并独立记录证据，CLI 本身不点击、不切换状态。

当前环境缺少某项能力时，保留已有可用能力，并明确缺口：可本地打开的 HTML 仍可交付；实际本地运行过可记已运行，未截图、未实测尺寸或未走交互分别记未验证。不统一降为“运行未验证”，也不把人工目测冒充自动测量。

## 组件工作台：拆分验收与纠偏工具

[组件工作台](../../../../tools/html-component-workbench/README.md)呈现原型、组件稿、关系与来源，辅助验收及必要的人工选区纠偏；拆分标准由[组件拆分与验收](component-decomposition.md)定义，目标是 AI 主拆、人检查，不是人人从零手拆。当前 AI 批量结果的生成与增量接入闭环尚待实现／验证，不把定位调整说成新增功能。

需要进入该工具时才适配其原型协议；普通 HTML 预览与体检无需因此改写，设计台也不代替组件关系验收。资源生成与内联仍用现有[占位资源脚本](layout-preview.md#占位资源脚本)。
