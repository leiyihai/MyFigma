# 组件拆分与验收：AI 主拆，人检查和纠偏

用于用户要求组件拆分、复用关系验收、检查工作台成果，或 Figma 任务接手已有工作台项目时。**不把每份普通 HTML 都改造成工作台项目**；纯预览仍走设计台，直接 Figma 任务可在 Figma 内建立维护源。

## 职责与依据

- **技能／本规范**决定拆分标准和完成条件；**组件工作台**负责呈现原型、组件稿、关系和来源，帮助检查及纠偏，不决定业务组件边界。
- **AI**先读原型及已有维护源，提出并准备组件边界、命名、组和显式引用；说明独立维护与复用的理由，校验结果，不要求用户从零逐个圈选。
- **人**检查整体效果和关键维护边界，可整批接受无需逐项重做；不对时指出目标和原因让 AI 重拆，或按需人工选区／归组／排除。人工修改和既有有效确认优先，AI 不静默覆盖。
- 原型是视觉与交互上下文，已验收拆分是维护意图依据；它们都不等于已经创建并验证了 Figma 主组件与实例。

## 拆分判断

1. **以维护意图划边界**：先认按钮、列表行、奖励卡、信息区等实际用途和独立换皮需求，不按每个 DOM 容器或截图矩形机械拆分。层级尽量少，容器应有明确职责。
2. **先找可复用源**：已有主组件／已验收组件稿能承接用途和结构时复用，只补实际缺项；外观相近不足以证明可合并，明确要独立换皮的对象保留独立源。
3. **内容差异不扩增源**：文字、数字、图标内容和显隐优先作为实例内容／属性差异；必要结构或美术状态才定义变体，不为每个数值和状态组合造组件。
4. **共享必须显式**：组表示同组件的主体／变体，不表示自动继承；嵌套引用表示真实共享结构。来源选区重叠、名字相似都不自动产生引用。
5. **美术便于替换**：可独立维护的背景、底板、图标与文字布局分开，不为每一层造槽位或套自动布局。HTML 的实现包装不要求在 Figma 中复制。
6. **受影响部分重拆**：保留未变化组件的身份、来源与人工纠偏；先展示共享更新影响，不靠重生成整份项目抹掉已确认关系。

## 验收与纠偏

- 对照原型检查组件边界有无漏项／错收，独立预览是否保留文字、图片、层叠与裁切；关系图和实际可读结构一致，独立维护入口与共享关系符合预期。
- AI 新提出的来源映射先作为 `candidate`，人工接受本批后才记为 `confirmed`；已排除关系和未解决复核继续保留。已有可信的同版本确认不重复询问。
- `confirmed` 是文件字段，不是人工确认来源证明，也不授权写 Figma。来源不明时先核对本批确认依据，不用 AI 自填状态冒充用户认可。
- 反馈至少定位到组件／来源和希望改变的边界，例如“这两个按钮独立换皮”“卡片只共享底板”。AI 只修受影响项，展示前后差异并复验；人工圈选是可选纠偏，不是每次的起点。
- 以当前版本的明确答复确认本批拆分；不要求新增长篇报告或逐个点击所有候选。实际写 Figma 仍须明确设计版本、目标与范围；这些信息已齐全时，可与拆分验收在同一问答中确认，不机械追加一轮相同确认。

**完成标准**：本批组件稿、来源与关系可查看，边界和共享理由清楚；人工反馈已处理，确认状态可说明；未支持／未验项明确。文件能打开不等于拆分正确，更不等于 Figma 同步已通过。

## 当前工具边界：目标流程不冒充已实现

[组件工作台 README](../../../../tools/html-component-workbench/README.md)说明当前功能，[接入契约](../../../../tools/html-component-workbench/CONTRACT.md)定义 v1 文件与原型协议。原型只有进入该工具时才需适配；使用方以实际支持范围为准。

- 已有选区提取、组件组／引用、来源映射、文件载入与保存及改版复核。合法的完整 v1 项目 HTML 可承载外部准备的组件结果，但载入是**整项目替换**，不是 JSON 批量 API 或增量合并。
- 当前无内置 AI 主拆入口；AI 预拆产物自动准备、反馈重拆的安全增量接入、确认来源审计和真实产物端到端验收仍待实现／验证。不能让用户手拆全部内容来掩盖这些缺口，也不能手改 JSON 后直接宣称已接通。
- 在缺少可靠接入时，AI 可先给出范围内的拆分建议，标明尚未载入验收；若用户选择人工试验，使用现有入口并说明边界。原型预览和其他已获准任务无需因此被迫走中间工作台。
