# 检查已有游戏 UI

1. 读[共同约定](../ui-design/references/common.md)。确定目标文件／Frame、检查范围、设计尺寸和需求依据；已有信息直接复用，不要求重走方案访谈。未给需求时可评估可见问题，但不能宣称需求完整性通过。
2. HTML：读[设计台能力适配](../ui-design/references/studio-tools.md)，查看源码和真实渲染，按目标尺寸检查溢出、遮挡、文字、图片及点击区；按需查[原型工艺](../ui-design/references/prototype-craft.md)。有安全操作能力时走核心路径和关键状态；真实账号、扣费、发奖等路径不擅自触发。
3. Figma：按[换皮维护与验收](../ui-design/references/figma-ui.md)只读检查目标结构、布局、维护源、实例关联及换皮入口。规范中的创建、测试副本、修改和清理均不在本任务授权内；需要写入才能验证的项标未验证。
4. 组件拆分结果：按[组件拆分与验收](../ui-design/references/component-decomposition.md)对照原型检查边界、独立维护入口、共享关系及来源。只读数据和实际可用预览；不提取、改组、确认映射或重拆，不能把字段状态／文件可读当作已获人工认可或 Figma 同步通过。
5. 按影响排序报告每个可证实的问题：位置、观察结果／数字、影响与建议。需求缺失、工具不可用、未实际操作分别说明；静态推断标明依据，不当作运行结果。

**交付与停止**：给出问题和证据，或说明检查范围内未发现问题；不修文件、不改稿、不生成测试副本。用户另行要求修复时，进入对应的原型或 Figma 任务，只确认受影响的重要变更。
