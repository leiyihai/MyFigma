# MyFigma 九宫格工具 v4 插件

由旧独立 9-Slice 插件迁移，保留单张／批量转换、四边及统一边距、保留或替换原图、可选重叠、预览缩放／平移及七种语言。旧插件目录不参与构建，也未写入。

## 独立构建与导入

需要 Node.js（本次验证 v24.15.0）和 npm：

```sh
npm ci
npm run build
npm run typecheck
npx playwright install chromium
npm test
```

Figma 桌面端通过开发插件菜单导入本目录的 **`manifest.json`**；其中 `main`／`ui` 指向构建后的 `dist/code-v4.js` 与 `dist/ui-v4.html`，因此先执行构建。无需本地助手、图集导入插件、旧插件、ui-studio 或运行时网络服务。构建只读取仓库的 `tools/figma-project-assets/packages/nine-slice/src/` 并 bundle 到产物。

没有复用旧发布插件的 ID。manifest 必须保留 `"id": "figma-project-assets-nine-slice"`；开发插件缺少 ID 时 Figma 会禁止读写 plugin data，表现为选中九宫格组件仍显示「生成九宫格组件」。复制本插件目录时也要保留同一个 ID，或按 Figma 分配的新 ID 同步修改记录读写。

Figma 开发插件可能按 `main`／`ui` 路径缓存旧 bundle；只改插件名或关闭窗口后重新打开，不一定执行新代码。更新后若界面/行为仍是旧版本，请重新导入本目录 `manifest.json`，必要时移除该开发插件或重启 Figma。入口文件名带有版本后缀；修改构建产物时必须同步 manifest，详细排查见 [真实客户端测试指南](../docs/real-figma-testing.md#开发插件可能缓存旧代码)。

## 使用

1. 在画布选择含图片填充的图层，运行插件。
2. 输入边距或拖动绿色引导线；滚轮缩放，中键或平移模式拖动预览，适配按钮复位。
3. 选中本工具生成的主组件会进入「更新九宫格组件」模式：读取现有边距，修改后原位更新，不创建第二个主组件，实例关联保留。旧版无元数据的组件会先检测切片结构并推导边距；结构无法识别时明确提示且不修改。选中实例时提示定位主组件，不会把实例或既有主组件转换成新组件；实例状态提供「定位主组件」，只在画布中选中共享主组件，不改实例或主组件。
4. 选中普通单图组件会进入「升级为九宫格组件」模式。支持两种结构：根节点只有单一图片填充、无子层；或根节点唯一一个直接图片子层完整铺满组件（位于 `0,0`、尺寸等于组件当前画布）。按原图像素尺寸预览和校验边距，在同一个主组件上完成**手动九宫格升级**：保留组件 ID、当前宽高与实例关联，移除旧图片内容并替换为 9 个切片。资源导入器写入的 `myfigma`／`atlas.origin` 来源标记只显示为「导入器来源」提示，不是升级前置条件；没有共享记录、导入器、助手或网络也能升级。图片子层未铺满、多个子层、额外可见内容、Auto Layout、子层圆角／描边／效果、实例或非组件会明确拒绝并说明原因；应用失败不留下半升级结构。
5. 批量模式将同一组参数应用到所有选中图片；状态标记不再遮挡操作。
6. 生成组件。保留原图默认关闭：全部目标生成成功后删除原图；开启后才保留。

保留原图、批量模式和消除缝隙默认关闭；旧版本保存的开启状态会在首次加载时迁移为关闭，之后尊重你的手动选择。编辑现有组件时保留原图/批量不适用，界面会禁用。

边距单位为图层尺寸，不一定等于源图片像素；普通单图组件的手动九宫格升级以原图像素为准，按主组件当前画布尺寸等比换算。左右之和必须小于宽度，上下之和必须小于高度；批量先校验所有目标。零边距不生成空切片。

适用范围沿用旧插件：普通、未旋转、单一图片填充、未自定义裁剪的图片图层。复杂裁剪、平铺、多填充、遮罩、特效与 Auto Layout 父级定位不保证视觉兼容。透明图建议关闭消除缝隙。

可编辑组件包括本工具生成的、由切片矩形组成且共用同一图片填充的组件，以及结构符合上述两种形态的普通单图组件；普通单图组件不要求来源标记。人工改造过内部结构、混合图片或多层复杂组件会跳过并说明原因，不强行修改。来源标记只作为「导入器来源」显示，不阻止手工组件升级；没有共享记录仍可独立升级，检测到共享记录时继续读写以兼容导入器。组件使用与图集导入插件共用的 Figma shared plugin data 记录（命名空间 `myfigma`、键 `nineSlice.v1`；旧版本私有 `myfigma.nineSlice.v1` 作为兼容回退，图集插件扫描时会迁移）：只有实际改动边距或消缝时才把 `override` 标为 true，同时保留导入插件记录的项目参数 `project`；原值提交不会把项目参数误标为人工覆盖。手动九宫格升级写入 `width`／`height`（当前画布）和 `imageSize`（原图像素），`current` 始终是原图像素空间的边距；导入插件按 `imageSize` 换算回画布校验并保留当前宽高，不会把主组件改回原图尺寸。

共享记录写入失败不会被当作完整成功：升级入口先写记录再改结构，写入失败时保持普通图片并提示重试；其他更新路径若切片已应用但记录写入失败，会明确提示来源、项目参数与人工覆盖状态未确认保存。导入器扫描仍会为旧组件补写来源标记，但该标记只用于显示来源，不再影响独立升级入口。

存在项目参数且当前为人工边距时，编辑状态会显示「人工边距优先」并提供「恢复项目参数」：清除 `override`、按 `project` 原位重建切片，主组件身份与实例关联保留；普通单图组件完成手动九宫格升级后同样保留当前宽高。没有记录项目参数时恢复按钮禁用并说明原因；项目参数无法应用到当前尺寸时拒绝恢复并保留原切片。导入插件遇到图片变小导致人工边距失效时会跳过该项并提示可恢复后重试。

## 验证

```sh
npm run test:browser -- --grep 'batch=true'
npm run test:browser -- --grep 'small selected'
npm run build && node --test tests/plugin.test.cjs
npm run typecheck
npm test
```

浏览器测试加载构建产物的真实页面，以平台消息输入图片，使用真实鼠标拖动／点击／输入验证交互。生成测试从 `figma.ui.onmessage` 驱动，只在 Figma API 边界使用替身，不测试私有函数。

红绿证据、根因和未验证项见 [VALIDATION.md](VALIDATION.md)。#24 的节点级记录来自真实 Figma 126.10.7 的根填充组件；#25 新增的无标记与图片子层两种结构目前只由构建后的插件消息入口和浏览器回归覆盖，真实 Figma 验收由后续父任务进行。节点级主线程、浏览器替身和新 UI 面板必须分别记录，不能互相扩大结论。
