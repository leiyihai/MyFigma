本批实现 GitHub [#1](https://github.com/leiyihai/MyFigma/issues/1)、[#2](https://github.com/leiyihai/MyFigma/issues/2)、[#3](https://github.com/leiyihai/MyFigma/issues/3)、[#4](https://github.com/leiyihai/MyFigma/issues/4)、[#5](https://github.com/leiyihai/MyFigma/issues/5)、[#6](https://github.com/leiyihai/MyFigma/issues/6)、[#8](https://github.com/leiyihai/MyFigma/issues/8)、[#10](https://github.com/leiyihai/MyFigma/issues/10) 与 [#11](https://github.com/leiyihai/MyFigma/issues/11)；已在用户授权的独立 Figma 测试文件完成小样客户端验收，仍不是完整资源管理版本。

## 组成与启动

- [Rust 本地助手](local-helper/README.md)：登记游戏并拆分简单图集。独立运行，不依赖 ui-studio。
- [资源导入器](atlas-import-plugin/README.md)：连接资源助手、维护项目登记、扫描并将散图导入空白页。
- [独立九宫格插件](nine-slice-plugin/README.md)：保留单张／批量转换，修复预览拖动；与导入插件分别构建。
- [共用九宫格核心](packages/nine-slice/README.md)：构建时复用，不运行时调用另一个插件。

在 `local-helper` 执行 `cargo run --release --locked`，或直接运行 `target\release\resource-helper.exe` 启动助手；它驻留通知区域（托盘），右键菜单可查看运行状态、打开数据目录或退出，退出后端口关闭。首次按该目录 README 从本机令牌文件完成配对，连接成功后自动记住。不把令牌贴到聊天或 Issue。

在两个插件目录分别执行 `npm ci` 和 `npm run build`。两个插件都导入各自根目录的 `manifest.json`；九宫格清单指向 `dist/` 下的构建产物。客户端要求有效开发插件身份时需自行注册。本次已在真实客户端验证两个开发插件加载及 localhost 配对连接。

最小演示将助手的 `examples` 目录登记为资源目录，可得到红、绿两个独立素材。扫描支持登记游戏根（含 `res/imageset`）或直接 `imageset` 目录的递归范围，并额外导入未被打包的独立图片；导入后的主组件先按散图原名开头的前缀 token 定类（`btn`/`button`、`icon`、`bg`/`background`、`panel`、`progress`/`pbar`、`font`/`wordart`），再回退到完整名称关键词与尺寸比例，归入按钮、底板、图标、背景、艺术字、进度条或未分类的自动换行分类 Frame；九宫格只决定拉伸结构，不参与用途。类别顺序、名称与颜色由资源页的页面级配置（`atlas.categories.v1`）决定，缺省为上述默认七类，并可按需「重新整理」分类区域；在画布选中主组件或实例后，面板用这些彩色类别标签展示，点击其他标签即批量分类（不再有下拉框和「应用」按钮），当前类别高亮，混合选择只显示混合状态，面板固定 350×600 且标签区最多四行、超出在标签区内滚动；分类动作行的「类别管理」可新增自定义类别（调色板稳定配色、立即生成分类 Frame）或删除未分类之外的类别（先把其中组件与用户自有节点移到未分类，再删配置与 Frame；主组件、来源与实例不丢）。登记游戏根时还会递归统计 `res/layout` 的图片引用与九宫格边距，导入插件据此生成唯一九宫格主组件。绑定一致的资源页可再次扫描并原位增量更新，源删除只标记、不删除组件。需要核对源图集时，可手动创建／更新只含主组件实例的对照页；默认导入不会创建该页。

## 验证

进行实际客户端自动化或排查平台专属问题时，先看 [真实 Figma 客户端测试指南](docs/real-figma-testing.md)：包含调试接入、文件隔离、消息排查、像素验收和恢复环境的步骤。

从各自目录运行：

| 目录 | 命令 | 验证边界 |
| --- | --- | --- |
| `packages/nine-slice` | `npm ci && npm run typecheck && npm test` | 公共切片规划 |
| `nine-slice-plugin` | `npm ci && npm run typecheck && npm test` | 插件入口与真实浏览器预览交互 |
| `local-helper` | `npm ci && cargo fmt --check && cargo check --locked && cargo clippy --all-targets --locked -- -D warnings && cargo test --locked && npm test` | 构建检查、真实产物启动/托盘退出/重启持久化与真实 Rust 子进程 HTTP／像素集成测试 |
| `atlas-import-plugin` | `npm ci && npm run test:all` | 助手至插件任务链路与浏览器管理界面 |

浏览器测试需要 Playwright Chromium（九宫格）和系统 Chrome（图集导入）。Rust 原生测试当前没有单元用例；真实 HTTP 集成测试由 Node 驱动，不能把 `cargo test` 的构建通过当作全部行为验证。

### 集成审查修复

- 失败项只恢复自身状态，不整体回滚；页面名称与绑定只在本轮无成功写入时恢复，保留用户同期修改及无关节点；先失败后通过的回归见 #5 条目。
- 扫描期间切页会记录待校验状态，结束后重新校验，并在校验前禁用导入；自动重验保留原任务的失败提示及失败显示，不吞掉断连后的启动指引。浏览器用受控网络等待和断连复现并回归。
- 小数边距辅助线与提交参数使用一致数值，四边实际位置经过浏览器验证；详见 [九宫格验证记录](nine-slice-plugin/VALIDATION.md)。

### 真实客户端验收

- 仅操作用户指定的独立测试文件；Playwright 操作真实插件 UI，Figwright 只用于测试素材准备、节点读回及导出验证。
- 复现页面校验约 60 秒后超时：主线程已经返回，UI 却误将非直接父窗口消息丢弃。修复后校验立即返回，示例扫描约 0.12 秒、导入约 0.37 秒；这些是两张小图的单次记录，不是性能承诺。
- 导入两张真实主组件，读回原始尺寸与自动布局；从 Figma 取回原始填充 PNG，验证 1×1 绿色和带透明留白的 2×2 红色图像像素完全正确。
- 原生资源面板搜索并插入实例，使用真实实例交换验证主组件关联；非空未绑定页和错误名称保护生效，保护测试矩形仍存在。
- 独立九宫格收到真实选图预览；单张、批量拖线可操作，非法批量边距不删源图，合法批量生成并按选项删除源图。
- 100×80 彩色九宫格及 180×80、100×140、180×140 实例导出后与预期逐像素一致。关闭消缝时，半透明原尺寸及双向拉伸实例保持统一 alpha 128，RGB 误差不超过 1，无空隙或透明度叠加。未穷举全部素材或开启消缝的半透明情形。
