# 九宫格图片精简与缩放后边距修复

## Problem Statement

现有九宫格功能只处理“已经存在的整张图片”：给图片标记边距，再生成九宫格组件。它没有生成精简九宫格图片的能力，源图片中可拉伸区域仍然保留全部像素，导致图片和组件体积偏大。

同时，已有九宫格组件被放大后再次编辑边距会出现错误：预览和绿色辅助线使用组件当前画布（例如 `858×769`），但输入和校验使用原图尺寸（例如 `256×256`）。拖动绿线得到的 `405/434` 等画布坐标被当成原图边距，触发“边距超出原图”的错误。

## Solution

在现有功能页面直接增加两个动作，不增加 Tab：

- **生成九宫格图片**：根据当前边距生成一张精简后的独立图片；原图保留，不创建组件，不替换原图。
- **生成九宫格组件**：内部先按同一规则生成精简图片，再调用现有九宫格组件生成流程；原图保留。

编辑已有九宫格组件时，预览、绿色辅助线和输入框统一使用**图片像素尺寸**，只有写入组件时才换算到当前画布尺寸。

## User Stories

1. 作为设计者，我希望不增加新的 Tab，直接在现有页面生成精简九宫格图片，以便沿用现有操作习惯。
2. 作为设计者，我希望“生成九宫格图片”不替换原图，以便处理错误后还能重新操作。
3. 作为设计者，我希望生成的图片保留原名并在原图旁边隔开显示，以便识别来源并保留两份素材。
4. 作为设计者，我希望“生成九宫格组件”复用精简图片逻辑，以便图片和组件使用同一套边距规则。
5. 作为设计者，我希望生成组件时也保留原图，以便不会因自动转换丢失源素材。
6. 作为设计者，我希望四角保持原尺寸，以便角部视觉不因精简改变。
7. 作为设计者，我希望纯色可拉伸区域压到 1px，以便尽量减少图片体积。
8. 作为设计者，我希望渐变或非均匀区域按原尺寸的 25% 保留，以便拉伸到大尺寸后仍能保持大体渐变。
9. 作为设计者，我希望按水平/垂直方向分别判断渐变，以便只压缩真正均匀的方向。
10. 作为设计者，我希望渐变区域不设最大保留尺寸，以便大图仍能保留足够渐变信息。
11. 作为设计者，我希望精简后图片的边距仍按原图边距值，以便后续编辑和组件行为一致。
12. 作为设计者，我希望生成组件的画布等于精简图片尺寸，以便组件不再携带原始大图。
13. 作为设计者，我希望放大九宫格组件后再次编辑边距时，输入框和绿线仍显示原图边距，以便不会出现数值超出原图宽高的错误。
14. 作为设计者，我希望修复后的编辑行为与未缩放组件一致，以便不需要重新生成组件。
15. 作为设计者，我希望精简图片保留透明度、颜色和基本渐变，以便不改变原始视觉意图。
16. 作为设计者，我希望无法识别或边距非法的输入被明确拒绝，以便不会生成错误图片或组件。
17. 作为设计者，我希望精简图片和组件的生成结果可通过 Figma 节点与像素读回验证，以便确认不是只更新了元数据。

## Implementation Decisions

- 不增加顶部 Tab。现有页面保留一个主操作区，新增按钮 A「生成九宫格图片」；现有生成动作改为按钮 B「生成九宫格组件」。选中已有 9 切片组件时仍显示「更新九宫格组件」，不显示 A/B。
- 按钮 A 只处理普通图片图层，不处理已有九宫格组件；输出是新的图片图层，不是组件，不替换原图。新图层放在原图旁边并保持原名；Figma 若因同名调整显示名，以 Figma 结果为准。
- 按钮 B 内部复用 A 的精简图片结果，再调用现有九宫格组件生成流程；原图始终保留，不因生成组件自动删除。
- 精简区域按九宫格边距划分：四角保持原尺寸；上/下边带、左/右边带、中心区域分别处理。可拉伸区域在拉伸轴上独立判断方向。
- 对每个可拉伸区域/方向做颜色均匀性判断：
  - 纯色或近似纯色：该方向压到 1px；
  - 存在明显颜色差异、渐变或非均匀纹理：该方向保留 `max(1, round(原尺寸 × 25%))`，不设最大上限。
- 上/下边带的宽度和中心区域宽度共用水平目标；左/右边带的高度和中心区域高度共用垂直目标。新图片宽高由四角、边距目标和中心目标共同决定。
- 精简图片使用双线性或面积重采样保留大体渐变；四角像素保持原样；透明通道随图片一起保留。
- 按钮 A 的新图片图层尺寸等于精简图片尺寸；原图位置/尺寸不变。按钮 B 的组件画布等于精简图片尺寸，`imageSize` 记录精简图片尺寸，`current` 记录原图边距值。
- 编辑已有九宫格组件时，预览尺寸、绿色辅助线和输入框使用 `imageSize`（源图或精简图尺寸），不使用组件当前画布。应用边距时再按组件当前画布换算。缩放后的组件只改变画布，不改变边距编辑坐标。
- 修复缩放后编辑 bug：原图 `256×256`、组件放大到 `858×769` 时，边距仍显示原图空间的 `60/80/40/50`；绿色辅助线范围仍为 `256×256`；不能出现 `405/434` 这类画布坐标被当作原图边距。
- 精简失败、边距非法、图片无法读取或重采样失败时，不创建图片/组件，不替换原图；错误提示说明失败原因。
- 不改变现有九宫格组件编辑、恢复项目参数、共享记录和来源标记语义。按钮 B 的组件记录使用精简图片尺寸；来源标记只作可选提示。

## Testing Decisions

- 通过插件消息入口和构建后 UI 验证按钮状态、预览尺寸、绿色辅助线、输出节点类型、原图保留和错误提示。
- 覆盖根因回归：原图 256×256、九宫格组件放大到 858×769 后再次选中，输入框和辅助线仍按 256 坐标工作，不再出现 405 等值。
- 覆盖纯色区域压到 1px、水平渐变保留 25%、垂直纯色保持 1px、水平和垂直都有渐变时双轴保留 25%；不设最大上限。
- 覆盖四角像素保持、边距目标、精简图片尺寸和组件 `imageSize`/`current` 记录；检查透明通道。
- 覆盖按钮 A：生成新图片图层、原图层保留且位置/尺寸不变、名称保持原名、位置隔开。
- 覆盖按钮 B：原图保留、生成精简九宫格组件、组件画布等于精简图片、实例/九宫格约束正确。
- 覆盖拒绝场景：非法边距、不可读取图片、非图片图层、已有九宫格组件不进入 A/B 生成路径。
- 真实 Figma 验证至少在放大后的组件上编辑边距、生成 A 图片和 B 组件，并读回节点尺寸、位置、图片尺寸和边距记录；像素抽样验证四角与渐变没有明显破坏。
- 浏览器测试覆盖新增按钮和禁用状态；涉及面板布局/视觉时遵循仓库 UI 技能入口，并调用 `frontend-design`。

## Out of Scope

- 新增顶部 Tab。
- 自动删除原图、自动替换已有组件图片。
- 对已有九宫格组件执行按钮 A。
- 把非图片内容转换为九宫格图片。
- 改变九宫格组件编辑、恢复项目参数或来源标记语义。
- 引入云端处理、外部服务或新的图像处理依赖。
