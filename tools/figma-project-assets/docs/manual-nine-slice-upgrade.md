# 普通图片主组件手动升级九宫格

## Problem Statement

资源导入器为没有项目九宫格用法的图片创建普通图片主组件。设计者后来想在 Figma 中使用九宫格拉伸时，独立九宫格插件不能将这类主组件转换：现有转换入口排除主组件，编辑入口只识别已有切片结构。

项目未使用九宫格不代表素材不适合九宫格。为解决这一入口缺失，不应放弃组件导入、实例关联与既有增量工作流。

## Solution

保留现有组件导入。独立九宫格插件允许设计者选择资源导入器生成、安全可识别的普通图片主组件，预览原图并设置四边边距，在同一个主组件上完成九宫格升级。已有九宫格编辑及普通图片转换继续保留。

选中实例时，先定位主组件，不直接修改实例或其主组件。升级保留组件身份、来源、分类、当前宽高和实例关联；后续增量保留人工边距。

## User Stories

1. 作为设计者，我希望未被项目布局用作九宫格的素材也能手动升级，以便按设计需要拉伸。
2. 作为设计者，我希望保留组件导入，以便继续使用实例复用、分类与增量更新。
3. 作为设计者，我希望选中普通图片主组件即可设置九宫格边距，不必解除组件或删除重导。
4. 作为设计者，我希望边距以原图像素尺寸为依据，以便不受画布缩放和组件当前尺寸影响。
5. 作为设计者，我希望升级保留主组件身份，以便已有实例不需要替换。
6. 作为设计者，我希望保留来源和分类，以便后续同步与人工标签仍然有效。
7. 作为设计者，我希望升级保留主组件当前宽高，以便不破坏已经调整的布局。
8. 作为设计者，我希望关联实例保留设计宽高，以便升级不会意外改变设计稿布局。
9. 作为设计者，我希望选中实例后先定位主组件，以便明确这次修改会影响共享素材。
10. 作为设计者，我希望人工改造或复杂组件被安全拒绝，以便不丢失子层和内容。
11. 作为设计者，我希望后续重新导入保留人工边距，以便不反复设置。
12. 作为设计者，我希望新图片尺寸容不下边距时跳过并提示，以便不会静默篡改人工设置。
13. 作为设计者，我希望没有项目参数时禁用恢复入口并说明原因，以便不会恢复到虚构参数。
14. 作为设计者，我希望真实 Figma 验证实例关联、宽高及拉伸效果，以便实际设计可以放心使用。

## Implementation Decisions

- 本规格是整合规格 #22 的增量补充：新增普通图片主组件的手动升级入口，不改变唯一主组件库、来源身份、用途分类和按需对照页设计。
- 普通图片主组件指资源导入器生成、尚未切片、未被人工改造成复杂内容的图片主组件；首期只开放可安全验证的此类对象，不强制处理任意组件。
- 区分三条操作：普通图片转换为新组件、已有九宫格主组件原位编辑、普通图片主组件手动九宫格升级。本次只补第三条，不把已有主组件送入新建替换路径。
- 复用现有九宫格预览和共用原位应用能力。升级沿用原组件身份，不删除重建主组件，保留来源、同步和分类信息。
- 预览与边距合法性校验以原图像素尺寸为依据；原图尺寸与组件当前画布尺寸必须区分。应用后保留主组件当前宽高。
- 选中实例不直接升级；提供定位主组件的明确入口，由设计者在主组件处显式执行操作。
- 修改边距形成有效九宫格后记录人工覆盖，并保存两个插件可互通的九宫格状态；结构和记录必须能通过导入器现有增量检查。
- 后续图片更新保持人工边距；项目新增或改变参数不覆盖人工值。图片缩小导致边距非法时跳过并提示，不钳制边距、不覆盖旧组件。
- 从未记录项目参数时不得伪造参数；“恢复项目参数”禁用并说明原因。存在合法项目参数时沿用已有恢复语义。
- 应用前校验对象和边距，拒绝不安全结构；失败不得留下半升级状态或破坏原组件。此处为待实施约束，不是对现有核心事务能力的结论。
- 保留已有实例关联和设计宽高是验收要求，不把静态代码推断或测试替身当作 Figma 平台保证。

## Testing Decisions

- 优先沿用插件消息入口和导入器公开增量流程；断言组件身份、来源、分类、尺寸、九宫格结构与记录、实例关联和错误结果，不绑定私有实现。
- 覆盖普通导入主组件识别、原图预览、边距合法性、手动九宫格升级、不同于原图的当前宽高保留、复杂组件拒绝和失败不破坏原内容。
- 覆盖实例只定位不直接修改、无项目参数时恢复禁用、已有普通图片转换与九宫格编辑不回归。
- 跨插件流程覆盖升级后无变化导入、像素与尺寸更新、人工边距保留、非法缩小跳过，以及有/无项目参数的差异；不能只用共享私有数据的替身证明跨插件互通。
- 浏览器验证现有预览和按钮状态；涉及面板修改时遵循仓库 UI 技能入口。
- 真实 Figma 使用已有关联实例的普通图片主组件，调整为非原图宽高后升级，检查 ID、实例关联、主组件和实例设计宽高、角固定、边单向与中心双向拉伸；再执行重新导入验证人工边距保留。
- 本轮仅静态核对了现有入口与核心能力，未运行功能测试、未复现客户端现象、未完成真实 Figma 验收。实施交付必须分别记录自动化与真实验收证据及未覆盖项。

## Out of Scope

- 全部资源改成普通图片、取消组件导入或取消九宫格支持。
- 重建、解除或替换既有主组件与实例。
- 强制转换任意复杂组件、自动升级全部资源、直接在实例上修改共享主组件。
- 新增“退回普通图片”功能、改变项目参数选择规则或自动修改项目文件。
- 模型分类及其他类别管理功能。

## Further Notes

- 已确认：保留组件、从实例先定位主组件、安全对象限定、保留人工边距、缺参数禁用恢复、保留当前宽高。
- 用户本轮仅授权整理并发布规格与任务，尚未授权开发。
- 静态核对发现已有手动升级核心与导入器升级路径；独立插件入口未开放，不等于底层无法保留组件身份。具体工作量和平台效果仍以实施验证为准。
