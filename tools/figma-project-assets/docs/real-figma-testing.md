# 真实 Figma 客户端测试指南

用于验证插件在实际 Figma 中的加载、UI—主线程通信、图像导入和组件行为。自动化单测、普通浏览器及平台替身不能替代本流程。本次具体结果保留在 [工具 README](../README.md) 和 [九宫格验证记录](../nine-slice-plugin/VALIDATION.md)，此处只维护可复用方法。

## 1. 固定范围与基线

开始前取得以下授权：专用测试文件链接、允许创建的页面／节点、重启客户端及开启本机调试端口的许可。确认用户没有待保存工作；有工作时先等待保存，不能为接通自动化直接结束进程。

- 记录代码提交、构建命令、客户端版本、助手版本及测试样本；按各模块 README 构建，并在 Figma 重新运行插件，确认实际加载新产物。
- 用唯一前缀登记测试项目、命名页面和节点，记录创建的 ID。重复测试先读回结果，避免每次失败都重新创建一套。
- 只对授权文件操作；文件名不是唯一身份，Playwright 以链接中的文件 key 匹配。多标签打开同一文件时先消除歧义。
- 测试助手修改登记表时只新增／修改本次测试登记，不覆盖使用者的项目配置。不编辑真实游戏资源，以小样或副本注入变化。
- 配对令牌只从本机文件读入测试进程内存，不打印、不提交、不放入 URL。若产品提供记住配对，验收后检查「忘记配对」确实清除了客户端保存；不要把保存后的令牌复制进测试产物。测试进程临时填入令牌不等于产品已实现自动配对。

**完成条件：**测试对象、可修改范围、构建版本和回退边界明确；尚未取得范围授权时只做本机只读检查。

## 2. 接入真实客户端

### 调试入口

先检查已有客户端和本机调试端口，避免重复启动或连接其他程序。使用 Playwright 的 CDP 接口连接客户端，不是另开一个普通 Chrome 网页假装 Figma 桌面端。

本次客户端为 Electron 版 Figma 126.10.7。普通启动即使带 `--remote-debugging-port`，应用也会主动移除该开关；只读检查安装包后确认，该版本在 `FIGMA_TEST` 存在时保留开关。

这是**特定客户端的实现事实，不是稳定公开 API**。其他版本先核查，不能把同一个环境变量当作通用开关，更不能修改安装包绕过限制。该测试模式还可能跳过保存确认、关闭更新、改变初始化及托盘行为，因此仅在获准的测试会话使用，结束后恢复普通启动。

已确认需要该方式时，可在 PowerShell 中临时启动；执行前填入已核实路径并正常退出原客户端：

```powershell
$figmaExe = '<已核实的 Figma.exe 绝对路径>'
$previousTestMode = $env:FIGMA_TEST
try {
    $env:FIGMA_TEST = '1'
    Start-Process -FilePath $figmaExe -ArgumentList @(
        '--remote-debugging-address=127.0.0.1',
        '--remote-debugging-port=9222'
    )
} finally {
    if ($null -eq $previousTestMode) {
        Remove-Item Env:FIGMA_TEST -ErrorAction SilentlyContinue
    } else {
        $env:FIGMA_TEST = $previousTestMode
    }
}
```

仅监听回环地址，不加任意来源放行，不设置系统级环境变量。调试端口具有高权限，即便仅本机也应尽量缩短开放时间。

确认 `/json/version` 可访问，并检查监听地址及进程归属；只记录版本，不传播完整调试目标、会话信息或个人数据。环境／客户端不支持时如实报告阻塞，不擅自更换编辑器或安装新工具。

### 选择正确页面

以下是连接片段，不会启动、关闭客户端或创建画布内容；结束时只断开 Playwright 会话，不调用 `browser.close()`：

```python
from playwright.sync_api import sync_playwright

file_key = '<用户授权链接中的文件 key>'
with sync_playwright() as p:
    browser = p.chromium.connect_over_cdp('http://127.0.0.1:9222')
    matches = [page for context in browser.contexts for page in context.pages
               if f'/design/{file_key}/' in page.url]
    if len(matches) != 1:
        raise RuntimeError('测试文件未打开或存在多个相同目标，请先确认')
    page = matches[0]
    page.bring_to_front()
    # 后续只操作这个 page；每次重新连接、导航后重新核对目标。
```

插件 UI 在嵌套 iframe 中，不一定是第一层。通过独特控件发现实际 UI frame，例如导入插件的 `#connection`、九宫格的 `#preview-img`；不要写死 frame 下标或输出整条 data URL。

**完成条件：**已连接真实客户端，目标文件唯一，能定位实际插件 UI；仅端口可访问或截图正常还不代表插件可工作。

## 3. 优先建立最小真实闭环

按公开操作推进，每一步检查可见结果，不先做整项目大批量导入：

1. 运行开发插件，确认 manifest 被接受、主线程启动且 UI 出现。
2. 配对助手，登记专用小样项目，选择项目并取得页面校验结果。
3. 扫描、核对摘要、导入；观察进度和错误，读回真实节点。
4. 验证资源搜索插入、实例交换及主组件关联。
5. 在本次测试页面中增加无关矩形、改名或切页，验证保护行为，并读回保护节点仍存在。改名试验结束后恢复本次修改的名称。
6. 九宫格分别验证选图、预览拖线、非法参数、批量、生成及实例拉伸。
7. 新功能实现后再增加对应真实场景，例如增量身份保持、取消和重试。未实现的功能不纳入“通过”清单。

真实 UI 使用 Playwright。Figwright 只承担测试素材准备、节点读回、实例创建／尺寸调整及图像导出，不能用桥接直接创建结果来冒充被测插件成功导入。每次打开 Figwright 前后都核对文件，通过 `list_files`／`use_file` 绑定唯一会话；插件重开后重新确认绑定。

### 稳定操作的经验

- 以控件值、可见性、启用状态、阶段和进度等待结果；固定睡眠只用于已知动画或受控故障时序，不代替成功断言。
- 快捷操作菜单通常可用 `Ctrl+/`。优先使用明确的近期开发插件入口；输入搜索词会触发异步搜索，不能把搜索文字自身误当结果点击。
- `Shift+I` 本次可打开资源插入搜索。搜索框的示例 placeholder 会轮换；用实际可见的搜索框或稳定语义定位，不依赖某一句占位文案。
- 页面名、图层名和插件名可能重复。定位范围应限于当前面板／弹窗，严格模式报多个匹配时收窄范围，而不是无条件取第一个或最后一个。
- 选择图片后等待图片解码、适配动画结束，再按当前 bounding box 换算拖动坐标。保存静态坐标会误把动画竞争当产品故障。
- Windows 正在运行的助手 exe 可能无法覆盖。助手现在驻留托盘，替换前先从托盘菜单「退出」，确认端口已关闭；不要强行结束用户进程。经允许关闭后重建，或构建另一份有明确名称的测试产物，记录实际运行的是哪份。

### 开发插件可能缓存旧代码

**现象：**修改 manifest 名称、关闭并重新打开插件、重新 Import manifest 后，界面或行为仍是旧版本；新加的诊断消息完全收不到。只改插件显示名不足以证明加载了新代码。

**原因：**Figma 开发插件会按已注册的 `main`／`ui` 文件路径缓存构建产物；重新导入同一路径或只改 `name` 时，可能继续执行旧 bundle，UI 与主线程甚至可能来自不同版本。

**排查：**先确认新代码真的在运行，再查业务逻辑。加一条唯一构建标记或临时诊断消息；如果 UI 收不到，先处理缓存，不要继续读业务代码。

**规避：**

- 构建时生成新的入口文件名，并同步修改 manifest，例如 `dist/code-v3.js`／`dist/ui-v3.html`；本目录九宫格插件已按此方式缓存失效。
- 或在 Figma 中移除该开发插件后重新导入 manifest，必要时重启 Figma；仅关闭插件窗口通常不够。
- 只打开名称和版本都匹配的新入口；旧开发插件条目可以保留但不要误开。
- 记录实际打开的插件名、manifest 路径和构建产物文件，避免把“旧插件行为”当成新代码 bug。

## 4. 分层定位错误，不先放大超时

| 现象 | 先检查 | 本次经验 |
| --- | --- | --- |
| manifest 拒绝开发域名 | 官方 manifest 规则、默认地址、客户端白名单和助手 Host 校验是否一致 | 数字 IP 写法被客户端拒绝；改为文档支持的 `http://localhost:端口`，同时保留仅回环访问与令牌认证 |
| 打开插件就报 import expression | 实际主线程 bundle，而非只查源码或类型检查 | 合法的 `async import(...)` 方法名触发安全求值器检查；改成 `importResources`，并用 SES 加载实际 bundle 做回归 |
| 打开插件即报 `currentPage` 未定义或 `Unable to load code` | 已注册 manifest 的 `main`／`ui` 是否指向真实构建产物，构建后是否产生多个同名入口 | 根清单曾指向不存在的根目录 `code.js`，真实产物在 `dist/`；统一唯一清单并加目标存在性回归 |
| 助手连接后，页面校验约60秒超时 | 请求是否发出、主线程是否回复、消息来源窗口／origin、requestId 是否匹配 | 回复已经到达 UI，但来自 Figma 顶层而非直接父窗口，被来源过滤丢弃 |
| Figma 控制台大量红字 | 清空后单次复现，展开与本插件有关的错误和栈 | 头像 CORS、遥测超时、网络能力警告不能单独证明插件根因 |
| 浏览器测试页面本身加载不了 | frame 层级、混合内容、本地网络权限 | 将 HTTPS 测试宿主嵌入 HTTP 本地页面可能先被浏览器阻止，尚未走到待测消息路径 |

### 只记录消息元数据

诊断收发时记录 `type`、`requestId`、origin、是否直接父窗口／顶层以及是否含结果／错误，不记录完整请求、响应和令牌。对照发送与接收证据后再改超时或协议。

本次真实客户端的可信回复满足：

```javascript
event.source === window.top && event.origin === 'https://www.figma.com'
```

现有插件同时保留直接父窗口通道。来源条件必须按实际拓扑核实，不能简单删除检查、接受所有 origin，或只凭消息字段长得像结果就接收。

嵌套消息回归应实际创建宿主 → 中间 frame → 插件 UI，由顶层发送回复，并验证陌生顶层域名不能伪造结果。只有直接父窗口的测试会漏掉这次问题。测试所需 HTTPS 宿主和子页可以用 Playwright 路由提供，避免外网依赖；拓扑测试可替换外部 HTTP 边界，真实助手链路另测，证据分开记录。

SES 是发现 import 表达式拦截的回归工具，不是 Figma 的完整运行时；通过 SES 仍需真实客户端加载。

**完成条件：**存在可重复的失败路径和根因证据；修复后同一场景通过，且错误路径／不可信来源仍被拒绝。

## 5. 用像素和关联证明结果

### 散图

使用已知小图：一张纯色图与一张具有透明留白、非零偏移的图。来源和预期独立于拆图算法定义，验证：

- 节点确为主组件，名称、尺寸、数量和自动布局正确。
- 从 Figma 提取原始 IMAGE 填充字节，比较完整 RGBA 像素，而不仅比较助手输出或画布截图。
- 原生资源面板能搜索并插入，实例交换后读回 `mainComponent`，不只看外观相似。
- 来源记录按公开可用的读取边界另验；其他插件通常不能直接读取本插件的私有 pluginData，不能将桥接节点快照当作已验证全部私有元数据。

### 九宫格

用九个区域不同颜色、四边不对称的图片，以便发现切错片和左右顺序错误；本次样本为100×80、左20／上10／右8／下12。至少验原尺寸、仅加宽、仅加高、双向拉伸四种情况。

- 读回九片坐标、尺寸、约束及实例关联，确认四角固定、边单向拉伸、中心双向拉伸。
- 从 Figma 导出实际渲染 PNG，明确 `scale: 1`。自动适配的预览截图会缩放，不能用于逐像素断言。
- 预期图独立按固定边区间绘制，不调用被测切片函数重算预期。不透明图可逐像素核对；透明图检查整个图的 alpha，避免只采中心点漏掉接缝。
- 再用半透明样本检查透明度叠加。本次 alpha128、关闭消缝时通过；这不证明开启重叠消缝也适合所有半透明图。
- 先核对文档颜色空间、尺寸和缩放。容差须解释来源，本次半透明 RGB 最大1的舍入差不应扩展为任意图片的宽松阈值。

## 6. 固化、收尾与报告

把真实客户端发现的故障变成最靠近公开行为的自动回归，先看到失败，再修复；类型检查和单文件测试持续运行，最后跑完整回归。针对消息拓扑的现有回归见两个插件各自的 `tests/browser/message-source.spec.*`，主线程加载回归见导入插件的 `tests/plugin-main.test.mjs`。

证据只保留必要的版本、操作、耗时、节点 ID、断言和脱敏截图。产物放系统临时目录，或通过 `git rev-parse --git-path native-acceptance` 得到的非版本化位置；不要把私人文件链接、原始 DevTools 日志、凭据、浏览器 profile、trace 或整个测试文件打包提交。需要保留 trace 时先确定脱敏办法，不能默认录下令牌输入。

结束时逐项核对：

- 测试节点可读回；只清理本次创建且确认不需保留的内容，保留供用户复查的样例时明确页面位置。
- 原名称等临时修改恢复；未覆盖用户同期操作，未删除已有登记或设计。
- 观察保存／同步状态；无法确认时注明，不把截图当作可恢复设计文件或已同步证明。
- 停止调试客户端，恢复不带调试参数、无临时测试变量的普通启动，并验证调试端口已关闭。只退出 Playwright 连接不会关闭客户端调试入口。
- 报告分别列出自动回归、真实客户端通过、失败及未验证；小样耗时不等于整项目性能，小样兼容不等于全量兼容。未覆盖的真实场景与尚未实施的反馈继续单独记录。

**完成条件：**失败用例已转绿、相关回归通过、授权边界可核对、客户端恢复、调试入口关闭，并明确未验证范围。
