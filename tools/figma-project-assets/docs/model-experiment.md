# 起床2 分类模型小样本实验

本次只验证“本地小模型是否能优于现有确定性分类”，不修改正式扫描/导入逻辑。

## 样本与标签

- 来源：g1108 源资源，不完整导入
- 临时项目：`g1108_model_sample`
- 临时 Figma 页：`g1108 模型样本（g1108_model_sample）- 分类资源`
- 人工标签页：`人工标注页`
- 样本数：175；人工纠正后的用途标签为权威标签
- 标签分布：
  - 底板 34
  - 进度条 30
  - 图标 29
  - 按钮 24
  - 背景 22
  - 艺术字 19
  - 未分类 17

分类目标为七类用途；九宫格只作为拉伸属性，不作为分类标签。

## 基线

用当前名称关键词 + 尺寸比例规则在这 175 个样本上的准确率：

- 全样本：129 / 175 = **73.7%**
- 20 次分层 70/30 留出切分：平均 **74.3%**（范围 67.9%–79.2%）

> 口径变更（#21）：上面两个数字是旧关键词规则在 g1108 小样本上的历史基线。g1048 的 920 条人工标签显示同一套通用规则只命中 18/920 = 2.0%，原因是它与项目的名称族组织方式不一致。#21 上线了从人工标签学习页面级命名规律的机制后，#20 的规则基线改用该机制在人工标签上的留出准确率：随机分层 20×70/30 约 64%，按图集分组 5 折约 59%（本实现实测 64.2% / 59.9%，同口径通用规则 2.0%）。比较模型时必须使用同一批人工标签、同一切分和同一新基线。

## 小模型尝试

### 通用视觉骨干横评

同一 175 个标签、同一 20 次分层 70/30 留出切分，使用预训练特征 + kNN：

| 模型 | 最高平均准确率 |
| --- | ---: |
| MobileNetV2-7 ONNX logits | 约 60% |
| MobileNetV3-Small | 52.9% |
| ConvNeXt-Tiny | 48.7% |
| EfficientNetV2-S | 50.9% |
| Swin-T | 50.4% |
| ViT-B/16 | 49.1% |
| DINOv2 ViT-S/14 | 52.5% |

DINOv2 是这轮里最强的通用特征，但仍显著低于规则基线 74.3%。这说明问题不只是“骨干网络太小”，而是通用视觉特征与游戏 UI 的用途边界不匹配。

### 1. MobileNetV2-7 ONNX + logits + kNN

- 输入：透明背景合成到黑/白底，缩放到 224×224；居中留白或拉伸
- 特征：ONNX 输出 1000 维 logits，L2 归一化
- 分类：kNN，cosine 相似度，k=3/5/7
- 10 次分层切分最佳平均准确率：**约 59.1%–60.0%**
- 单次留出集：**60.4%**

### 2. MobileNetV3-Small ImageNet 特征 + kNN

- 使用 torchvision 预训练 MobileNetV3-Small，移除分类头，取 576 维特征
- 透明图合成到黑底
- 20 次分层切分：
  - k=1：**52.9%**
  - k=3：**49.6%**
  - k=5：**47.8%**
  - k=7：**46.4%**

## 结论

本轮所有通用模型都没有超过当前规则基线（74.3%），因此**暂不接入正式导入流程**，也不新增模型文件/推理依赖到助手或插件。

可能原因：

- ImageNet 语义与游戏 UI 用途不一致；
- 175 个样本很小，且“未分类/底板/按钮”的视觉边界依赖布局与文字语义；
- 只用图片、去掉名称和布局信息，丢失了现有规则最强的信号；
- 九宫格拉伸属性被刻意从标签中剥离，模型无法借它判断按钮/进度条。

## 后续可选方向

1. 继续扩充标签，尤其底板、按钮、进度条、未分类的边界样本；
2. 在强骨干上训练轻量分类头，而不是直接用通用模型 logits 做 kNN；
3. 将图片特征与名称、尺寸、布局引用组合，做混合分类器；
4. 如果仍不超过规则基线，保留规则分类，不做模型接入。
