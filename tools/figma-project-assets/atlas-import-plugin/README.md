# 项目图集导入插件（#3、#4、#6）

独立 Figma Design 开发插件，真实连接 Rust 本地助手。没有 ui-studio 运行时依赖，不修改共享核心或独立九宫格插件。

## 构建与使用

要求 Node 24、npm、Rust stable（完整测试会启动真实助手）。先按 [助手 README](../local-helper/README.md) 构建并启动助手。

```powershell
npm ci
npm run typecheck
npm run build
```

构建产物：`dist/code.js`（Figma 主线程）、`dist/ui.html`（内联 UI 脚本）；无需开发服务器。Figma 的开发插件入口选择此目录 `manifest.json`。manifest 只在开发模式放行 `http://localhost:38473`；不承诺发布模式/远端助手，不要把域名改成 `*`。不同端口的测试只在浏览器沙箱运行，并未改变 manifest。

1. 首次使用时手动启动助手（托盘图标悬停时应显示「资源助手运行中」），从本机 `%LOCALAPPDATA%\MyFigmaAssets\token` 读取令牌，粘贴到「配对令牌」并连接；保持「记住本机配对」勾选。之后重新打开插件会自动连接，无需再次粘贴。若连接失败，先确认托盘里的助手仍在运行（否则从构建产物重新启动），再检查端口及 Figma/浏览器本地网络权限。

「忘记配对」会删除本机保存的令牌并取消记住；忘记后可在助手托盘菜单选择「显示配对令牌」，或运行 `figma-assets-helper.exe --show-token`，再重新粘贴。首次配对仍需手动复制令牌，自动连接只省去重复粘贴。
2. 「管理项目」填写游戏名称、项目编号、资源目录（游戏根或直接 `res/imageset` 目录）和长期维护标记，保存。可以先登记助手的 `examples` 目录，编号如 `demo2`，名称如「示例游戏」。目录只保存在助手侧，UI 的编辑表单可读取它。
3. 默认下拉只显示长期维护游戏；搜索名称/编号会查全部登记。管理弹窗可以编辑名称、路径、维护标记，或删除登记；编号是身份，编辑时锁定，改变编号应另行登记。
4. 在**专门用于验收的 Figma 文件/空白页**选择游戏、校验、扫描，检查图集/散图/独立图片数量和异常，以及「布局引用／九宫格／公共引用忽略」汇总。扫描递归读取登记范围内的对象式 JSON + PNG，并导入未被打包的独立图片；摘要出现「扫描不完整」时说明有错误或触达规模上限，此时只能导入已成功拆解的部分，且不会把缺失资源标记为源删除。
5. 扫描摘要同时显示新增、更新、源缺失、未变和跳过数量。点击「导入主组件」：空白页命名为「游戏名称（项目编号）- 分类资源」，保存版本化绑定；在「未分类」自动换行 Frame 内创建主组件。有九宫格用法的散图用共用核心生成唯一九宫格主组件（切片裁剪、角固定/边单向拉伸/中心双向拉伸，内部不使用 Auto Layout），其余仍为普通图片组件。绑定一致的资源页可再次导入，组件按来源身份原位更新；普通组件新增九宫格用法时原位升级，用法消失时不自动降级。按钮悬浮提供用途和适用条件。

非空未绑定页、绑定其他项目、绑定版本不符、名称与绑定不符均拒绝。每次扫描/导入都重新校验当前页，不清空用户已有内容。源删除只把已有组件标记为 `source-missing`，不删除组件或实例；散图改名、跨图集移动按旧身份移除加新身份新增，不按显示名或内容猜测匹配。

## 本地开发地址兼容

实际手动验收发现 Figma 拒绝 manifest 的数字 IP 开发域名。按 [Figma 官方 manifest 文档](https://developers.figma.com/docs/plugins/manifest/) 中的本地服务器写法，改用 `http://localhost:38473`，同步调整 UI 默认值、客户端白名单和助手精确 Host 校验。

manifest 与构建 UI 地址一致性、localhost 实际配对连接、Host 冒用拦截及浏览器登记导入均已自动验证；这些测试不是 Figma 原生 manifest 校验器。修改后仍需在 Figma 重新加载 manifest、关闭旧助手并启动新构建，再用默认 localhost 地址配对。

## 主线程沙箱兼容

手动加载曾报 `SyntaxError: possible import expression rejected`。构建产物虽然已 bundle，但平台接口名 `async import(...)` 触发了安全沙箱的导入表达式检查；已改为 `importResources(...)`，消息类型仍为 `import`，用户操作不变。

新增 SES 安全求值器开发依赖，直接加载实际 `dist/code.js`，先捕获 `SES_IMPORT_REJECTED`，修复后验证打开 UI、页面校验、真实助手扫描结果导入及进度消息。SES 是回归用安全求值器，不宣称它等同于 Figma 原生运行时，也不替代平台渲染验收。随后已在授权的独立 Figma 文件确认真实加载和示例导入。

## 嵌套窗口消息兼容

真实客户端复现页面校验约 60 秒后提示响应超时。仅记录消息类型、requestId 和窗口关系，确认 Figma 早已返回结果：来源为顶层窗口，origin 为 `https://www.figma.com`，但不是 UI 的直接父窗口。旧来源检查误将回复丢弃，并非助手扫描慢。

现同时接受直接父窗口及来源严格为 Figma 顶层窗口的消息；陌生顶层域名仍拒绝。浏览器回归使用与实际一致的嵌套结构，分别验证可信 Figma 顶层可完成校验、陌生顶层不能伪造回复。该拓扑测试仅模拟外部助手 HTTP 边界；其他集成测试仍启动真实 Rust 助手。

## 边界和安全

- HTTP/配对/登记/源格式及身份决策详见助手 README。默认请求仅由 UI 发往 `http://localhost:38473`（助手只监听 IPv4 loopback；CLI 测试也支持精确数字回环地址），拒绝 HTTP 重定向。
- 勾选记住配对后，令牌只在 UI 与插件主线程之间传递，由主线程保存到本机 `figma.clientStorage`；不写入 Figma 文档、不上传远端、不进入日志。它是本机插件级保存，不是账号同步；点击忘记配对会删除。
- 自动连接会把保存的令牌发往保存的本机 `localhost` 端口；若该端口被未知程序占用，先不要打开插件，检查助手进程，必要时忘记配对并轮换令牌。
- UI 任务入口 `Workflow` 统一控制登记、搜索、选择、校验、扫描、导入和互斥状态。任务期间禁用项目切换、管理修改、重复扫描/导入和连接。选择变化或登记修改会使旧扫描失效；清空选择也清空旧目标。
- 连接检查按操作触发，不轮询。网络错误/401 显示未连接，并提示确认托盘中的助手是否仍在运行、必要时从构建产物重启后重新连接；不把失败当作扫描为空。重启助手后点击「连接助手」即可恢复扫描和导入，登记与令牌跨重启保留。请求 30 秒超时；Figma 桥接 60 秒超时。
- 主线程 `createFigmaPlatform` 只接受版本 3 的完整扫描（最多 20 000 项），校验身份、尺寸、嵌套相对路径、重复来源、可选的九宫格参数和警告，并白名单保存来源字段。不会把本机绝对路径、布局节点引用或未知字段写进文档。组件名为「未分类/原名 · 相对路径」，避免跨图集同名混淆；独立图片同样使用该命名。
- 九宫格主组件与独立九宫格插件共用 `myfigma.nineSlice.v1` 记录和 `packages/nine-slice` 生成逻辑：记录含 `project`（项目统计参数）、`current`（当前生效参数）、`override`（人工覆盖）及兼容旧版的 `margins`/`overlap`/`width`/`height`。人工覆盖且仍适用于新尺寸时增量更新保留边距；图片缩小导致人工边距失效、项目参数无法应用或内部切片被人工改造时跳过并明确报告，不静默生成错误切片。
- 页面绑定键 `atlas.binding`：`{schemaVersion:1,projectId}`；组件来源键 `atlas.source`：v1 来源身份、类型（`atlas`/`standalone`）、原始名称、相对路径、引擎引用、尺寸、裁切、偏移。增量同步键 `atlas.sync.v1` 保存内容指纹、原始尺寸和 `current`/`source-missing` 状态；分类 Frame 使用 `atlas.category` 标记。显示名称、分类和位置不参与来源身份。
- 导入使用真实 Figma `createImage` / `createComponent`，只上传每张散图，不上传整张图集。任务中切换页面或 Figma 图片创建失败会删除本次新建组件/Frame，恢复本次已更新组件的尺寸、填充、来源与同步键，恢复已写的 `source-missing` 标记，并恢复原页名称/绑定；不会删除原有用户节点或既有组件。成功后保留进度，失败回滚后进度归零，允许修复后重试。
- #4 已实现按来源身份的原位增量、内容/尺寸变化检测、源缺失标记、人工结构跳过和实例尺寸尽量保持。#6 已实现布局九宫格导入、普通组件原位升级和不自动降级；取消/补齐、九宫格人工编辑与恢复、完整分类和对照页仍属 #5、#7–#10。助手托盘已在 #11 提供，插件自身不带托盘，也不以禁用的假按钮模拟未实现能力。

## 自动化验证

两目录各自执行 `npm ci`；插件的测试钩子会构建本插件和相邻助手，生产插件本身不依赖助手源代码的相对位置。

```powershell
npm run test:all
npm audit --audit-level=low
```

`test:all` 包含类型检查、18 个 Node 任务链路/连接安全、递归扫描载荷、增量流程、助手重启恢复及主线程沙箱加载测试、4 个 Playwright 浏览器交互测试。可分别运行 `npm test` / `npm run test:browser`。浏览器配置使用本机已有 Chrome（`channel: chrome`）；无 Chrome 时可安装经授权的浏览器或显式调整本目录测试配置。本次尝试下载 Playwright Chromium 超时，未将下载成功计为验收；实际浏览器验证使用系统 Chrome。

### 已验证（不是 Figma 真实渲染验收）

- 通过真实 Rust 子进程的 HTTP 登记 → 全量搜索/长期维护 → 扫描 → 插件任务入口 → Figma 平台替身，观察页面绑定、未分类 Frame、主组件名称/尺寸/来源/图片数量和进度。
- 非空未绑定、错绑和改名保护；绑定一致的非空页允许增量；执行中拒绝项目切换、重复任务；失败回滚与重试；断连清理过期扫描；清空游戏选择清理旧目标。
- 首次导入→无变化重复导入→像素/尺寸变化→改名/跨图集移动→源删除→不完整扫描→人工结构修改，覆盖新增、原位更新、源缺失标记、跳过提示、不留重复主组件及实例尺寸保持。
- 布局九宫格扫描→导入→新增用法原位升级→用法消失不降级→人工边距保留→失效边距跳过→人工改造九宫格结构跳过，覆盖公共引用忽略、多参数选择及跨两个插件的记录兼容。
- 浏览器实际运行构建的 UI，处于 opaque-origin 沙箱中：首次／自动配对、忘记配对、管理登记、默认列表/全量搜索、扫描摘要、hover／编号提示、编辑锁定态、无页面滚动、执行中禁用、进度、断连提示。HTTP 使用真实助手，Figma 消息宿主是测试替身。
- 真实 Figma 客户端确认 520×720 主面板和 520×704 管理弹窗均无外层滚动；重新打开插件可自动连接，令牌输入框保持为空。
- 像素正确性由助手的公开 HTTP 测试读取仓库固定 2×1 PNG，比较恢复 PNG 的明确 RGBA 字面值；不是替身的像素裁剪模拟。
- Node 依赖审计修复了 esbuild 开发服务器公告，使用 0.28.1+；本项目不运行 esbuild dev server。

### 实际红→绿证据

| 回归/纵向行为 | 修复前的实际失败 | 修复后 |
| --- | --- | --- |
| 完整登记扫描导入入口 | `HelperClient is not a constructor`（初始空入口） | 任务链路通过 |

### 真实客户端验收与剩余边界

用户授权独立空白测试文件后，使用 Playwright 连接真实客户端，实际执行加载、localhost 配对、登记、页面校验、扫描和导入。修复消息来源后，页面校验立即返回；两张小样散图扫描约 0.12 秒、导入约 0.37 秒，仅为一次小样记录。

通过 Figwright 读回 1×1 与 2×2 主组件、自动布局及实例关联，并从 Figma 提取原始图片填充，核对绿色和透明留白红色 PNG 的全部像素。原生资源面板搜索插入实例及实例交换通过；非空未绑定页、错误页名保护和测试矩形保留通过。测试内容仅写入该独立文件，不操作其他设计稿。

在真实 Figma 的 `auto_acceptance` 资源页补齐增量验收：先导入两张旧版组件，首次扫描显示「更新 2」；再次无变化扫描显示「未变 2」，组件身份未变。修改临时源图集红像素后扫描显示「更新 1 · 未变 1」，导入后从 Figma 取回 2×2 原始填充，右下角为新的蓝色像素；预先缩放到 20×20 的红色实例仍为 20×20。删除临时源图集后扫描显示「源缺失 2」，导入后两个主组件和实例仍在；恢复源文件后可再次更新回当前状态。该过程同时暴露并修复了 `dynamic-page` 下 `page.findAll()` 前必须 `await page.loadAsync()` 的真实客户端问题。

未在真实 Figma 重跑「扫描不完整时抑制源缺失」和「人工结构修改跳过」，这两项由公开流程测试覆盖；也没有执行三个实际游戏项目的兼容/性能验收，不将该小样结果扩展为完整图集支持或所有环境的网络兼容保证。

开发依赖：TypeScript、esbuild、Figma plugin typings、Playwright、SES（仅测试安全求值）；运行时无 Node/Web 框架依赖。构建/测试产物均由本目录 `.gitignore` 排除。
