# 资源导入器插件

独立 Figma Design 开发插件，通过本机 Rust 助手将项目私有图集和独立 PNG 导入为唯一主组件库。运行时不依赖 ui-studio、独立九宫格插件或 Node 服务。

[工具入口与任务状态](../README.md) · [整合规格 #22](https://github.com/leiyihai/MyFigma/issues/22) · [领域术语](../../../GLOSSARY.md)

## 构建与连接

要求 Node 24、npm；完整流程测试还需要 Rust stable。先按[助手说明](../local-helper/README.md)构建并启动助手；安装或更新依赖须先获准。

```powershell
npm ci
npm run typecheck
npm run build
```

Figma 导入本目录根 `manifest.json`，入口为 `dist/code.js` 和 `dist/ui.html`，无需开发服务器。网络白名单仅在开发模式放行 `http://localhost:38473`，不支持远端助手，也不要改成 `*`。

1. 在底栏齿轮打开资源助手设置，填写本机配对令牌和助手文件夹。令牌从 `%LOCALAPPDATA%\MyFigmaAssets\token` 读取，或由助手托盘菜单／`resource-helper.exe --show-token` 显示；不要贴到聊天、Issue 或日志。
2. 手动运行 `resource-helper.exe`，点击连接。连接成功自动保存本机配对；下次打开自动连接。设置中“忘记配对”删除保存令牌，首次仍需手动复制。
3. “启动资源助手”尝试打开已保存文件夹；Figma 不允许 `file://` 时会复制路径并打开设置，请粘贴到资源管理器后双击 exe。此按钮不保证直接启动程序。
4. 连接失败先检查托盘进程、端口占用和本地网络权限，重启助手后重新连接。健康检查按操作触发，不轮询；HTTP 默认超时 30 秒，Figma 消息桥接 60 秒。

令牌经 UI 与主线程保存到本机 `figma.clientStorage`，不写文档、不账号同步、不上传。自动连接会把令牌发往本机固定服务；端口被未知程序占用时先排查，必要时忘记配对并轮换令牌。

## 导入与增量更新

1. 管理项目中登记名称、编号、资源目录和长期维护标记。支持游戏根或直接私有图集目录，可先用助手 `examples` 演示。默认下拉只列长期维护项目，全部项目在管理弹窗维护；编号编辑时锁定，改编号应另登记。删除只删登记，不删磁盘或 Figma 内容。
2. 不同游戏使用不同 Figma 文件。首次选择空白页；自动校验通过后扫描，核对图集、散图、独立图片、布局引用、九宫格、忽略公共引用及异常摘要。
3. 扫描递归读取项目内对象式 JSON + PNG、恢复原尺寸和透明偏移，导入未打包独立 PNG，不按布局引用过滤、不向外补找公共资源。旋转、坏格式、超限等报告后跳过。“扫描不完整”可导入成功部分，但不会据此标记源删除。
4. 导入前显示新增、更新、源缺失、未变和跳过。首次写入将空白页命名“游戏名称（项目编号）- 分类资源”并绑定；后续校验页名和绑定。非空未绑定、错绑、绑定损坏和页名不符均拒绝，不清空用户内容。
5. 唯一主组件进入分类 Frame；普通素材使用图片组件，有九宫格用法时使用共用切片核心。显示名为“分类/散图原名”，同类同名追加来源路径；原名另存于来源记录。
6. 再次扫描按来源身份和内容指纹更新。像素／尺寸变化原位写入，尽量保持实例设计尺寸；改名或跨图集移动按旧身份源缺失 + 新身份新增，不按显示名或像素猜测匹配。源删除只标记，不删除主组件或实例。
7. 人工内部结构改造、非法边距等跳过并报告；工具来源记录损坏时阻止可能的重复创建，分类 Frame 内无关用户组件不改造。

任务中禁止切换项目、管理修改和重复启动。扫描显示阶段状态而非逐文件百分比，导入显示已尝试数量／总量，完成后记录耗时与结果，异常详情按需打开。扫描期间切页会重新校验，校验完成前禁用导入。

### 失败、取消与补齐

- 单项失败只恢复该项的尺寸、图片和来源／同步状态，新增半成品移除；其他成功项保留，不全局回滚。只有没有任何成功写入时，才按原状态恢复本轮页面名称／绑定并清理新建空 Frame，不覆盖用户同期修改。
- 扫描取消中止 UI 请求并丢弃结果，助手已开始的扫描可能短暂继续；需要重新扫描。它不是空扫描，不据此标记源删除。
- 导入取消在每项之间检查，停止后续调度，已完成项保留，未完成项不记成功，未处理的源缺失不补写。保留有效扫描结果时可直接再次导入，只补齐剩余项。
- 任务状态如实显示就绪、部分失败或已取消，列出成功／失败数与原因，不把部分完成写成全部成功。

## 用途分类与页面类别

优先级统一为 **人工覆盖 > 页面命名规律 > 通用前缀 > 名称关键词 > 尺寸比例 > 未分类**。九宫格是独立拉伸属性，不决定用途，九宫格按钮仍可归按钮。

默认七类按“按钮 → 底板 → 图标 → 背景 → 艺术字 → 进度条 → 未分类”排序。通用前缀不区分大小写，识别 `btn`/`button`、`icon`、`bg`/`background`、`panel`、`progress`/`pbar`、`font`/`wordart`；前缀未命中再查完整名称关键词，最后按尺寸兜底，没有明确线索归未分类。项目特有类别可由人工选择和命名规律使用，不靠新增类别自动产生规则。

- 页面配置保存有序名称和稳定颜色；类别名去首尾空白后唯一、最多 24 字符，不含 `/`、`\` 或控制字符，最多 64 类，始终包含未分类。
- 新增先创建分类 Frame 再写配置，颜色先取调色板未用色，用尽后按索引稳定生成互异色；已有颜色和顺序不随重新打开改变。
- 改名原位替换名称，保留顺序、颜色与 Frame 身份；同步类别标记、人工覆盖、显示名、命名规律和会话撤销快照，不重算组件自动类别，来源与实例关系不变。
- 删除需确认，只把带工具来源记录的子节点移到未分类，清除指向被删类别的人工覆盖，**不写成“未分类”人工标签**。无关用户对象留在原 Frame，Frame 仍有内容则保留并清除类别标记，只有空 Frame 删除；返回迁移／保留数量。失败恢复本次受影响状态及配置、规律。
- 未分类不可删除、不可改名。类别配置损坏回退默认七类，只在已绑定资源页回写修复；不在配置里的旧“九宫格底板”等类别不自动迁移、不认领、不移动、不参与整理，legacy `unsorted` 仍读作未分类。
- 类别管理入口可在未连接或未选项目时只读打开。新增／改名／删除／清空规律要求已选择游戏、当前页匹配且已绑定、任务空闲；未选游戏提示“先选择游戏”，未绑定提示先导入。写类别本身不请求助手 HTTP，不额外以助手在线状态授权。

### 选中分类与撤销

选中本工具主组件或实例后，面板显示页面彩色标签；实例映射主组件，无关对象只计数不改造。单一类别高亮，混合选择不错误高亮某一类。点击其他标签立即批量移动、刷新显示名并写人工覆盖，来源身份与实例关系不变；点击已高亮类别是空操作，无可修改组件时禁用。

人工覆盖在后续增量中保留。“恢复自动分类”清除覆盖，按当前命名规律及通用回退重算，不再只执行旧前缀／尺寸规则。

“撤销”保存最近一次人工分类（含批量）的操作前类别与覆盖状态，按快照恢复组件，不重算组件类别；之后页面命名规律仍会按当前人工标签重学。缺失、无关或类别不再适用的对象跳过并计数。下一次人工分类覆盖记录，撤销完成或恢复自动分类清空记录，类别改名重定向快照。记录只存在当前 UI 会话，不写页面或 clientStorage，重开插件即失效；入口抛错时保留记录并提示。

### 命名规律

从当前页人工标签学名称族，不硬编码某游戏规则。学习输入要求来源完整、属于当前项目并按身份去重，损坏或无关对象跳过；自动分类结果及工具删类别的迁移不作为标签。

- 名称小写后按非字母数字中文分隔；首段为 `prefix`，其余为 `suffix`，纯数字或首段 `number` 另记 `glyph`。同名称重复 token 一票，token 超过 64 字符丢弃。
- 多数票规则需 `support ≥ 2`、未舍入 `purity ≥ 0.6`，记录少数票 `conflicts`；纯度落盘保留三位小数。按支持度降序、同支持度 token 升序保存，最多 400 条。
- 匹配按 `log(1+support) × purity` 得分，平分先支持度大者、再页面类别顺序；指向已不存在类别的规则不命中。导入、增量和恢复自动分类共用该优先级，人工覆盖最高。
- 人工分类、撤销及类别变更后重学；缺失时按现有人工标签惰性补算，无标签不凭空制造规则；损坏时重建，无标签则写空，只写已绑定资源页，不阻断导入。
- 类别管理显示“命名规律 N 条 · 预计命中 M 条”：N 为规则数，M 只统计当前页没有人工覆盖且可匹配的主组件；导入预览的“按学习命名规律预分类 N 条”是本批资源命中数，三者口径不同。
- “清空规律”仅写空规则，**不会立即重学、搬动或重分类已有组件**。后续需要自动计算的操作回退通用规则，下次人工分类、撤销或类别变更再重学；不是全页一键重分类。

### 提交训练样本

动作行的“提交训练样本”收集当前资源页有效来源主组件的人工覆盖，向本机助手发送项目编号及 `identity`、`category`。自动类别、无效旧类别、显示名、图片、令牌和本机路径均不进入样本；不需选中组件、不改变画布、不访问远端。

同一来源身份仅保留第一条并报告忽略数。无标签只提示，不用空结果覆盖旧样本；重复提交整体替换本机该项目的最新样本，成功显示保存数量。未连接或忙碌时禁用，失败显示助手可操作错误。协议、请求上限和本机文件格式见助手说明；视觉模型评估仍属 #20，不随提交自动开始。

## 九宫格与共享记录

两个插件分别 bundle 共用核心。主组件以切片矩形、图片裁剪和约束实现角固定、边单向拉伸、中心双向拉伸，内部无 Auto Layout。项目最高频参数由助手统计，普通组件出现用法原位升级，用法消失不自动降级。

参数共享使用 Figma **shared plugin data**：namespace `myfigma`、key `nineSlice.v1`。旧私有 `myfigma.nineSlice.v1` 只作兼容回退，导入器读取旧组件时可迁移到共享记录。记录区分 `project`、`current`、`override`，并保留旧字段；不能因两插件私有键同名就认为可互读。

人工边距有效时增量保留，只有实际改变边距或消缝才标记覆盖；图片缩小导致人工边距失效或切片被人工改造时跳过并报告。存在适用的项目参数时，可在独立插件原位恢复后重试增量；恢复使用组件已保存的项目参数，不即时扫描磁盘。实例在九宫格编辑流程中提示定位主组件，不像用途分类那样自动映射写入。

## 排版与可选对照页

分类 Frame 横向 Auto Layout 自动换行，新增组件追加，普通增量不移动既有 Frame。“重新整理”在资源页按页面类别配置从左到右单行摆放工具 Frame，在对照页按 `ceil(sqrt(n))` 列近方形网格摆放分组；只改 Frame 坐标，不重建组件、实例或九宫格切片。

“对照页”不需要先扫描，按来源记录创建或更新“游戏名称（项目编号）- 图集对照”绑定页；每个图集一组、独立图片另组，全部是现有主组件实例。重复点击复用页面和实例、补齐缺失，清理工具重复或已不存在身份的实例；源缺失主组件仍保留时其实例也保留。默认／日常增量不维护对照页结构。绑定损坏拒绝操作，其他游戏绑定和同名用户页不接管，同名时另建带“（工具创建）”后缀页。删除对照页不影响来源或增量。

## 界面约定

- 主面板 350×600，任务状态与底栏固定，主面板无整体滚动。标签高 24px、间距 6px、最多四行（114px 可视高度），更多类别只在标签区内滚动；当前类别滚出时仅调整标签区滚动位置。
- 正文 12px、标签 11px，类别色只用于色点和当前描边；中性背景、文字、边框取 Figma 主题变量，名称、✓ 与 `aria-pressed` 共同表达状态，不只靠颜色。
- 类别管理、撤销、提交训练样本同行；恢复自动分类作为次级动作随标签区滚动，不另撑高面板。类别弹窗提供固定新增／改名／确认区，类别列表内部滚动。
- hover 解释用途、适用条件和必要风险；未连接、无项目、无选择、忙碌、混合状态各自如实显示。
- 浅／深色自检截图曾保存在仓库外 `E:/MyFigma-notes/issue-13/screens/`，属于构建后浏览器 UI 证据，**不是**新版真实 Figma 渲染验收。

## 开发验证与历史证据

已安装依赖后运行：

```powershell
npm run test:all
npm audit --audit-level=low
```

`test:all` 包含类型检查、Node 流程和 Playwright 浏览器交互；可分别运行 `npm test`、`npm run test:browser`，测试钩子构建插件与相邻真实 Rust 助手。浏览器配置使用系统 Chrome，缺少浏览器时安装须获准。生产插件不依赖助手源码的相对位置。

- `workflow`、`incremental`、`full-scan`、`compare`、`nine-slice` 测试从公开 Workflow／平台入口观察文档与错误；真实 HTTP 和像素由助手子进程验证。
- `category` 和 `samples` 覆盖类别配置、人工覆盖、改名／删除、撤销、规律优先级与阈值、损坏重建、失败回滚和人工样本导出／覆盖，不为私有函数另造入口。
- 浏览器加载构建后 UI，覆盖配对、项目管理、进度取消、标签、类别弹窗、撤销、样本和无外层滚动；Figma RPC 宿主为替身，不把其简化业务当作平台数据正确性的证据。
- 主线程安全沙箱回归验证实际 bundle 可加载，SES 不是原生 Figma；嵌套窗口回归允许可信 Figma 顶层消息，拒绝陌生来源。manifest 开发域名统一 localhost，测试不等同于原生 manifest 校验器。
