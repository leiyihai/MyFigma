# 项目图集导入插件（#3、#4、#5、#6、#8、#10）

独立 Figma Design 开发插件，真实连接 Rust 本地助手。没有 ui-studio 运行时依赖，不修改共享核心或独立九宫格插件。

## 构建与使用

要求 Node 24、npm、Rust stable（完整测试会启动真实助手）。先按 [助手 README](../local-helper/README.md) 构建并启动助手。

```powershell
npm ci
npm run typecheck
npm run build
```

构建产物：`dist/code.js`（Figma 主线程）、`dist/ui.html`（内联 UI 脚本）；无需开发服务器。Figma 的开发插件入口选择此目录 `manifest.json`。manifest 只在开发模式放行 `http://localhost:38473`；不承诺发布模式/远端助手，不要把域名改成 `*`。不同端口的测试只在浏览器沙箱运行，并未改变 manifest。

1. 首次使用时手动启动助手（托盘图标悬停时应显示「资源助手运行中」），从本机 `%LOCALAPPDATA%\MyFigmaAssets\token` 读取令牌，粘贴到「配对令牌」并连接；保持「记住本机配对」勾选。之后重新打开插件会自动连接，无需再次粘贴。若连接失败，先确认托盘里的助手仍在运行（否则从构建产物重新启动），再检查端口及 Figma/浏览器本地网络权限。

「忘记配对」会删除本机保存的令牌并取消记住；忘记后可在助手托盘菜单选择「显示配对令牌」，或运行 `figma-assets-helper.exe --show-token`，再重新粘贴。首次配对仍需手动复制令牌，自动连接只省去重复粘贴。
2. 「管理项目」填写游戏名称、项目编号、资源目录（游戏根或直接 `res/imageset` 目录）和长期维护标记，保存。可以先登记助手的 `examples` 目录，编号如 `demo2`，名称如「示例游戏」。目录只保存在助手侧，UI 的编辑表单可读取它。
3. 默认下拉只显示长期维护游戏；搜索名称/编号会查全部登记。管理弹窗可以编辑名称、路径、维护标记，或删除登记；编号是身份，编辑时锁定，改变编号应另行登记。
4. 在**专门用于验收的 Figma 文件/空白页**选择游戏、校验、扫描，检查图集/散图/独立图片数量和异常，以及「布局引用／九宫格／公共引用忽略」汇总。扫描递归读取登记范围内的对象式 JSON + PNG，并导入未被打包的独立图片；摘要出现「扫描不完整」时说明有错误或触达规模上限，此时只能导入已成功拆解的部分，且不会把缺失资源标记为源删除。
5. 扫描摘要同时显示新增、更新、源缺失、未变和跳过数量。点击「导入主组件」：空白页命名为「游戏名称（项目编号）- 分类资源」，保存版本化绑定。主组件按用途归入页面上的独立分类 Frame：先看九宫格用法（含保留的九宫格结构），再看散图原名中的关键词（按钮/btn/button、图标/icon、背景/bg/background、艺术字/wordart/artfont/font/title、九宫格/底板/nine），最后用尺寸比例（≥512×512 为背景；方形且 8–256 像素为图标；高度 8–96 且宽高比 ≥2.5 为按钮）；没有明确线索时归入未分类，不做图片识别。分类 Frame 使用横向 Auto Layout + 自动换行，新主组件追加到末尾，普通增量更新不移动既有分类 Frame。有九宫格用法的散图用共用核心生成唯一九宫格主组件（切片裁剪、角固定/边单向拉伸/中心双向拉伸，内部不使用 Auto Layout），其余仍为普通图片组件。显示名为「分类/散图原名」，同一分类内同名时补充来源路径消歧；原始名字保存在来源记录中，显示名不改变资源身份。绑定一致的资源页可再次导入，组件按来源身份原位更新；普通组件新增九宫格用法时原位升级，用法消失时不自动降级；尺寸或九宫格用法变化导致用途改变时，主组件移动到新分类 Frame，身份、来源和实例关联保持不变。按钮悬浮提供用途和适用条件。
6. 扫描阶段显示阶段状态与不确定进度（助手一次请求返回完整扫描，不额外改协议）；导入阶段按「已尝试 / 总数」显示进度，并在「异常与失败详情」中按需展开逐项失败原因。
7. 扫描或导入执行中可点击「取消任务」：取消会停止调度后续工作，已完成项保留，未完成或未成功提交的项不记成功；源删除标记不会在取消后补写。取消后保留本次扫描结果，直接再次点击「导入主组件」即可按最新页面状态只补齐未完成项，不重复创建已成功组件。
8. 单项失败不会回滚整次任务：失败项恢复到导入前的自身状态并列入详情，其他成功项保留；再次运行会通过来源身份和内容指纹重新检测失败/未完成项。任务结束状态显示为「就绪」「部分失败」或「已取消」，并展示成功/失败数与上次导入摘要。
9. 需要核对源图集时，手动点击「创建 / 更新对照页」。首次点击新建「游戏名称（项目编号）- 图集对照」页，按来源记录中的图集分组为 Frame，独立图片单独成组；Frame 内只放现有主组件的实例，不复制主组件。再次点击更新同一绑定页，补齐新增素材并复用已有实例，不重复建页或重复实例；默认扫描/导入不会创建或改动该页，日常增量后再次点击即可反映当前分组。按钮悬浮说明额外实例会增加文件负担。若已有同名用户页，本工具另建带「（工具创建）」后缀的页面，不覆盖用户页。
10. 分类 Frame 最初自上而下按创建顺序摆放，普通增量只把新组件追加到对应 Frame，不整体重排。分类区域重叠时，点击「重新整理」：本工具创建的分类 Frame 按「按钮 → 九宫格底板 → 图标 → 背景 → 艺术字 → 未分类」从上到下重新摆放并消除重叠。该操作只改分类 Frame 坐标，不重建、不移动主组件，不改变九宫格切片及内部约束；按钮悬浮说明作用范围和会改变的位置。

非空未绑定页、绑定其他项目、绑定版本不符、名称与绑定不符均拒绝。每次扫描/导入都重新校验当前页，不清空用户已有内容。源删除只把已有组件标记为 `source-missing`，不删除组件或实例；散图改名、跨图集移动按旧身份移除加新身份新增，不按显示名或内容猜测匹配。对照页是可选的手动视图：只认页面绑定和本工具的实例标记，不按同名或页码接管用户页面；创建对照页不需要扫描，也不改变当前页。

## 本地开发地址兼容

实际手动验收发现 Figma 拒绝 manifest 的数字 IP 开发域名。按 [Figma 官方 manifest 文档](https://developers.figma.com/docs/plugins/manifest/) 中的本地服务器写法，改用 `http://localhost:38473`，同步调整 UI 默认值、客户端白名单和助手精确 Host 校验。

manifest 与构建 UI 地址一致性、localhost 实际配对连接、Host 冒用拦截及浏览器登记导入均已自动验证；这些测试不是 Figma 原生 manifest 校验器。修改后仍需在 Figma 重新加载 manifest、关闭旧助手并启动新构建，再用默认 localhost 地址配对。

## 边界和安全

- HTTP/配对/登记/源格式及身份决策详见助手 README。默认请求仅由 UI 发往 `http://localhost:38473`（助手只监听 IPv4 loopback；CLI 测试也支持精确数字回环地址），拒绝 HTTP 重定向。
- 勾选记住配对后，令牌只在 UI 与插件主线程之间传递，由主线程保存到本机 `figma.clientStorage`；不写入 Figma 文档、不上传远端、不进入日志。它是本机插件级保存，不是账号同步；点击忘记配对会删除。
- 自动连接会把保存的令牌发往保存的本机 `localhost` 端口；若该端口被未知程序占用，先不要打开插件，检查助手进程，必要时忘记配对并轮换令牌。
- UI 任务入口 `Workflow` 统一控制登记、搜索、选择、校验、扫描、导入和互斥状态。任务期间禁用项目切换、管理修改、重复扫描/导入和连接。选择变化或登记修改会使旧扫描失效；清空选择也清空旧目标。
- 连接检查按操作触发，不轮询。网络错误/401 显示未连接，并提示确认托盘中的助手是否仍在运行、必要时从构建产物重启后重新连接；不把失败当作扫描为空。重启助手后点击「连接助手」即可恢复扫描和导入，登记与令牌跨重启保留。请求 30 秒超时；Figma 桥接 60 秒超时。
- 主线程 `createFigmaPlatform` 只接受版本 3 的完整扫描（最多 20 000 项），校验身份、尺寸、嵌套相对路径、重复来源、可选的九宫格参数和警告，并白名单保存来源字段。不会把本机绝对路径、布局节点引用或未知字段写进文档。组件名为「分类/散图原名」；同一分类内同名时追加来源路径，避免跨图集或独立图片同名混淆。显示名只用于资源面板查找，不是资源身份；来源记录保留散图原名、相对路径和身份。分类 Frame 标记为 `atlas.category`；用户放入分类 Frame 的无关组件不会被当作损坏来源，也不会被改写。
- 九宫格主组件与独立九宫格插件共用 `myfigma.nineSlice.v1` 记录和 `packages/nine-slice` 生成逻辑：记录含 `project`（项目统计参数）、`current`（当前生效参数）、`override`（人工覆盖）及兼容旧版的 `margins`/`overlap`/`width`/`height`。人工覆盖且仍适用于新尺寸时增量更新保留边距；图片缩小导致人工边距失效、项目参数无法应用或内部切片被人工改造时跳过并明确报告，不静默生成错误切片。人工边距失效且存在可恢复的项目参数时，提示先在九宫格插件恢复项目参数再重试；恢复后记录为 `override:false`、`current:project`，增量导入可继续原位更新。
- 页面绑定键 `atlas.binding`：`{schemaVersion:1,projectId}`；组件来源键 `atlas.source`：v1 来源身份、类型（`atlas`/`standalone`）、原始名称、相对路径、引擎引用、尺寸、裁切、偏移。增量同步键 `atlas.sync.v1` 保存内容指纹、原始尺寸和 `current`/`source-missing` 状态；分类 Frame 使用 `atlas.category` 标记。显示名称、分类和位置不参与来源身份。
- 导入使用真实 Figma `createImage` / `createComponent`，只上传每张散图，不上传整张图集。任务按单项隔离：新增失败时删除该项半成品组件，更新失败时恢复该项尺寸/填充/来源/同步键，源缺失标记失败时恢复同步键；已完成的项保留。取消与失败均不宣称整次任务原子回滚——下次运行按来源身份重新检测并补齐，不会把未写入的项记为成功或把取消当成源删除。仅当本次没有任何成功写入时才恢复页面名称/绑定并移除新建的空 Frame；已有成功项时保留绑定以便增量补齐。不会删除原有用户节点或既有组件，也不会覆盖用户同期的页面名称/绑定修改。
- 对照页键 `atlas.compare`：页面绑定 `{schemaVersion:1,projectId}`；分组 Frame 使用 `atlas.compare.group`（`atlas:<相对路径>` 或 `standalone`），实例使用 `atlas.compare.item` 保存来源身份。分组依据主组件上的 `atlas.source` 来源记录，不依赖组件显示名或所在分类 Frame；无图集的独立图片只在「独立图片」分组出现。重复点击复用绑定页和已有实例，只补齐缺失实例；来源身份不再存在或重复的实例会移除，源缺失（`source-missing`）组件仍未删除，其实例保留。页面绑定损坏时拒绝继续而不是覆盖，绑定属于其他游戏时保持原样。
- #4 已实现按来源身份的原位增量、内容/尺寸变化检测、源缺失标记、人工结构跳过和实例尺寸尽量保持；#5 已实现扫描/导入进度、协作式取消、单项失败隔离及后续增量补齐；#6 已实现布局九宫格导入、普通组件原位升级和不自动降级；#7 已实现人工边距覆盖、失效跳过与恢复项目参数后的重试链路；#8 已实现按用途自动分类、分类 Frame 自动换行与重新整理；#10 提供可选的手动实例对照页。批量手动分类及恢复自动分类仍属 #9。助手托盘已在 #11 提供，插件自身不带托盘，也不以禁用的假按钮模拟未实现能力。
- 取消边界在插件侧：扫描取消会中止 UI 到助手的 HTTP 请求，助手已开始的扫描可能短暂继续但结果被丢弃；导入取消通过插件消息传入主线程，在每项之间检查。未新增助手取消协议字段，扫描仍是单次原子响应，因此扫描进度是阶段状态而非逐文件百分比。

## 自动化验证

两目录各自执行 `npm ci`；插件的测试钩子会构建本插件和相邻助手，生产插件本身不依赖助手源代码的相对位置。

```powershell
npm run test:all
npm audit --audit-level=low
```

`test:all` 包含类型检查、41 个 Node 任务链路/连接安全、递归扫描载荷、增量流程、取消与单项失败补齐、按需对照页、助手重启恢复及主线程沙箱加载测试、4 个 Playwright 浏览器交互测试。可分别运行 `npm test` / `npm run test:browser`。浏览器配置使用本机已有 Chrome（`channel: chrome`）；无 Chrome 时可安装经授权的浏览器或显式调整本目录测试配置。本次尝试下载 Playwright Chromium 超时，未将下载成功计为验收；实际浏览器验证使用系统 Chrome。

### 已验证（不是 Figma 真实渲染验收）

- 通过真实 Rust 子进程的 HTTP 登记 → 全量搜索/长期维护 → 扫描 → 插件任务入口 → Figma 平台替身，观察页面绑定、分类 Frame、主组件名称/尺寸/来源/图片数量和进度。
- 自动分类（#8）：名称关键词、九宫格用法和尺寸比例分别归入六类；方形小图/宽扁条/大图按比例分类，无线索的图片和独立图片留在未分类；唯一主组件只放在分类 Frame 内，不创建第二套组件或对照页。同类同名时两个组件都追加来源路径，重复导入复用同一 Frame 与组件；尺寸或九宫格用法变化后组件跨分类移动，身份/来源/组件 ID 不变。重新整理按固定顺序摆放分类 Frame 并消除重叠，只改 Frame 坐标，九宫格切片约束不变；普通增量不移动既有 Frame。分类 Frame 内的用户自有组件不阻塞导入；工具记录损坏或被整体清除时，仍按工具插件记录或「分类/原名」显示名拦截重复创建。
- 分类 Frame 自动换行参数（`layoutMode`、`layoutWrap`、固定主轴/自适应纵轴、间距与内边距）与新建位置不重叠由平台流程断言；真实 Figma 渲染和资源面板搜索/插入/交换不在本 worktree 的自测范围。
- 非空未绑定、错绑和改名保护；绑定一致的非空页允许增量；执行中拒绝项目切换、重复任务；断连清理过期扫描；清空游戏选择清理旧目标。
- 单项失败隔离：注入第二张图片创建失败，第一项已成功项保留且同步状态为当前，失败项无组件/无同步记录，详情显示原因；保留扫描结果直接重试只创建剩余项，不重复创建。取消：执行中取消后停止调度，已完成为 1 项、未完成项既不记成功也不写源缺失；保留扫描结果再次导入只补齐，取消时的待标记源删除在重试后才写入。扫描取消丢弃结果，不按空结果标记源删除。
- 浏览器实际验证取消按钮仅在扫描/导入执行中启用，hover 说明准确；取消后显示「已取消」、成功/失败摘要，保留扫描结果并允许重试。
- 首次导入→无变化重复导入→像素/尺寸变化→改名/跨图集移动→源删除→不完整扫描→人工结构修改，覆盖新增、原位更新、源缺失标记、跳过提示、不留重复主组件及实例尺寸保持。
- 布局九宫格扫描→导入→新增用法原位升级→用法消失不降级→人工边距保留→失效边距跳过→九宫格插件恢复项目参数→重试原位更新成功→人工改造九宫格结构跳过，覆盖公共引用忽略、多参数选择及跨两个插件的真实入口调用。
- 按需对照页（#10）：默认导入无对照页；首次手动创建按 `atlas.source` 图集分组、独立图片单独成组、只建实例不复制主组件；重复点击复用页面和实例；新增素材后日常增量不改对照页，再次点击才补齐；同名用户页与绑定其他游戏的页面保持原样，删除对照页后来源保存与增量导入仍可用。
- 浏览器实际运行构建的 UI，处于 opaque-origin 沙箱中：首次／自动配对、忘记配对、管理登记、默认列表/全量搜索、扫描摘要、hover／编号提示、编辑锁定态、无页面滚动、执行中禁用、进度、断连提示，以及默认导入不建对照页、对照页按钮悬浮文件负担提示与手动创建结果。HTTP 使用真实助手，Figma 消息宿主是测试替身。
- 真实 Figma 客户端确认 520×720 主面板和 520×704 管理弹窗均无外层滚动；重新打开插件可自动连接，令牌输入框保持为空。
- 像素正确性由助手的公开 HTTP 测试读取仓库固定 2×1 PNG，比较恢复 PNG 的明确 RGBA 字面值；不是替身的像素裁剪模拟。
- Node 依赖审计修复了 esbuild 开发服务器公告，使用 0.28.1+；本项目不运行 esbuild dev server。

### 真实客户端验收与剩余边界

用户授权独立空白测试文件后，使用 Playwright 连接真实客户端，实际执行加载、localhost 配对、登记、页面校验、扫描和导入。修复消息来源后，页面校验立即返回；两张小样散图扫描约 0.12 秒、导入约 0.37 秒，仅为一次小样记录。

通过 Figwright 读回 1×1 与 2×2 主组件、自动布局及实例关联，并从 Figma 提取原始图片填充，核对绿色和透明留白红色 PNG 的全部像素。原生资源面板搜索插入实例及实例交换通过；非空未绑定页、错误页名保护和测试矩形保留通过。测试内容仅写入该独立文件，不操作其他设计稿。

在真实 Figma 的 `auto_acceptance` 资源页补齐增量验收：先导入两张旧版组件，首次扫描显示「更新 2」；再次无变化扫描显示「未变 2」，组件身份未变。修改临时源图集红像素后扫描显示「更新 1 · 未变 1」，导入后从 Figma 取回 2×2 原始填充，右下角为新的蓝色像素；预先缩放到 20×20 的红色实例仍为 20×20。删除临时源图集后扫描显示「源缺失 2」，导入后两个主组件和实例仍在；恢复源文件后可再次更新回当前状态。该过程同时暴露并修复了 `dynamic-page` 下 `page.findAll()` 前必须 `await page.loadAsync()` 的真实客户端问题。
