# 资源导入器（#3、#4、#5、#6、#8、#9、#10、#13、#14、#15、#16、#17、#18、#21）

独立 Figma Design 开发插件，真实连接 Rust 本地助手。没有 ui-studio 运行时依赖，不修改共享核心或独立九宫格插件。

## 构建与使用

要求 Node 24、npm、Rust stable（完整测试会启动真实助手）。先按 [助手 README](../local-helper/README.md) 构建并启动助手。

```powershell
npm ci
npm run typecheck
npm run build
```

构建产物：`dist/code.js`（Figma 主线程）、`dist/ui.html`（内联 UI 脚本）；无需开发服务器。主界面固定为 350×600：任务阶段、进度和取消固定在底部，主面板不整体滚动；类别标签区最多四行，类别更多时只在标签区内部滚动。静态说明收进 hover。Figma 的开发插件入口选择此目录 `manifest.json`。manifest 只在开发模式放行 `http://localhost:38473`；不承诺发布模式/远端助手，不要把域名改成 `*`。不同端口的测试只在浏览器沙箱运行，并未改变 manifest。

1. 首次使用时手动启动助手（托盘图标悬停时应显示「资源助手运行中」），从本机 `%LOCALAPPDATA%\MyFigmaAssets\token` 读取令牌。点击底栏连接状态左侧的齿轮打开「资源助手设置」，填写配对令牌和资源助手文件夹（例如当前构建的 `local-helper\target\release`）并保存。未连接时点击底栏「启动资源助手」尝试打开该文件夹；Figma 插件 API 不允许 `file://` 时，会复制路径并打开设置、选中路径字段，请在资源管理器地址栏粘贴打开。双击 `resource-helper.exe` 后再点击「连接资源助手」；地址固定为 `localhost:38473`，成功后自动记住。之后重新打开插件会自动连接，无需再次粘贴；资源助手文件夹也会保留。若连接失败，先确认托盘里的助手仍在运行（否则从构建产物重新启动），再检查端口及 Figma/浏览器本地网络权限。

资源助手设置中可「忘记配对」，删除本机保存的令牌；忘记后可在助手托盘菜单选择「显示配对令牌」，或运行 `resource-helper.exe --show-token`，再重新粘贴。首次配对仍需手动复制令牌，自动连接只省去重复粘贴。
2. 「管理项目」填写游戏名称、项目编号、资源目录（游戏根或直接 `res/imageset` 目录）和长期维护标记，保存。可以先登记助手的 `examples` 目录，编号如 `demo2`，名称如「示例游戏」。目录只保存在助手侧，UI 的编辑表单可读取它。
3. 默认下拉只显示长期维护游戏；全部登记项目在管理弹窗中维护。管理弹窗可以编辑名称、路径、维护标记，或删除登记；编号是身份，编辑时锁定，改变编号应另行登记。
4. 在**专门用于验收的 Figma 文件/空白页**选择游戏；插件会自动检查当前页是否可作为资源页，状态显示在游戏项目区。然后扫描，检查图集/散图/独立图片数量和异常，以及「布局引用／九宫格／公共引用忽略」汇总。扫描递归读取登记范围内的对象式 JSON + PNG，并导入未被打包的独立图片；摘要出现「扫描不完整」时说明有错误或触达规模上限，此时只能导入已成功拆解的部分，且不会把缺失资源标记为源删除。
5. 扫描摘要同时显示新增、更新、源缺失、未变和跳过数量。点击「导入主组件」：空白页命名为「游戏名称（项目编号）- 分类资源」，保存版本化绑定。主组件按用途归入页面上的独立分类 Frame：先看当前资源页从人工标签**学到的命名规律**（见第 12 条），命中即用它定类；未命中再按散图原名开头的 token（`btn`/`button` → 按钮，`icon` → 图标，`bg`/`background` → 背景，`panel` → 底板，`progress`/`pbar` → 进度条，`font`/`wordart` → 艺术字），token 以 `_`、`-`、`.`、空格、数字等边界切分且大小写不敏感；前缀不匹配时回退到散图原名中的关键词（按钮/btn/button、底板/面板/panel、图标/icon、背景/bg/background、艺术字/wordart/artfont/font/title、进度/progress/pbar），再回退到尺寸比例（≥512×512 为背景；方形且 8–256 像素为图标；高度 8–96、宽度 ≤1024 且宽高比 ≥2.5 为按钮）；没有明确线索时归入未分类，不做图片识别。人工覆盖始终最高优先，学到的规律不会覆盖它；「恢复自动分类」按同一优先级重算。预览摘要会写「按学习命名规律预分类 N 条」，让用户在导入前知道这批素材会被怎么分。九宫格用法、边距与切片结构只决定拉伸，不参与用途，因此九宫格按钮仍归按钮、九宫格进度条仍归进度条。分类 Frame 使用横向 Auto Layout + 自动换行，新主组件追加到末尾，普通增量更新不移动既有分类 Frame。有九宫格用法的散图用共用核心生成唯一九宫格主组件（切片裁剪、角固定/边单向拉伸/中心双向拉伸，内部不使用 Auto Layout），其余仍为普通图片组件。显示名为「分类/散图原名」，同一分类内同名时补充来源路径消歧；原始名字保存在来源记录中，显示名不改变资源身份。绑定一致的资源页可再次导入，组件按来源身份原位更新；普通组件新增九宫格用法时原位升级，用法消失时不自动降级；尺寸变化导致用途改变时，主组件移动到新分类 Frame；九宫格用法出现/消失只改变拉伸结构，身份、来源和实例关联保持不变。按钮悬浮提供用途和适用条件。
6. 扫描阶段显示阶段状态与不确定进度（助手一次请求返回完整扫描，不额外改协议），完成后摘要追加扫描耗时；导入阶段按「已尝试 / 总数」显示进度，完成后在最近操作行显示导入耗时，并在「异常与失败详情」浮层中按需查看逐项失败原因。
7. 扫描或导入执行中可点击「取消任务」：取消会停止调度后续工作，已完成项保留，未完成或未成功提交的项不记成功；源删除标记不会在取消后补写。取消后保留本次扫描结果，直接再次点击「导入主组件」即可按最新页面状态只补齐未完成项，不重复创建已成功组件。
8. 单项失败不会回滚整次任务：失败项恢复到导入前的自身状态并列入详情，其他成功项保留；再次运行会通过来源身份和内容指纹重新检测失败/未完成项。任务结束状态显示为「就绪」「部分失败」或「已取消」，并展示成功/失败数与上次导入摘要。
9. 需要核对源图集时，手动点击「对照页」。首次点击新建「游戏名称（项目编号）- 图集对照」页，按来源记录中的图集分组为 Frame，独立图片单独成组，分组按当前分组数量取近方形网格排列（例如 4 组 2×2、9 组 3×3、10 组 4×3）；Frame 内只放现有主组件的实例，不复制主组件。再次点击更新同一绑定页，补齐新增素材并复用已有实例，不重复建页或重复实例；默认扫描/导入不会创建或改动该页，日常增量后再次点击即可反映当前分组。按钮悬浮说明额外实例会增加文件负担。若已有同名用户页，本工具另建带「（工具创建）」后缀的页面，不覆盖用户页。
10. 分类 Frame 最初从左到右按创建顺序摆放，普通增量只把新组件追加到对应 Frame，不整体重排。分类区域重叠时，点击「重新整理」：本工具创建的分类 Frame 按当前资源页的类别配置顺序从左到右单行摆放并消除重叠（未配置时即「按钮 → 底板 → 图标 → 背景 → 艺术字 → 进度条 → 未分类」）。当前页是本工具对照页时，同一按钮只整理图集分组，按分组数量取 `ceil(sqrt(n))` 列近方形网格；不新增/删除实例，需要补齐素材仍点击「对照页」。整理只改 Frame 坐标，不重建、不移动主组件，不改变九宫格切片及内部约束；按钮悬浮说明作用范围和会改变的位置。
11. 在画布中选中一个或多个主组件或实例后，「选中主组件分类」把页面类别以彩色标签平铺显示（顺序、名称与颜色来自页面级配置回读），不再使用下拉框和「应用」按钮。单选或实例只高亮当前类别；混合选择不高亮任何单一类别，状态标签明确写「混合分类：…」；无关对象只计数、不改造，实例先定位主组件。点击其他类别标签立即把选中主组件批量移入该类别并更新显示名，保留来源身份和实例关系；点击当前已高亮的标签不产生任何写入。没有可修改的本工具主组件时整组标签禁用。标签的稳定色点只作辅助识别，名称、`aria-pressed` 选中态和 ✓ 标记保证不只靠颜色区分。标签区最多四行，类别更多时在标签区内滚动，当前类别滚出窗口时会自动滚回可见。该面板只读取 Figma 当前选择，不通过画布拖动推断分类意图。标签区末端保留「恢复自动分类」按钮：清除人工覆盖并按当前名称前缀与尺寸规则重新归类，它随标签区一起滚动，不额外撑高面板。
12. 标签区动作行最右侧的「类别管理」打开独立弹窗：按页面配置顺序列出当前类别（色点 + 名称），「未分类」标为「兜底类别」且没有删除按钮。填写新类别名称（去掉首尾空白后唯一、最多 24 字符、不含 `/`、`\` 与控制字符）后点击「新增类别」：先写入页面配置 `atlas.categories.v1` 并创建对应分类 Frame，标签区与弹窗立即回读新顺序；颜色由追加式调色板按「第一个未使用颜色」自动分配，页面配置保存颜色，重新打开页面或再次新增都不会重排已用颜色；调色板用尽后按索引沿色相环稳定生成新颜色，同一索引颜色恒定且不与已有颜色重复，不再复用旧色。删除其他类别需要先在同一弹窗内确认（确认条固定显示在列表下方）：只把带本工具来源记录的子节点（主组件等）移到「未分类」，页面还没有未分类 Frame 时新建一个，把指向被删类别的人工覆盖写空清除（不改写成「未分类」，否则会学出工具自造的假标签）并按新父分类刷新显示名；Frame 里若还有用户自有对象，保留该 Frame、只清除它的类别标记使其不再被本工具认领，并在返回提示中说明保留了多少个非本工具对象。最后才删除配置项与空分类 Frame；主组件、来源记录与实例关系都不丢。每个非「未分类」类别还带「改名」按钮：在列表下方的改名行里输入新名称并点「保存名称」，页面配置按同一位置、同一颜色换名，分类 Frame 原地改名并更新类别标记，指向该类别的人工覆盖与派生显示名（`分类/原名`）一起同步，来源身份、组件与实例关系不变；改名不重跑自动规则；本次会话里的撤销快照也一并指向新名称，避免撤销时把旧名称当作未知类别跳过；失败时把页面配置原文、`atlas.category.rules.v1` 原文、Frame 名与类别标记、人工覆盖一并改回原值，不留下半改的页面。「未分类」是兜底类别，没有改名与删除按钮。未分类不可删除，重名、非法名称、未选择游戏与任务执行中都会禁用提交并在弹窗内给出可操作的中文提示；同一名称/重名/非法名的提示与平台返回的文案一致。类别配置存在页面里，弹窗可只读打开；但新增、改名、删除都要经平台按当前项目校验页面绑定，因此未选择游戏时按钮禁用并提示「先选择游戏」（不会静默无效）。新增/删除只写已绑定的资源页，空白未绑定页会提示先导入主组件；面板仍是 350×600，动作行新增一个 24px「类别管理」按钮（与「撤销」「提交训练样本」同行，共三个），标签区四行内部滚动与底栏位置不变。弹窗顶部还显示「命名规律 N 条 · 预计命中 M 条」并提供「清空规律」：N 是当前页学到的规则条数，M 是按规律能匹配到的、没有人工覆盖的当前页组件数；清空只写空规则、不立即重学，分类回退通用规则，下一次人工分类或类别变更时才重新学习。命名规律从当前页人工标签学出（详见第 15 条），类别改名时指向该类别族同步改指新名称，删除类别时相关族随之失效，不会把组件重新引回已删除类别。
13. 标签区下方的分类动作行提供「撤销」：最近一次人工批量分类（含单次）是一个撤销单元，操作时返回该批组件操作前的类别与人工覆盖状态，撤销按这份快照写回并清除记录，不重新运行自动分类，也不改来源身份、同步记录或实例关联；已删除或不再属于本工具的组件安全跳过并计数。无记录或任务执行中按钮禁用，hover 说明显示本次可恢复的组件数；再次人工分类覆盖旧记录。恢复自动分类会让旧记录失效并清空撤销：类别已按当前规则重算，旧快照的类别不再对应当前页面状态，写回会覆盖刚算出的自动结果，因此不保留可撤销状态。失败时保留记录并在错误区给出可操作提示；撤销本身不把状态卡或底栏挤出 350×600。撤销记录只存在于当前 UI 会话（模块变量），不写入页面或 `clientStorage`，重新打开插件即不存在。
14. 分类标签下方的分类动作行提供「提交训练样本」：收集**当前资源页**中带人工类别覆盖（`atlas.category.manual`）的主组件，按 `atlas.source.identity` + 当前类别提交给本机助手，保存为该项目的训练样本。自动分类结果、显示名、图片和本机路径都不进入样本；不需要先在画布选中组件。没有人工覆盖时只给提示、不写空文件。重复提交按最新人工标签整体覆盖旧样本，成功后显示提交标签数量。未连接助手或任务执行中按钮禁用，失败时在状态区显示可操作的错误。该动作不改变画布，也不上传图片或访问远端。
15. 命名规律（#21）：每次人工分类、撤销或类别变更后，平台从当前资源页重算规则并写入 `atlas.category.rules.v1`（术语与阈值口径见 `GLOSSARY.md`「命名规律」）。学习输入只认真实人工覆盖：先按 `atlas.source` 校验项目与来源完整性，再按来源身份去重，损坏或无关组件跳过而不是让整页抛错。token 超过 64 字符在学习阶段直接丢弃，避免写盘后再读被判损坏；support/purity 用未舍入比例判定，落盘只保留 3 位小数。规则按 support 降序、同 support 按 token 升序存放并最多保存 400 条。记忆只来自人工标签，自动分类结果不作为训练信号；没有人工标签时页面不会写入该键。配置缺失时按现有人工标签惰性补算一次；损坏或含非法条目时整份回退，存在人工标签就**立即按标签重建并落盘**（没有标签才写空），只写已绑定资源页，不阻断导入与页面校验。类别管理弹窗展示「命名规律 N 条 · 预计命中 M 条」（字段为 `rules:{count,estimatedHits}`，口径见术语表）并可「清空规律」：只写空规则、不立即重学，分类回退通用规则，下一次人工分类或类别变更时才重新学习。导入预览追加「按学习命名规律预分类 N 条」。


非空未绑定页、绑定其他项目、绑定版本不符、名称与绑定不符均拒绝。每次扫描/导入都重新校验当前页，不清空用户已有内容。源删除只把已有组件标记为 `source-missing`，不删除组件或实例；散图改名、跨图集移动按旧身份移除加新身份新增，不按显示名或内容猜测匹配。对照页是可选的手动视图：只认页面绑定和本工具的实例标记，不按同名或页码接管用户页面；创建对照页不需要扫描，也不改变当前页。

## 分类标签视觉方案

- 颜色：页面配置里的类别颜色（`#rrggbb`）只用于标签色点与「当前类别」的描边；标签底、文字、边框和类别管理列表都取 Figma 中性变量（`--figma-color-bg`、`--figma-color-text`、`--figma-color-border`），浅色与深色主题的对比度交给 Figma，不把类别色当底色或文字色。
- 字号层级：面板正文 12px，类别标签 11px；弹窗沿用既有的 11px 列表名与 10px 辅助说明。
- 间距：标签高 24px、标签间 gap 6px；标签区可视高度 = 4×24 + 3×6 = 114px（CSS 为 `calc(var(--tag-height)*4 + var(--tag-gap)*3)`），超出只在标签区内部滚动，主面板不整体滚动，固定 350×600 不变。
- 标签状态：
  - 默认：中性底 + 边框，色点表达类别色，名称是识别主信息；
  - hover：Figma hover 中性底 + 更强边框；
  - 当前：`aria-pressed="true"` 加 ✓（`aria-hidden`），描边取类别色；
  - 混合选择：不点亮单一标签，`data-mixed="true"`，状态行写「混合分类：…」；
  - 禁用：没有可修改的本工具主组件或任务执行中，整组 `disabled` 与 `aria-disabled`；
  - 「恢复自动分类」是虚线边框的次级动作，与标签一起在标签区内滚动。

## 边界和安全

- HTTP/配对/登记/源格式及身份决策详见助手 README。默认请求仅由 UI 发往 `http://localhost:38473`（助手只监听 IPv4 loopback；CLI 测试也支持精确数字回环地址），拒绝 HTTP 重定向。
- 连接成功后令牌只在 UI 与插件主线程之间传递，由主线程保存到本机 `figma.clientStorage`；不写入 Figma 文档、不上传远端、不进入日志。它是本机插件级保存，不是账号同步；配对窗口中的忘记配对会删除。
- 自动连接会把保存的令牌发往保存的本机 `localhost` 端口；若该端口被未知程序占用，先不要打开插件，检查助手进程，必要时忘记配对并轮换令牌。
- UI 任务入口 `Workflow` 统一控制登记、选择、校验、扫描、导入和互斥状态；主界面不再提供搜索，避免与 Figma 原生搜索混淆。任务期间禁用项目切换、管理修改、重复扫描/导入和连接。选择变化或登记修改会使旧扫描失效；清空选择也清空旧目标。
- 连接检查按操作触发，不轮询。网络错误/401 显示未连接，并提示确认托盘中的助手是否仍在运行、必要时从构建产物重启后重新连接；不把失败当作扫描为空。重启助手后点击「连接资源助手」即可恢复扫描和导入，登记与令牌跨重启保留。请求 30 秒超时；Figma 桥接 60 秒超时。
- 主线程 `createFigmaPlatform` 只接受版本 3 的完整扫描（最多 20 000 项），校验身份、尺寸、嵌套相对路径、重复来源、可选的九宫格参数和警告，并白名单保存来源字段。不会把本机绝对路径、布局节点引用或未知字段写进文档。组件名为「分类/散图原名」；同一分类内同名时追加来源路径，避免跨图集或独立图片同名混淆。显示名只用于资源面板查找，不是资源身份；来源记录保留散图原名、相对路径和身份。分类 Frame 标记为 `atlas.category`；用户放入分类 Frame 的无关组件不会被当作损坏来源，也不会被改写。
- 九宫格主组件与独立九宫格插件共用 `myfigma.nineSlice.v1` 记录和 `packages/nine-slice` 生成逻辑：记录含 `project`（项目统计参数）、`current`（当前生效参数）、`override`（人工覆盖）及兼容旧版的 `margins`/`overlap`/`width`/`height`。人工覆盖且仍适用于新尺寸时增量更新保留边距；图片缩小导致人工边距失效、项目参数无法应用或内部切片被人工改造时跳过并明确报告，不静默生成错误切片。人工边距失效且存在可恢复的项目参数时，提示先在九宫格插件恢复项目参数再重试；恢复后记录为 `override:false`、`current:project`，增量导入可继续原位更新。
- 页面绑定键 `atlas.binding`：`{schemaVersion:1,projectId}`；组件来源键 `atlas.source`：v1 来源身份、类型（`atlas`/`standalone`）、原始名称、相对路径、引擎引用、尺寸、裁切、偏移；训练样本提交只读取 `atlas.source.identity` 与 `atlas.category.manual`，请求体只含 `{projectId,samples:[{identity,category}]}`，助手按项目写入本机 `samples/<projectId>.json`；同一来源身份重复出现时只导出第一条并返回 `ignored` 数量，成功提示追加「忽略 M 个重复身份」。新组件同时在该记录的 `sync` 字段保存内容指纹、原始尺寸和 `current`/`source-missing` 状态，旧 `atlas.sync.v1` 保留读取回退但不迁移。分类 Frame 使用 `atlas.category` 标记，人工分类覆盖使用 `atlas.category.manual`；页面级类别配置为 `atlas.categories.v1`：`{schemaVersion:1,categories:[{name,color}]}`，有序，缺省为默认七类，必须始终包含「未分类」；读取仅在已绑定资源页回写修复结果。类别新增/删除同样只写已绑定资源页：新增先建 Frame 再写配置；删除只迁移带工具来源记录的子节点、刷新显示名，然后写配置；只有空出来的分类 Frame 才删除，仍有用户自有对象的 Frame 保留并清除 `atlas.category` 标记，同时在消息里说明保留数量。单个页面最多 64 个类别（读回上限），达到上限时拒绝新增而不是写坏整份配置；调色板用尽后按索引沿色相环生成 `#rrggbb`，同一索引恒定且不与已有颜色重复。类别名去空白后唯一、最多 24 字符、禁止 `/`、`\` 与控制字符，颜色为 `#rrggbb`。不在当前配置里的旧 `atlas.category`（如「九宫格底板」）不被认领、不搬动、不参与重新整理也不改写，legacy `unsorted` 仍读作「未分类」。显示名称、分类和位置不参与来源身份。
- 导入使用真实 Figma `createImage` / `createComponent`，只上传每张散图，不上传整张图集。任务按单项隔离：新增失败时删除该项半成品组件，更新失败时恢复该项尺寸/填充/来源/同步键，源缺失标记失败时恢复同步键；已完成的项保留。取消与失败均不宣称整次任务原子回滚——下次运行按来源身份重新检测并补齐，不会把未写入的项记为成功或把取消当成源删除。仅当本次没有任何成功写入时才恢复页面名称/绑定并移除新建的空 Frame；已有成功项时保留绑定以便增量补齐。不会删除原有用户节点或既有组件，也不会覆盖用户同期的页面名称/绑定修改。
- 对照页键 `atlas.compare`：页面绑定 `{schemaVersion:1,projectId}`；分组 Frame 使用 `atlas.compare.group`（`atlas:<相对路径>` 或 `standalone`），实例使用 `atlas.compare.item` 保存来源身份。分组依据主组件上的 `atlas.source` 来源记录，不依赖组件显示名或所在分类 Frame；无图集的独立图片只在「独立图片」分组出现。重复点击复用绑定页和已有实例，只补齐缺失实例；来源身份不再存在或重复的实例会移除，源缺失（`source-missing`）组件仍未删除，其实例保留。页面绑定损坏时拒绝继续而不是覆盖，绑定属于其他游戏时保持原样。
- #18 已实现人工训练样本提交：只导出当前资源页中有 `atlas.category.manual` 且类别仍在该页配置里的主组件，身份取 `atlas.source.identity`；同一来源身份重复时只保留第一条、忽略数量进入返回值与成功提示；经 `HelperClient` 提交到本机助手（仍只允许 `localhost`/`127.0.0.1`，未加域名白名单），不接收或保存图片。没有人工覆盖时提示且不写空样本，失败显示助手返回的可操作错误；新增按钮位于分类动作行，未连接/忙碌禁用，不撑高 350×600 面板。类别管理弹窗可只读打开；新增、改名、删除需要已选择游戏并连接助手（类别写回要经平台按项目校验页面绑定）。
- #4 已实现按来源身份的原位增量、内容/尺寸变化检测、源缺失标记、人工结构跳过和实例尺寸尽量保持；#5 已实现扫描/导入进度、协作式取消、单项失败隔离及后续增量补齐；#6 已实现布局九宫格导入、普通组件原位升级和不自动降级；#7 已实现人工边距覆盖、失效跳过与恢复项目参数后的重试链路；#8 已实现按用途自动分类、分类 Frame 自动换行与重新整理；#9 已实现批量人工分类、人工覆盖保留和恢复自动分类；#15 把分类区改为彩色标签点击即分类，面板 350×600、标签区四行内部滚动；#16 提供类别新增/删除弹窗与未分类兜底迁移；#17 在分类动作行加入会话内「撤销」，按操作前快照恢复类别与人工覆盖且不重跑自动规则；#18 把人工覆盖提交为本机训练样本（`/v1/samples`，只含来源身份与类别）；#21 从人工标签学出页面级命名规律并在导入、增量与「恢复自动分类」中优先于通用规则，类别管理可查看并清空；#10 提供可选的手动实例对照页。助手托盘已在 #11 提供，插件自身不带托盘，也不以禁用的假按钮模拟未实现能力。

### 性能基准

- 内容指纹按分段流式计算并缓存到同一次扫描的资源对象，预览与导入不重复哈希整段 base64；首次导入在无重名时跳过全页重命名扫描。
- 导入进度约每 100 ms 刷新，每 20 项才让出一次事件循环；取消检查仍保留在每一项边界。
- 分类 Frame 在批量导入期间暂停 Auto Layout，全部写入后一次性恢复，避免每个组件 append 都触发重排。
- 新组件把来源和同步合并写入一个 `atlas.source` 私有记录；旧 `atlas.sync.v1` 仍可读取，不迁移旧数据。
- 真实 Figma 本机小基准：300 个独立 PNG 首次导入 6.79 秒（扫描 0.54 秒）；这是单次小样数据，不承诺完整 g1108 或三个游戏的固定耗时。
- 三个实际游戏首次导入、无变化扫描、受控副本增量和像素抽样记录见 [三个真实游戏项目验收记录](../docs/real-project-acceptance.md)。

### 真实客户端验收与剩余边界

用户授权独立空白测试文件后，使用 Playwright 连接真实客户端，实际执行加载、localhost 配对、登记、页面校验、扫描和导入。修复消息来源后，页面校验立即返回；两张小样散图扫描约 0.12 秒、导入约 0.37 秒，仅为一次小样记录。

通过 Figwright 读回 1×1 与 2×2 主组件、自动布局及实例关联，并从 Figma 提取原始图片填充，核对绿色和透明留白红色 PNG 的全部像素。原生资源面板搜索插入实例及实例交换通过；非空未绑定页、错误页名保护和测试矩形保留通过。测试内容仅写入该独立文件，不操作其他设计稿。
