# 项目图集导入插件（#2）

独立 Figma Design 开发插件，真实连接 Rust 本地助手。没有 ui-studio 运行时依赖，不修改共享核心或独立九宫格插件。

## 构建与使用

要求 Node 24、npm、Rust stable（完整测试会启动真实助手）。先按 [助手 README](../local-helper/README.md) 构建并启动助手。

```powershell
npm ci
npm run typecheck
npm run build
```

构建产物：`dist/code.js`（Figma 主线程）、`dist/ui.html`（内联 UI 脚本）；无需开发服务器。Figma 的开发插件入口选择此目录 `manifest.json`。manifest 只在开发模式放行 `http://127.0.0.1:38473`；不承诺发布模式/远端助手，不要把域名改成 `*`。不同端口的测试只在浏览器沙箱运行，并未改变 manifest。

1. 手动启动助手，从本机 `%LOCALAPPDATA%\MyFigmaAssets\token` 读取令牌，粘贴到「配对令牌」，点击「连接助手」。插件关闭后需要重新配对。若连接失败，按提示检查进程、端口及 Figma/浏览器本地网络权限。
2. 「管理项目」填写游戏名称、项目编号、直接包含 JSON/PNG 的资源目录和长期维护标记，保存。可以先登记助手的 `examples` 目录，编号如 `demo2`，名称如「示例游戏」。目录只保存在助手侧，UI 的编辑表单可读取它。
3. 默认下拉只显示长期维护游戏；搜索名称/编号会查全部登记。管理弹窗可以编辑名称、路径、维护标记，或删除登记；编号是身份，编辑时锁定，改变编号应另行登记。
4. 在**专门用于验收的新 Figma 文件/空白页**选择游戏、校验、扫描，检查散图数量和异常。扫描仅支持直接目录的小型对象式 JSON + PNG，不递归；有异常时仅可导入成功拆解的部分，不代表完整扫描。
5. 点击「导入主组件」。空白页命名为「游戏名称（项目编号）- 分类资源」，保存版本化绑定；在「未分类」自动换行 Frame 内创建普通主组件，分别使用拆解的 PNG。按钮悬浮提供用途和适用条件。

非空未绑定页、绑定其他项目、绑定版本不符、名称与绑定不符均拒绝。每次扫描/导入都重新校验当前页，不清空用户已有内容。已导入的非空页也明确拒绝重导入，因为 #4 增量不在本期范围。需要再次演示时请使用新的空白文件/页，不删除用户已有设计。

## 边界和安全

- HTTP/配对/登记/源格式及身份决策详见助手 README。所有请求仅由 UI 发往精确的 IPv4 loopback 地址，拒绝 HTTP 重定向；令牌不发往 Figma 主线程、document、clientStorage、URL 或日志。
- UI 任务入口 `Workflow` 统一控制登记、搜索、选择、校验、扫描、导入和互斥状态。任务期间禁用项目切换、管理修改、重复扫描/导入和连接。选择变化或登记修改会使旧扫描失效；清空选择也清空旧目标。
- 连接检查按操作触发，不轮询。网络错误/401 显示未连接和重新启动/配对提示，不把失败当作扫描为空。请求 30 秒超时；Figma 桥接 60 秒超时。
- 主线程 `createFigmaPlatform` 只接受版本 1 的小型扫描（最多 64 项），校验身份、尺寸、重复来源并白名单保存来源字段。不会把本机绝对路径或未知字段写进文档。组件名为「未分类/原名 · 图集相对路径」，避免跨图集同名混淆。
- 页面绑定键 `atlas.binding`：`{schemaVersion:1,projectId}`；组件来源键 `atlas.source`：v1 来源身份、原始名称、相对路径、引擎引用、尺寸、裁切、偏移。没有九宫格或增量兼容承诺，集成时须保留版本检查。
- 导入使用真实 Figma `createImage` / `createComponent`，只上传每张散图，不上传整张图集。任务中切换页面或 Figma 图片创建失败会删除本次新建 Frame，并恢复原页名称/绑定；不会删除原有用户节点。成功后保留进度，失败回滚后进度归零，允许修复后重试。
- 未实现 #3–12 的完整递归/独立图扫描、增量、取消、九宫格、完整分类、对照页、托盘等；不以禁用的假按钮模拟这些能力。

## 自动化验证

两目录各自执行 `npm ci`；插件的测试钩子会构建本插件和相邻助手，生产插件本身不依赖助手源代码的相对位置。

```powershell
npm run test:all
npm audit --audit-level=low
```

`test:all` 包含类型检查、7 个 Node 任务链路/连接安全测试、1 个 Playwright 浏览器交互测试。可分别运行 `npm test` / `npm run test:browser`。浏览器配置使用本机已有 Chrome（`channel: chrome`）；无 Chrome 时可安装经授权的浏览器或显式调整本目录测试配置。本次尝试下载 Playwright Chromium 超时，未将下载成功计为验收；实际浏览器验证使用系统 Chrome。

### 已验证（不是 Figma 真实渲染验收）

- 通过真实 Rust 子进程的 HTTP 登记 → 全量搜索/长期维护 → 扫描 → 插件任务入口 → Figma 平台替身，观察页面绑定、未分类 Frame、主组件名称/尺寸/来源/图片数量和进度。
- 非空未绑定、错绑和改名保护；扫描后页面变为非空也拒绝；执行中拒绝项目切换、重复任务；失败回滚与重试；断连清理过期扫描；清空游戏选择清理旧目标。
- 浏览器实际运行构建的 UI，处于 opaque-origin 沙箱中：配对、管理登记、默认列表/全量搜索、扫描摘要、hover 提示、执行中禁用、进度、断连提示。HTTP 使用真实助手，Figma 消息宿主是测试替身。
- 像素正确性由助手的公开 HTTP 测试读取仓库固定 2×1 PNG，比较恢复 PNG 的明确 RGBA 字面值；不是替身的像素裁剪模拟。
- Node 依赖审计修复了 esbuild 开发服务器公告，使用 0.28.1+；本项目不运行 esbuild dev server。

### 实际红→绿证据

| 回归/纵向行为 | 修复前的实际失败 | 修复后 |
| --- | --- | --- |
| 完整登记扫描导入入口 | `HelperClient is not a constructor`（初始空入口） | 任务链路通过 |
| 浏览器表单/交互 | 初始 UI 无「助手地址」而超时；实现后发现 sandbox 表单提交未保存、select 标签不可精确访问 | 改为显式保存事件/关联 label，浏览器通过 |
| 助手断连状态 | `true !== false`，仍显示 connected | 断连提示、扫描清理通过 |
| 导入回滚进度 | `1 !== 0`，页面已回滚但显示完成一项 | 归零并可重试通过 |
| HTTP 重定向 | `Missing expected rejection`，连接错误跟随了另一个端点 | 拒绝重定向，目标端点未收到请求 |
| 清空项目 | 抛出「请选择已登记的游戏」，未清除旧目标 | 清空选择/扫描/页面状态通过 |

### 未验证与集成注意

没有隔离安全的真实 Figma 目标，因此**没有导入任何用户设计，也未验证实际 Figma manifest 导入、桌面/网页 loopback 权限、真实图像渲染、Auto Layout 换行、资源检索/实例交换**。类型检查和平台替身不代替这些验收。后续应在新建的专用文件中用 `examples` 样本核对 2 张主组件、透明像素、组件身份、页面保护与布局。

没有执行三个实际游戏项目的兼容/性能验收（本期只覆盖小型简单图集），也没有独立双轴评审或父分支集成套件；这些留给父代理。所有改动仅位于本目录与 `local-helper`，不修改根 package、gitignore、AGENTS 或共享 schema。

开发依赖：TypeScript、esbuild、Figma plugin typings、Playwright；运行时无 Node/Web 框架依赖。构建/测试产物均由本目录 `.gitignore` 排除。
