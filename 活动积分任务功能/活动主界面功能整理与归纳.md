# 活动主界面功能整理与归纳

## 1. 结论摘要

活动主界面是限时活动的「做任务、积累积分、领取阶段奖励」页面。玩家进入后，需要快速看清活动剩余时间、累计积分、奖励进度，以及当前可以完成的任务。

主界面可归纳为六个功能区：活动基础信息、玩法说明、累计积分、普通奖励进度、终极奖励、任务区域。核心操作是切换任务分类、前往完成任务、查看奖励详情和一键领取可领取奖励。

设计时优先明确以下四点：

1. **任务积分与阶段奖励的区别**：任务完成后获得活动积分，积分达到节点后再领取物品奖励。
2. **奖励点击区域的区别**：点击物品图标查看详情，点击图标外的奖励卡片区域触发领取。
3. **领取是批量行为**：触发领取时，一次领取当前所有可领取奖励；终极奖励沿用同一逻辑。
4. **活动到期立即退出**：倒计时归零时关闭当前活动界面及主界面活动入口，已达成但未领取的奖励由系统补领。

## 4. 各功能区详细整理

### 4.1 活动入口与开放状态

**文档明确**：活动仅在有效起止时间内开放。未开始、已结束或配置失效时，不提供任务完成、积分累计和奖励领取功能，入口需要关闭。活动结束时的系统补领属于独立处理。（需求 A36、A42、A57）

**示意图参考**：入口位置以游戏主界面顶部附近的框选区域为参考。图中没有提供最终入口图标、名称或红点规则，不宜据此确定成品样式。

### 4.2 活动基础信息与玩法说明

| 项目 | 文档明确的要求 | UI 整理 |
| --- | --- | --- |
| 活动标题 | 左上角显示当前活动标题 | 预留不同活动标题及多语言文本的承载空间 |
| 活动倒计时 | 页面正上方显示距离活动结束的时间，格式为 `X天 00:00:00` | 保持清晰可读，与主题装饰区分层级 |
| 到期处理 | 倒计时归零，刷新状态并关闭当前界面，同时关闭入口 | 到期提示、关闭过渡以及弹窗打开期间的处理待确认 |
| 玩法说明 | 点击问号弹出通用弹窗，内容支持多语言 | 示意图将问号放在累计积分旁，便于就近解释积分玩法 |

来源：需求 A40:A44。标题示意图出现「起床战争大乱斗」「杂草丛生」，属于当前活动的视觉参考，不代表所有活动使用固定标题。

### 4.3 累计活动积分

**文档明确**：显示玩家在活动期间获得的活动积分总额，累计值不会减少。（需求 A48）

- 积分是奖励达成进度，不应表现为领奖时会扣除的消耗货币。
- 进入活动界面时，积分数字需要伴随进度条增长播放数字增长跳动特效。（特效 B2、B15）
- 积分达到进度上限后，进度条不再变化；累计积分是否继续增加、数值如何显示，原文未明确。（需求 A56）

### 4.4 普通奖励列表与积分进度条

#### 奖励内容与列表定位

**文档明确**：奖励列表支持滑动，每次进入活动界面都定位至玩家当前奖励进度所在位置。（需求 A54）

**示意图参考**：普通奖励沿横向积分路线排列，每档显示积分门槛和物品图标。图中的 `500`、`1000` 等为示例门槛，实际以当前活动内容为准。

#### 奖励状态

| 状态 | 条件含义 | 文档要求的表现 | 点击整理 |
| --- | --- | --- | --- |
| 未达成 | 积分未达到该档门槛 | 常态 | 图标可查看详情；卡片其他区域点击反馈待确认 |
| 可领取 | 已达门槛且尚未领取 | 奖励图标高亮 | 图标查看详情；卡片其他区域触发一键领取 |
| 已领取 | 奖励已经领取 | 置灰 | 图标查看详情；卡片其他区域点击反馈待确认 |

来源：需求 A50:A52。示意图另有勾选标记，可作为已领取状态的辅助参考，正文明确要求是置灰。

#### 点击与一键领取规则

1. 点击奖励物品图标：打开通用物品详情弹窗。
2. 点击可领取奖励卡片中图标之外的区域：触发领取。
3. 一次领取当前所有可领取奖励，不仅领取被点击的这一档。
4. 终极奖励作为列表末尾奖励，沿用同样的状态和领取逻辑。

来源：需求 A51:A52、A62。原文 A51 使用了“点击任意可领取奖励”的概括表述，A52 又细分了点击区域；本文按更具体的区域规则整理，最终热区需确认。

#### 进度条规则

**文档明确**：节点本身不参与区间进度百分比计算。（需求 A55:A56）

- 例如累计 `999` 分时，填充停在 `1000` 分节点之前。
- 达到 `1000` 分时，节点填满，随后表现 `1000—1500` 分区间内的进度。
- 达到进度上限后，进度条保持满进度，不再增长。

**设计建议**：将连接线进度和节点达成状态分别表达，避免未达门槛时节点已被填亮，造成可领取的误解。

### 4.5 终极奖励

**文档明确**：终极奖励位于积分进度最右侧，使用独立展示区域，与普通奖励列表区分。其达成、可领取、已领取及操作逻辑与普通奖励完全一致。（需求 A61:A62）

- 需要展示大奖物品、目标积分及三种奖励状态。
- **示意图参考**：大奖以放大的独立卡片展示，图中 `10000积分` 为示例。
- **文档明确**：大奖需要常驻循环发光，积分进度到达大奖节点时播放更突出的专属礼花特效。（特效 B11、B18）
- **待确认**：普通奖励列表滑动时大奖是否固定可见，以及大奖已领取后是否继续循环发光。

### 4.6 任务区域

#### 任务分类与完成比例

**文档明确**：任务区域位于页面右上角，提供「每日任务」和「活动任务」两个页签，首次进入默认展示每日任务。（需求 A66:A67）

- 任务区右上角展示当前分类的完成比例 `A/B`。
- `A` 为该分类已完成的有效任务数量，`B` 为该分类有效任务总数。
- 切换页签后，任务内容和完成比例应对应当前分类。
- 再次进入时是否记忆上次页签，以及无有效任务时如何展示，原文未说明。

来源：需求 A71。图中的 `11/34已完成` 为示例，不作为固定任务数量。

#### 单条任务结构

| 元素 | 含义与规则 |
| --- | --- |
| 任务积分 | 展示任务完成后发放的活动积分数量，需与物品奖励区别 |
| 任务描述 | 告知完成目标及必要条件 |
| 当前进度/目标进度 | 展示该条任务的完成情况 |
| 前往按钮 | 仅未完成且配置了跳转目标的任务显示；点击前往对应页面或功能位置 |
| 完成状态 | 已完成任务排列在列表下方，隐藏前往按钮；额外完成标记样式待确认 |

来源：需求 A68:A69、A73。未完成但没有跳转目标的任务不显示前往按钮，具体占位方式待确认。任务列表是否滚动、可见条数和同状态任务排序均未明确。

#### 每日任务与活动任务的差异

| 对比项 | 每日任务 | 活动任务 |
| --- | --- | --- |
| 时间规则 | 每天 UTC+8 00:00 刷新，以服务器时间为准 | 当前活动有效期内持续累计 |
| 完成与积分 | 完成每日任务可获得活动积分；具体结算反馈未单独说明 | 达到目标后结算活动积分并计入完成比例 |
| 完成次数 | 每日任务具体重置内容及可完成次数未单独展开 | 同一活动内单项任务仅能完成、结算一次 |
| 活动结束 | 受活动整体关闭规则约束 | 未完成任务停止累计 |

来源：需求 A35、A77、A81:A83。原文没有任务积分领取按钮，界面整理不额外增加任务领奖步骤。

#### 任务文本承载范围

`任务列表`工作表包含对局结算、击杀、伤害、方块操作、货币消耗与获取、在线时长、破床等已有任务，也包含带额外条件的新任务，例如一局内推人下虚空、低生命值击杀、限定时间带回钻石、装备整套装备和英雄熟练度目标。（任务列表 B2:B13、B18:B32）

**设计建议**：使用最长任务文案验证排版，为条件较多的描述保留换行空间，不将“一局内”“生命低于某比例”“限定时间”等达成条件直接截掉。各任务是否属于每日或活动分类，清单未逐项说明，不能自行归类。

## 5. 关联界面与用户操作流程

### 5.1 关联界面清单

| 界面/组件 | 入口 | 主要内容与结果 | 明确程度 |
| --- | --- | --- | --- |
| 活动主界面 | 游戏主界面活动入口 | 查看积分、奖励、任务及剩余时间 | 文档明确 |
| 玩法说明通用弹窗 | 问号按钮 | 多语言玩法说明 | 文档明确；关闭方式沿用通用规范需核对 |
| 物品详情通用弹窗 | 奖励物品图标 | 被点击奖励物品的详情 | 文档明确；关闭方式沿用通用规范需核对 |
| 任务目标页面/功能 | 任务前往按钮 | 进入任务对应玩法或功能 | 文档明确；返回活动路径待确认 |
| 奖励领取结果反馈 | 一键领取成功后 | 告知本次领取的奖励及状态变化 | 反馈形式待确认，未规定独立弹窗 |

### 5.2 主流程

1. 活动开放，玩家从主界面入口进入。
2. 首次进入展示每日任务；奖励列表定位到当前积分进度。
3. 查看任务目标和完成比例，必要时切换到活动任务。
4. 点击符合条件的「前往」按钮，进入目标玩法或功能。
5. 完成任务获得活动积分；活动任务达标后结算一次。
6. 再次进入活动界面，展示更新后的积分与奖励进度，播放相应增长特效。
7. 点击可领取卡片的领取区域，一次领取全部可领取奖励，更新奖励状态；领取结果的具体反馈形式待确认。

### 5.3 分支与时间变化

- **查看规则或奖励**：点击问号或物品图标打开相应通用弹窗。
- **任务完成**：已完成任务移动到列表下方，隐藏前往按钮，分类完成比例随之更新。
- **每日刷新**：UTC+8 00:00 刷新每日任务；玩家停留在界面时的刷新表现及提示方式待确认。
- **活动结束**：倒计时归零，关闭活动界面和入口；已完成但未领取的奖励由系统补领，补领到达方式及通知形式待确认。

## 6. 页面结构与信息负载

### 6.1 页面区域归纳

结合正文与总览示意图，可按以下结构理解主界面：

| 区域 | 内容与优先级 | 布局依据 |
| --- | --- | --- |
| 左上 | 活动标题，识别当前活动 | 正文明确 |
| 正上方 | 活动结束倒计时，提供时限信息 | 正文明确 |
| 中部主题区 | 当前活动角色、场景和主题表现 | 示意图参考 |
| 右上任务区 | 分类页签、完成比例、任务列表与前往按钮 | 正文明确 |
| 左下至底部 | 问号、累计积分、普通奖励滑动列表和进度条 | 示意图参考 |
| 奖励进度最右侧 | 独立终极奖励展示 | 正文明确；固定或随滚动待确认 |

### 6.2 信息负载与可读性建议

以下为已有功能的设计建议：

- **任务描述与进度并列易拥挤**：保持积分、描述、进度、操作的稳定分组，长描述换行，按钮位置保持一致。代价是单条任务高度可能增加。
- **阶段奖励较多**：通过横向滑动与进入时定位降低查找成本；保留清晰的可滑动提示，避免玩家误以为只存在当前可见奖励。
- **一键领取缺少显性提示**：在可领取卡片附近清楚表达批量领取结果，避免玩家误以为只领取单档。具体文案和是否提供独立按钮需确认，不直接新增按钮。
- **积分增长与列表定位可能互相影响**：需明确先定位还是先播放增长，以及跨多个节点时的展示顺序，避免动效发生在可视区外。
- **已领取和未达成容易混淆**：置灰之外建议用勾选或文字辅助识别，不只依赖颜色。
- **多语言与复杂数字**：重点验证活动长标题、任务条件、较大累计积分和多位数完成比例，保证关键内容不被裁切。

| 中 | 未达成/已领取卡片非图标区域点击时是否提示？加载和请求异常时如何表现？ | 决定交互反馈覆盖范围 |
| 中 | 积分超过进度上限时累计数值如何显示？大奖领取后是否保留常驻光效？ | 决定满进度和完成后的视觉状态 |
| 低 | 活动入口是否有红点？关闭/返回控件位置与通用弹窗规范是什么？ | 决定入口提示与导航控件；原文未规定 |

### 8.2 设计交付应覆盖的状态

- 主界面：首次进入、再次进入、进度增长、积分满进度、活动到期关闭。
- 任务区：每日/活动两个分类、未完成有前往、未完成无前往、已完成置底、跨日刷新；空列表及全完成表现待确认。
- 奖励区：未达成、可领取、已领取，包含终极奖励的对应状态。
- 关联弹窗：玩法说明、物品详情；领取结果及系统补领通知形式待确认。
- 动效：积分和进度同步增长、普通节点达成、大奖达成，以及标题、大奖、页面常驻效果。
- 适配检查：长任务描述、多语言标题、较大积分数值、滑动列表边界，以及同时出现弹窗和活动到期的情况。
